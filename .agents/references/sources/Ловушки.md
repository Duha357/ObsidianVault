## Назначение

- Собирает поведение, которое ломается неочевидно и стоит дорого.
- На выходе — список мест, где интуиция подводит, с признаком поломки.
- Называет то, что при чтении кода не видно.
- **Не:**
	- Перечисляет открытые дефекты и их статусы.
	- Заменяет чтение кода.

## Транспорт

- Разделитель частей составного запроса берётся из отдельного заголовка `Boundary`, а не из параметра `Content-Type`. Разбор заголовков режет строку по переводу строки и по первому двоеточию, параметры внутри значения не трогает. Нет отдельной строки — разделитель пуст, частей ноль.
- Перекодировка части ломает электронную подпись: она считается по байтам файла. Любой `convert` над подписанным содержимым делает подпись недействительной, ошибка проявится только на стороне ФНС.
- Отправка составного запроса добавляет каждой части `Content-Transfer-Encoding: binary` и всегда считает длину тела двумя проходами. Разделитель частей в общем HTTP-пакете свой, менять его нельзя.
- Имена частей и расширения файлов ФНС проверяет. Имя файла подписи в отдельных сервисах обязано совпадать с идентификатором из тела документа.
- Служебный метод скачивания не использует имя файла подписи из адреса. Пока подпись на версии одна, это незаметно. Как только подписей станет больше, разные ссылки будут вести в одну выборку.

## Разбор XML

- Разбор тегов возвращает плоский список узлов с путём, родителем и порядковым номером. Повторяющиеся блоки собираются по идентификатору родителя.
- Соединять экземпляры блока по локальному номеру нельзя: номер считается на пару «путь и имя», и при необязательных элементах внутри блока строки разъезжаются.
- Значение есть только у листьев. У составного узла оно пустое.
- Родитель определяется по вхождению значения потомка в значение предка. Два одинаковых по составу соседних блока могут привязаться к чужому родителю. Риск принят осознанно.
- Разбор идёт вложенными циклами с динамическим запросом на каждую пару узлов. На большом теле это заметно.
- Одноимённые теги в разных ветках схемы различаются только путём. Отбор по одному имени соберёт значения из чужой ветки.

## Сборка XML

- Namespace в конструкции объявления пространств имён принимает только литерал. Переменная там не работает, и это причина, по которой разбор через теги предпочтительнее выборки по пути.
- Обёртка исходящего документа берёт namespace от функции обмена, записанной в истории обмена. Функция не проставлена — namespace соберётся неверно, а ошибки не будет.
- Обёртка ставит атрибуты `xsi` и `xsd`. Прежняя ручная сборка ставила `tns` и `xs`. Переход меняет исходящий документ, проверять на живом обмене.
- Даты собираются явным форматированием. Без него формат зависит от настроек сессии, и схема ФНС перестанет приниматься.
- Порядок элементов важен там, где схема объявляет последовательность. Собирать блоки разных типов в одном цикле нельзя: они перемешаются.
- Числа с дробной частью приводятся отдельной функцией, потому что стандартное преобразование даёт запятую.

## Версионность

- Связь вызывающего с реализацией динамическая. Компилятор её не видит, отсутствие пакета версии обнаружится только в рантайме.
- Поиск вызовов по имени функции обходит эту слепоту не всегда: имя пакета собирается строкой. Искать нужно по имени функции без префиксов.
- Реализованность версии не проверяется. Запрос версии без пакета выглядит как авария, а не как штатный отказ.
- Ошибка маршрутизации, неизвестная версия и краш реализации дают один и тот же ответ. Различить их можно только по журналу.
- Приём не ограничен настроенной версией. Настройка управляет исходящими, входящие обрабатываются по адресу.

## Мёртвый код

- В папке модуля лежит старый монолит, из которого код разносили по версионным пакетам. Он не вызывается, но попадает в результаты поиска по всему модулю. При поиске его нужно отсекать.
- Тип связи документа с обменом, на который опиралась одна из веток сборки ответа, в системе не заведён. Ветка не отрабатывала никогда, хотя выглядела рабочей.
- Два пакета работы с составными запросами выведены из употребления и заменены общемодульными. В репозитории их нет.
- Устаревшие функции сборки адреса помечены в шапке. Вызовов не осталось, но сигнатуры сохранены.
