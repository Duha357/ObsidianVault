## Задача модуля

- Модуль обслуживает информационный обмен организации с ФНС в рамках налогового мониторинга.
- Обмен двусторонний: ФНС вызывает наши сервисы, мы вызываем сервисы ФНС.
- Сценарий обмена задан приложением к регламенту ФНС. Приложений 33, каждое — набор методов вокруг одной темы.
- Модуль решает три задачи: принять и разобрать входящий запрос, собрать и отправить исходящий, сохранить историю обмена.

- Маршрутизирует входящий вызов до реализации нужной версии API.
- Разбирает и валидирует тело запроса, отвечает кодом ФНС.
- Собирает файлы обмена и отправляет их по HTTP.
- Ведёт историю: запрос, ответ, привязанные документы, цепочку сообщений.
- **Не:**
	- Хранит предметные объекты. Требование, решение и результат обработки остаются файлами и историей обмена.
	- Подписывает и проверяет ЭП. Обе операции на клиенте, см. `docs/TRFTS/Граница с клиентом.md`.
	- Решает, когда отправлять. Инициатор — клиент или планировщик.
	- Транспортирует HTTP сам: работа с протоколом в `BTS_HttpPKG`.

## Границы

| Сторона | Через что | Кто инициирует |
| --- | --- | --- |
| ФНС | HTTPS, посредник Jetty | Обе стороны |
| ERP Client | Прямой вызов PL/SQL | Клиент |
| `BTS` | `BTS_HttpPKG`, `BTS_XMLPKG` | Модуль |
| `DOC` | Документы, версии файлов, подписи | Модуль |
| Планировщик | `RefreshAllTokens`, `SendAllCompanyGroupInfo` | Планировщик |

- Посредник доносит адрес целиком, включая сегмент версии. Подтверждено на живом вызове.
- Обратный канал ФНС к нашим файлам — служебный метод `getFileById`. Ссылки на него мы кладём в исходящие документы сами.

## Состав

Роли пакетов перечислены в `code/TRFTS/AGENTS.md`. Здесь только то, что из ролей не следует.

- Реализация сценария разложена по версиям API: один пакет на версию. Старая версия остаётся рабочей, новая заводится рядом.
- Имя версионного пакета в коде не пишется. Оно собирается из версии и подставляется в `execute immediate`, поэтому связь вызывающего с реализацией компилятор не видит.
- Служебные функции вне сценариев и вне версий вынесены в отдельный неверсионный пакет.
- Генерация файлов отделена от отправки: сценарий отдаёт данные, генератор строит XML и части запроса.

Исключение из правила версионности одно: генератор частей multipart вызывается из реализации своей же версии напрямую, с именем пакета в коде. Причина — тип частей это запись PL/SQL, через `execute immediate` она не передаётся.

## Ключевые решения

- Код HTTP всегда `200`, если запрос доставлен. Настоящий код операции лежит в теле ответа. Так сбой транспорта отделён от сбоя обработки.
- Версия API не глобальная. Она задана на пару «функция обмена + конфигурация обмена», потому что приложения ФНС живут в разных версиях одновременно.
- Версии по умолчанию нет. Не настроена — сборка адреса падает, вместо тихой отправки не туда.
- Приём не ограничен настроенной версией: обрабатывается любая, для которой есть реализация. В переходный период ФНС шлёт и старую, и новую.
- Одна конфигурация обмена — один участник мониторинга. Их может быть несколько, выбор идёт по `idpCfg`, при отсутствии берётся `nOrder = 1`.
- Мнемокод функции обмена — сквозной ключ. Из него выводятся имя пакета, версия, путь метода и namespace схемы.
