## Правила

После открытия текущего документа — прочитай и постоянно применяй при работе с целевой сущностью! Если дальнейшими инструкциями или пользователем не указано иное.

- Текущий `## Правила` наследует все `## Правила` в `AGENTS.md` уровнем выше в папочной иерархии текущего проекта.
- Любое несоответствие целевой сущности текущего документа, разделам текущего документа и (если есть) разделам унаследованным текущим документом — не исправлять. Явно сообщить!
- Спорные случаи не решать самому. Явно сообщить! Предложить варианты решения.
- Перед выдачей проверять соответствие разделам текущего документа и (если есть) разделам унаследованным текущим документом.
- Эталон задаёт состав и порядок разделов инструкции для человека.
- Сверять инструкцию с ближайшим образцом, при расхождении образца и скилла — со скиллом.
- Состав шагов сборки брать в `.agents/skills/md-instruction-create/SKILL.md`: образец процедуры не задаёт.
- Держать образцы парами: плохо и хорошо на один случай.
- Добавлять новый случай парой, не одиночным примером.
- Эталоны:
	- Раздел внутри блока эталона — раздел будущего документа.
	- **Не:**
		- Считать содержание примеров—эталонов разделами этого файла.
		- Проверять состав разделов этого файла по содержанию примеров—эталонов.
- **Не:**
	- Дублировать унаследованные правила в текущем разделе `## Правила`.
- **Исключение:**
	- Заданные эталоном `## Правила` дублировать допускается.

## Эталоны

- Инструкция целиком:
	- Структура в подразделе «Эталон 1. Инструкция для человека».
- Отдельный аспект:
	- Структура в подразделе «Эталон 2. Раздел аспекта».

##### Эталон 1. Инструкция для человека

```markdown
## Содержание

{Список отвечает на вопрос `Что внутри?`. Строка на каждый раздел H2, ссылкой `[[#Заголовок]]`. Раздел не добавляется, если разделов H2 меньше 3.}
{Замена. Непосредственно список.}

---

## Назначение

{Список отвечает на вопросы `Какие проблемы решает?`, `Что получится на выходе?`. Читается за 30 секунд.}
{Замена. Непосредственно список.}

[[#Содержание|↑ Назад]]

---

## Роли

{Список отвечает на вопросы `Кто исполняет?`, `Кто принимает и вправе отказать?`, `К кому идти с вопросом?`. Строка на роль: имя роли — что делает. Раздел не добавляется, если роль одна и она ясна из названия документа.}
{Замена. Непосредственно список.}

[[#Содержание|↑ Назад]]

---

## Об <аспекте>

{Замена. Разделы аспектов по «Эталон 2. Раздел аспекта». Один аспект — один раздел H2. Порядок разделов — порядок этапов, при отсутствии этапов — от общего к частному.}

---

## О запретах

{Строка о праве владельца отказать.}
{Замена. Непосредственно строка.}

Запрещено:

{Список запретов, общих для всех аспектов. Запрет, действующий только внутри одного аспекта, остаётся в разделе этого аспекта.}
- {Замена. Непосредственно пункты.}
- **Исключение:**
	- {Замена. Ситуации, снимающие запрет. Блок не добавляется, если исключений нет.}

```

##### Эталон 2. Раздел аспекта

```markdown
## Об <аспекте>

{Статусная строка этапа. Формат: `**Требуется** на этапе <этап>` или `**Не требуется** на этапе <этап>`. Строка не добавляется, если у аспекта нет этапа.}
{Абзац контекста: зачем аспект нужен владельцу. Абзац не добавляется, если это ясно из названия раздела.}

Обязательно:

{Список действий, без которых результат не принимается. Один пункт — одно действие.}
- {Замена. Непосредственно пункты.}
- **Не:**
	- {Замена. Действия, которых адресат не совершает. Блок не добавляется, если таких действий нет.}
- **Исключение:**
	- {Замена. Ситуации, снимающие требование. Блок не добавляется, если исключений нет.}

Для значительного повышения качества, рекомендуется:

{Список необязательных действий, повышающих итоговый результат. Блок не добавляется, если таких действий нет.}
- {Замена. Непосредственно пункты.}

Примеры <чего>:

{Пары образцов на один случай. Причина оценки — в скобках после образца. Блок не добавляется, если требование не допускает двух трактовок.}
- **Плохо:**
	- {Замена. Образец нарушения с причиной в скобках.}
- **Хорошо:**
	- {Замена. Парный образец, снимающий ту же причину.}

{Замыкающая строка: что владелец готов обсуждать в индивидуальном порядке и к кому идти. Строка не добавляется, если обсуждать нечего.}

[[#Содержание|↑ Назад]]
```

## Примеры: плохо

Пункт блока `Обязательно:`:

```markdown
Обязательно:

- Научиться качественно донести мысль
- Отработать плохую дикцию
```

Аспект в двух документах:

```markdown
Файл «Инструкция по подготовке оратора»:
### О запретах

Организаторы мероприятия имеют право не допустить заявку

Файл «Инструкция по составлению доклада»:
### О запретах

Мы имеем право не допустить заявку
```

Исключение:

```markdown
- Включать рекламу, прямую или завуалированную
	- Исключение: упоминание после выступления
```

Пример с узнаваемым третьим лицом:

```markdown
- **Плохо:**
	- Миллион RPS в YDB: история изменения небольшого конфига (польза сомнительна)
```

Пункт с несколькими фактами:

```markdown
- **Объём:** 200-1000 знаков. 3-10 пунктов/вопросов + ответы + примерный объём в минутах
```

Роль без введения:

```markdown
- Об этом следует сообщить своему куратору
```

Мотивирующая фраза в списке требований:

```markdown
Обязательно:

- Быть в рамках тематики мероприятия
- В результате доклада, индикатором будет очередь из желающих задать вопросы
```

## Примеры: хорошо

Пункт блока `Обязательно:`:

```markdown
Обязательно:

- Прогнать доклад вслух перед 2-3 слушателями и собрать замечания.
- Записать себя на диктофон и вычистить слова-паразиты.
```

Аспект в двух документах:

```markdown
Файл «Общие запреты», владелец аспекта:
## О запретах

Мы имеем право не допустить заявку.

Файл «Инструкция по составлению доклада»:
## О запретах

Перечень запретов — в документе "[[Общие запреты]]".
```

Исключение:

```markdown
- **Не:**
	- Включать рекламу, прямую или завуалированную.
- **Исключение:**
	- Упоминание после выступления.
```

Пример с узнаваемым третьим лицом:

```markdown
- **Плохо:**
	- Миллион запросов в <продукт>: история изменения небольшого конфига (польза сомнительна).
```

Пункт с несколькими фактами:

```markdown
- **Объём:** 200-1000 знаков.
- **Состав:** 3-10 пунктов или вопросов, с ответами.
- **Хронометраж:** Примерный объём каждого пункта в минутах.
```

Роль без введения:

```markdown
## Роли

- **Куратор** — сотрудник владельца, принимает материалы и отвечает на вопросы адресата.

## Об аспекте

- Сообщить куратору о смене темы.
```

Мотивирующая фраза в списке требований:

```markdown
Обязательно:

- Быть в рамках тематики мероприятия.

Индикатор удачного доклада — очередь из желающих задать вопросы.
```
