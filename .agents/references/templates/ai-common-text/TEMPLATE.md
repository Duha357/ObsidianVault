## Правила

После открытия текущего документа — прочитай и постоянно применяй при работе с целевой сущностью! Если дальнейшими инструкциями или пользователем не указано иное.

- Текущий `## Правила` наследует все `## Правила` в `AGENTS.md` уровнем выше в папочной иерархии текущего проекта.
- Любое несоответствие целевой сущности текущего документа, разделам текущего документа и (если есть) разделам унаследованным текущим документом — не исправлять. Явно сообщить!
- Спорные случаи не решать самому. Явно сообщить! Предложить варианты решения.
- Перед выдачей проверять соответствие разделам текущего документа и (если есть) разделам унаследованным текущим документом.
- Сверять оформление с ближайшим образцом, при расхождении образца и правила — с правилом.
- Держать образцы парами: плохо и хорошо на один случай.
- Добавлять новый случай парой, не одиночным примером.
- **Не:**
	- Дублировать унаследованные правила в текущем разделе `## Правила`.
- **Исключение:**
	- Заданные эталоном `## Правила` дублировать допускается.

## Примеры: плохо

Обычный текст:

```markdown
Конечно! Я с удовольствием вам помогу. Проблема, с которой вы столкнулись, скорее всего, вызвана...
```

Список:

```markdown
Итак, я внимательно проверил реализацию по плану. Стоит отметить, что в целом большинство пунктов выполнено, однако при детальном рассмотрении выяснилось, что пункт 3, касающийся валидации, реализован лишь частично, поскольку проверка длины строки присутствует, а вот проверка формата email, как видим, отсутствует. Надеюсь, это поможет вам разобраться.
```

Негативные и исключающие пункты:

```markdown
- Не нажимать красную кнопку.
- Если пользователь не указал явно.
- Не чихать.
- Без использования автоприцела.
- Только не когда пользователь чихнул 2 раза.
```

Деструктивная операция:

```markdown
Сейчас всё почищу, это быстро, скорее всего ничего важного там нет.

`DROP TABLE users;`
```

## Примеры: хорошо

Обычный текст:

```markdown
Ошибка в промежуточном ПО аутентификации.
```

Список:

```markdown
## Находки

##### Пункт 3 (валидация)

- Реализован частично.
- Проверка длины есть.
- Проверки формата email нет — `src/validators/user.ts:42`.

##### Пункт 5

- Чекбокс закрыт. Записи в Progress Log нет.

##### Scope creep

- Добавлен эндпоинт `/api/debug`. В плане нет.
```

Негативные и исключающие пункты:

```markdown
- **Не:**
	- Нажимать красную кнопку.
	- Чихать.
	- Использовать автоприцел.
- **Исключение:**
	- Явное указание пользователя.
	- Пользователь чихнул 2 раза.
```

Деструктивная операция:

```markdown
Внимание: это приведёт к безвозвратному удалению всех строк в таблице users; действие необратимо.

`DROP TABLE users;`

Сначала убедитесь, что резервная копия существует.
```
