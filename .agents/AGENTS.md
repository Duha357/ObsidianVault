## Правила

После открытия текущего документа — прочитай и постоянно применяй при работе с целевой сущностью! Если дальнейшими инструкциями или пользователем не указано иное.

- Текущий `## Правила` наследует все `## Правила` в `AGENTS.md` уровнем выше в папочной иерархии текущего проекта.
- Любое несоответствие целевой сущности текущего документа, разделам текущего документа и (если есть) разделам унаследованным текущим документом — не исправлять. Явно сообщить!
- Спорные случаи не решать самому. Явно сообщить! Предложить варианты решения.
- Перед выдачей проверять соответствие разделам текущего документа и (если есть) разделам унаследованным текущим документом.
- Владелец справочника — правило или скилл с тем же именем папки.
- В файле сущности — правило или процедура.
- Объёмные образцы, каталоги и большие таблицы — в справочник.
- Шапка справочника — обратная ссылка на владельца.
- Канон нейтрален, адаптеры тонкие.
	- Канон — `.agents/`: обычный markdown, ничего специфичного для конкретного агента.
	- Адаптер — `.claude/`, `.codex/` и подобные: только доставка канона, без правил.
	- Новый агент — новая папка-адаптер, канон не меняется.
- Ядро не знает о потребителях.
	- `.agents/rules/*` не ссылается на `.agents/skills/*`.
	- Удаление любого скилла не ломает правила.
- Канал сущности — самый ленивый, на котором она ещё срабатывает вовремя.
	- Правило:
		- Без `paths` — каждый ответ.
		- С `paths` — только своя область.
	- Скилл — `description` всегда, тело при вызове.
	- Справочник — только по ссылке владельца.
- Разделение сущностей оправдано, только если у них разные каналы.
- Реестр правил и их областей — `sh .agents/scripts/md-validate.sh --rules`.
- Правило заводится после 2+ реальных расхождений одного типа.
- Заведение новой сущности — `## Инструкции`, подраздел `Новая сущность`.
- Перенос и переименование сущности — `## Инструкции`, подраздел `Перенос и переименование`.
- Скрипты — POSIX `sh`, без Node, Python и внешних утилит сверх идущих с git.
	- Причина: одинаковый запуск на Windows (Git Bash) и Linux (`sh`).
- **Не:**
	- Дублировать унаследованные правила в текущем разделе `## Правила`.
	- Класть файлы напрямую в `.agents/rules/`, `.agents/skills/`, `.agents/references/sources/`, `.agents/references/templates/`.
	- Класть справочник рядом с владельцем.
	- Игнорировать правила в `.agents/rules/*`.
	- Дублировать в справочнике содержание владельца.
	- Копировать список правил оформления в документ: правило доставляется по своей области само.
- **Исключение:**
	- Заданные эталоном `## Правила` дублировать допускается.

## Инструкции

##### Новая сущность

1. Создать папку по имени сущности в нужной категории.
2. Положить внутрь файл роли.
3. Для `.agents/references/*` — прописать на него путь во владельце и обратную ссылку в шапке справочника.
4. Для `.agents/rules/*` — задать `paths` во фронтматтере.
5. Прогнать `sh .agents/scripts/md-validate.sh .agents`.

##### Перенос и переименование

1. Обновить все ссылки на старый путь (`grep -rn "<старый путь>"`).
2. Прогнать `sh .agents/scripts/md-validate.sh .agents`.

## Архитектура

- `.agents/AGENTS.md` — общие инструкции для ИИ агентов и раскладка.
- `.agents/CLAUDE.md` — инструкции для Claude Code, импортирует `@AGENTS.md`.
- `.agents/.gitattributes` — атрибуты git для файлов папки: скрипты выезжают с LF.
- `.agents/rules/<тема>/RULE.md` — правило: требование к поведению или оформлению.
- `.agents/skills/<имя>/SKILL.md` — скилл/процедура.
- `.agents/references/sources/<владелец>/SOURCE.md` — каталоги источников/справочники.
- `.agents/references/templates/<владелец>/TEMPLATE.md` — шаблоны оформления.
- `.agents/scripts/<имя>.sh` — проверки на POSIX `sh`.
