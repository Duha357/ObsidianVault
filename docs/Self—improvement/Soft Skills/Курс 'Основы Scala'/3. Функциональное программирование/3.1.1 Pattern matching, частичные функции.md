Сопоставление с образцом разбирает не только значения и типы, но и структуру объекта, а правила разбора можно задавать самому — через метод `unapply`. Частичные функции — та же конструкция `case`, вынесенная в самостоятельное значение, которое можно комбинировать и передавать. Ниже: пользовательские экстракторы, сопоставление по регулярным выражениям, безопасный вызов частичных функций и их композиция.

Базовый синтаксис `match` разбирался в разделе 1.2.3, объявление `PartialFunction` — в разделе 1.4.4.

---

## Углублённый pattern matching

`match` похож на `switch` из других языков, но сравнивает не только значения: он проверяет тип и разбирает объект на составные части — декомпозирует его.

> [!example]- Пример: Разбор по значению, типу и структуре
> Ветки перечисляют разные виды образцов: конкретное значение, тип с привязкой имени, разбор case-класса и вариант по умолчанию.
>
> Ожидаемый результат: для `"Harry Potter"` — `"This is a bestseller!"`; для числа — `"The book has N pages"`; для `Book` — `"Book: ..."`; иначе — `"Unknown item"`.
>
> ```scala
> def describeItem(item: Any): String = item match
>   case "Harry Potter" => "This is a bestseller!" // конкретное значение
>   case pages: Int     => s"The book has $pages pages" // тип
>   case book: Book     => s"Book: ${book.title}"
>   case _              => "Unknown item"
> ```
>
> Пример показывает: для чего `match` заменяет цепочки `if-else` — один разбор покрывает значения, типы и структуры.

Свойства сопоставления с образцом:

- Работает как выражение и возвращает значение.
- Поддерживает декомпозицию объектов.
- Проверяется компилятором на исчерпываемость для `sealed`-иерархий.
- Допускает дополнительные условия в ветке: `case x if condition =>`.

## Пользовательские экстракторы

Экстрактор задаёт правило разбора объекта. Это метод `unapply` в объекте: он получает значение и возвращает `Option` с извлечёнными частями.

> [!example]- Пример: Плохо — разбор строки вручную
> Строка разбирается прямо в месте использования: сначала проверка, потом разбиение, потом обращение по индексам. Логика разбора повторяется в каждом таком месте.
>
> Ожидаемый результат: для `"john@example.com"` печатается `user=john, domain=example.com`; при добавлении второго места разбора код придётся скопировать.
>
> ```scala
> val contact = "john@example.com"
>
> if contact.contains("@") then
>   val parts = contact.split("@")
>   println(s"user=${parts(0)}, domain=${parts(1)}")
> else
>   println("not an email")
> ```
>
> Пример показывает: для чего нужны экстракторы — правило разбора иначе размазывается по коду вызывающих мест.

> [!example]- Пример: Хорошо — экстрактор через unapply
> Правило разбора объявлено один раз в объекте. `Some` означает, что разбор удался и его результат подставляется в образец, `None` — что ветка не подходит.
>
> Ожидаемый результат: для `"john@example.com"` печатается `user=john, domain=example.com`; для строки без `@` срабатывает вторая ветка.
>
> ```scala
> object Email:
>   def unapply(value: String): Option[(String, String)] =
>     value.split("@") match
>       case Array(user, domain) => Some((user, domain))
>       case _                   => None
>
> "john@example.com" match
>   case Email(user, domain) => println(s"user=$user, domain=$domain")
>   case _                   => println("not an email")
> ```
>
> Пример показывает: зачем выносить разбор в экстрактор — сложная логика прячется за читаемым образцом.

Механика работы: компилятор вызывает `Email.unapply("john@example.com")`; при `Some` происходит декомпозиция, при `None` ветка пропускается.

Экстракторы расширяют возможности сопоставления, скрывают сложную логику разбора и позволяют строить DSL — синтаксис под конкретную предметную область (раздел 3.3.1).

## unapplySeq — переменное число элементов

Если заранее неизвестно, на сколько частей разбивается значение, применяется `unapplySeq`: он возвращает последовательность.

> [!example]- Пример: Экстрактор с переменным числом частей
> Путь разбивается на произвольное количество сегментов. Символ `*` в образце означает «все оставшиеся элементы».
>
> Ожидаемый результат: для `"/usr/local/bin"` в `rest` попадает `List("local", "bin")`.
>
> ```scala
> object Path:
>   def unapplySeq(path: String): Option[Seq[String]] =
>     Some(path.split("/").filter(_.nonEmpty).toSeq)
>
> "/usr/local/bin" match
>   case Path("usr", rest*) => println(rest) // List(local, bin)
>   case _                  => println("unknown path")
> ```
>
> Пример показывает: для чего нужен `unapplySeq` — структуры переменной длины разбираются тем же механизмом образцов.

## Сопоставление по регулярным выражениям

Объекты регулярных выражений уже содержат `unapplySeq`, поэтому подставляются в образец напрямую. Группы захвата становятся извлечёнными значениями.

> [!example]- Пример: Регулярное выражение в образце
> Метод `.r` превращает строку в регулярное выражение. Группа `(\d{4})` попадает в переменную образца.
>
> Ожидаемый результат: для `"Published in 2005"` печатается `Year: 2005`.
>
> ```scala
> val Year = raw"(\d{4})".r // имя с заглавной буквы: используется как образец
>
> "2005" match
>   case Year(year) => println(s"Year: $year")
>   case _          => println("Year not found")
> ```
>
> Пример показывает: почему имя образца пишут с заглавной буквы — со строчной оно было бы новой переменной, а не образцом.

## Частичные функции

Обычная функция определена для всех значений своего типа. Частичная функция `PartialFunction[A, B]` обрабатывает только часть значений, остальные лежат вне её области определения.

> [!example]- Пример: Объявление частичной функции
> Тело состоит только из веток `case`, поэтому значение сразу является `PartialFunction`.
>
> Ожидаемый результат: функция определена для 1 и 2; `genreMap(3)` выбрасывает `MatchError`.
>
> ```scala
> val genreMap: PartialFunction[Int, String] =
>   case 1 => "Fantasy"
>   case 2 => "Science Fiction"
> ```
>
> Пример показывает: зачем нужен отдельный тип — он честно сообщает, что функция покрывает не все входы.

---

## Безопасный вызов

> [!example]- Пример: Плохо — прямой вызов частичной функции
> Функция вызывается со значением, для которого не определена. Компилятор такой вызов пропускает.
>
> Ожидаемый результат: `MatchError` во время выполнения.
>
> ```scala
> genreMap(3) // MatchError
> ```
>
> Пример показывает: для чего частичной функции нужен безопасный способ вызова — прямой вызов ведёт себя как непроверенное приведение типа.

> [!example]- Пример: Хорошо — lift
> `lift` превращает частичную функцию в обычную, возвращающую `Option`. Значение вне области определения даёт `None`.
>
> Ожидаемый результат: `lifted(1)` — `Some("Fantasy")`, `lifted(5)` — `None`; исключений нет.
>
> ```scala
> val lifted: Int => Option[String] = genreMap.lift
>
> lifted(1) // Some("Fantasy")
> lifted(5) // None
> ```
>
> Пример показывает: зачем нужен `lift` — отсутствие результата становится значением, а не аварией.

Второй способ — проверка `isDefinedAt` перед вызовом. Он подходит там, где решение о вызове принимается заранее.

## Композиция частичных функций

##### orElse

`orElse` объединяет частичные функции: если первая не определена для значения, применяется вторая.

> [!example]- Пример: Объединение правил
> Каждая функция описывает своё правило. Объединение проверяет их по порядку.
>
> Ожидаемый результат: `combined(1)` — `"Fantasy"`, `combined(3)` — `"Detective"`; область определения расширилась.
>
> ```scala
> val detectiveGenre: PartialFunction[Int, String] =
>   case 3 => "Detective"
>
> val combined = genreMap.orElse(detectiveGenre)
> ```
>
> Пример показывает: для чего нужна композиция — набор правил собирается из независимо объявленных частей.

##### andThen

`andThen` применяет вторую функцию к результату первой, оставляя область определения прежней.

> [!example]- Пример: Обработка результата
> После определения жанра результат приводится к верхнему регистру.
>
> Ожидаемый результат: `upperGenre(1)` — `"FANTASY"`; для 3 функция по-прежнему не определена.
>
> ```scala
> val upperGenre = genreMap.andThen(_.toUpperCase)
> ```
>
> Пример показывает: чем `andThen` отличается от `orElse` — он меняет результат, а не область определения.

## Цепочки case на практике

Чаще всего частичную функцию не сохраняют в отдельное значение, а передают блок `case` прямо в метод коллекции.

> [!example]- Пример: Блок case внутри collect
> `collect` принимает частичную функцию: элементы, не подошедшие ни к одной ветке, отбрасываются, подошедшие — преобразуются.
>
> Ожидаемый результат: `booksOnly` — `List("Chocolat", "The Lollipop Shoes")`; строка и число отброшены.
>
> ```scala
> // список из разнотипных данных
> val items = List("plain text", Book("Chocolat"), 42, Book("The Lollipop Shoes"))
>
> val booksOnly = items.collect {
>   case book: Book => book.title
> }
> ```
>
> Пример показывает: зачем частичные функции нужны на практике — фильтрация и преобразование записываются одним блоком `case`.
