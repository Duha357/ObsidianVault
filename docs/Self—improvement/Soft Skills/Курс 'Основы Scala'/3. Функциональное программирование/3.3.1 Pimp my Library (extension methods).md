## Проблема закрытых классов

Проблема звучит так: мы хотим добавить кастомный метод в класс String, чтобы проверять, является строка ISBN-номером книги. Но класс String - final, то есть мы не можем его переопределить и добавить метод.

Вместо этого мы создаём утилиту, и вызов выглядит так:

StringUtils.isISBN("978-5-17-180326-1") 

В Scala придуман отличный способ, чтобы не создавать или не переопределять дополнительные классы - методы-расширения (также такая технология есть в C# и Kotlin). Он позволяет привязать метод к любому существующему типу!

Например, для класса String метод-расширение будет выглядеть следующим образом (упрощенный пример проверки ISBN):

extension (s: String)

  def isISBN: Boolean = s.startsWith("978-") || s.startsWith("979-")

println("978-5-389-02083-2".isISBN) // Выведет true

println("123-qwerty".isISBN)        // Выведет false 

Исходный код класса String не изменился.

## Построение DSL

Мы часто добавляем расширения, которые необходимы для нашей бизнес-логики. Это значит, что мы реализуем  DSL (Domain Specific Language) - синтаксис, который заточен под конкретную предметную область.

Код ниже научит конвертировать числа в секунды.

extension (n: Int)

  def seconds: Long = n * 1000L

val timeout = 5.seconds // 5000L

## AnyVal в Scala 2

В коде на Scala 2 для расширений использовались implicit и специальный тип AnyVal. 

Например, так бы выглядел код с конвертацией в секунды.

implicit class IntOps(val n: Int) {

  def seconds: Long = n * 1000L

} 

Но в этом коде есть проблема: каждый запуск n.seconds создавал бы новый объект-обёртку. 

Поэтому существует конструкция extends AnyVal - компилятор обрабатывает наш класс-обёртку как примитивное значение. Он делает это так: неявный метод объявленного класса превращается в вызов обычного статического метода, поэтому дополнительная память почти не требуется.

implicit class IntOps(val n: Int) extends AnyVal {

  def seconds: Long = n * 1000L

} 

Для использования такой оптимизации нужно следующее:

1. Был только один параметр (поскольку важен тип).

2. Не передавался var

3. Мы не можем использовать вложенный класс или наследоваться от этого класса
