## Неизменяемость и работа с состоянием

## Проблема изменяемого состояния

В императивном стиле мы храним состояние программы в переменных и меняем их в коде. Например, для генерации уникальных ID новых книг создают одну глобальную переменную, которая изменяется при каждом вызове функции:

var lastId = 0

def nextId(): Int = 

  lastId = lastId + 1

  lastId 

Проблема кода заключается в том, что поведение программы непредсказуемо, и мы не понимаем по переменной lastId, кто и сколько раз вызывал эту программу. Код сложен для тестирования и использования в многопоточных программах.

---

## Функциональный подход: передача состояния

Чтобы не использовать неизменяемые переменные, мы можем написать чистую функцию, которая будет вычислять новый ID и возвращать новое состояние вместе с результатом. 

Опишем реализацию в виде трейта:

trait IdGenerator:

  def nextId: (Int, IdGenerator) 

---

## Реализация генератора

Для реализации трейта нам не нужны изменяемые переменные, при этом мы добавляем возврат нового состояния

case class LibraryIdGenerator(currentId: Int) extends IdGenerator:

  def nextId: (Int, IdGenerator) =

    // 1. Вычисляем новый ID

    val newId = currentId + 1

    // 2. Создаем новый объект генератора с этим новым ID

    val nextGenerator = LibraryIdGenerator(newId) 

    // 3. Возвращаем кортеж: (Само значение, Новое состояние)

    (newId, nextGenerator) ) 

---

## Использование

Теперь исходный объект не будет меняться, а будут создаваться новые объекты.

val gen1 = LibraryIdGenerator(0)

val (id1, gen2) = gen1.nextId // id1 = 1, gen2 хранит currentId = 1

val (id2, gen3) = gen2.nextId // id2 = 2, gen3 хранит currentId = 2 

При вызове gen1.nextId несколько раз мы будем получать один и тот же объект. 

Программа стала предсказуемой:

- Всегда знаем, что программа вернет при определенном seed;
    
- Несколько потоков не изменяют одну и ту же переменную.

## Проблема «state hell»

Ручная передача состояния может привести к усложнению кода:

У такого подхода есть минус: если нам нужно сгенерировать много ID, используя результат прошлого вызова, то код превратится в цепочку вызовов промежуточных переменных.

val (firstId, g1) = generator.nextId

val (secondId, g2) = g1.nextId

val (thirdId, g3) = g2.nextId

// ... и так далее 

В этой цепочке легко запутаться и передать неправильное состояние. Такое явление часто называют “state hell” (ад состояний)

Основная проблема заключается в том, что мы передаем состояние вручную. В продвинутом функциональном программировании эту проблему решает инструмент под названием Монада состояний (State Monad), обычно используется готовая реализация из библиотеки Cats. 

В рамках базового курса мы не будем погружаться в ее устройство, но теперь для вас известна суть проблемы
