Раскрываются: механизм работы с исключениями в Scala (наследники Throwable). Генерация исключений через throw. Обработка с помощью конструкции try { ... } catch { ... } finally { ... }. Сопоставление с образцом (pattern matching) в блоке catch для обработки разных типов исключений (case e: IOException => ...). Блок finally для гарантированного освобождения ресурсов. Особенность Scala: отсутствие проверяемых исключений (checked exceptions) в отличие от Java. Контраст с ФП (через Try/Option)

3. Функциональное программирование

  
3.1 Продвинутые концепции ФП  
3.1.1 Pattern matching, частичные функции

Раскрываются: углубленное использование сопоставления с образцом. Пользовательские экстракторы (extractors) - объекты с методами unapply и unapplySeq для создания правил декомпозиции сложных объектов. Сопоставление по регулярным выражениям. Продвинутая работа с PartialFunction: композиция (orElse, andThen), метод lift для превращения частичной функции в обычную, возвращающую Option. Использование case chained statements для создания лаконичной логики обработки

  

[Pattern matching](https://docs.google.com/document/d/1EhQ1IZW8BK3bUK8U088GLcTVrqAFD8tcbD-Kk5Le77Y/edit?usp=sharing)

  
3.1.2 Неизменяемость и работа с состоянием (например, тип Rand)

Раскрываются: подход к управлению состоянием без использования var. Концепция "передачи состояния" (state threading): функция принимает текущее состояние и возвращает новое состояние вместе с результатом. Практический пример: генератор случайных чисел (RNG), где "зерно" (seed) передается явно. Проблема "адского состояния" (state hell) при ручной передаче и подготовка к пониманию монады состояния (State Monad). Преимущества для отладки и воспроизводимости (pure functions)

  

[Неизменяемость и работа с состоянием](https://docs.google.com/document/d/1XSig-67khFsZU0INXcBxj36xyE0eTgUNd2prZLZayiw/edit?usp=sharing)

  

3.1.3 Типы для сайд-эффектов

Раскрываются: концепция описания побочных эффектов (работа с БД, консолью, сетью) через типы, а не прямое выполнение. Принцип "Referential Transparency" - программа не делает ничего, пока её явно не запустят. Сравнение Future (eager, выполняется сразу, требует контекста) и IO/Task (lazy, описание вычислений, чистота). Проблема "лжи" типов (функция возвращает Int, но делает запрос в сеть). Типы как синие отпечатки программы (description of a program)

  

[Типы для сайд-эффектов](https://docs.google.com/document/d/1FZSoyL-wrofKyv5ZUDQxs3NPsk-m2O3cZylFpY6-qCY/edit?usp=sharing)

  
3.2 Алгебраические структуры  
3.2.1 Монойды, функторы, аппликативы

Раскрываются: введение в теорию категорий для программистов. Монойды (Monoid): типы, которые можно объединять (ассоциативная операция + нейтральный элемент). Примеры: сложение чисел (0), конкатенация строк (""). Использование для свертки списков. Функторы (Functor): контейнеры, к которым можно применить функцию map. Сохранение структуры контекста. Аппликативы (Applicative): возможность применить функцию, обернутую в контекст, к значению, обернутому в контекст (mapN, ap). Независимое выполнение вычислений (например, валидация формы с накоплением ошибок)

  

[Алгебраические структуры](https://docs.google.com/document/d/1g8saUr1oPDCwwnIS4LBwR2iyvA8IV18ouLbESCvbTv0/edit?usp=sharing)

  
3.2.2 Монады и их использование (Option, Either, IO)

Раскрываются: Монада как "программируемая точка с запятой" (способ sequencing вычислений в контексте). Связь с уже известными flatMap и for-comprehensions. Законы монад (левая и правая единица, ассоциативность) на интуитивном уровне. Почему List - это недетерминированная монада (множество результатов), Option - монада возможного отсутствия, Either - монада ошибок. Концепция "flatMap-able" типов

  

[Монады и их использование](https://docs.google.com/document/d/1l57La7Oeb5wC6B_ZNmbZgkk_tdneoTj0ZT2OnWC3FAg/edit?usp=sharing)

  
3.3 Функциональные паттерны  
3.3.1 Pimp my Library (extension methods)

Раскрываются: паттерн добавления новых методов к существующим классам (в том числе финальным классам из JDK) без использования наследования. Реализация в Scala 3 через ключевое слово extension. Сравнение с неявными классами (implicit class) из Scala 2. Использование для создания читаемых DSL (например, 1.second, "string".myCustomMethod). Принцип разделения интерфейса и реализации

  

[Pimp my library](https://docs.google.com/document/d/1jBDQk4fbctYwjQCJZRzNWEBPShkvfNAubyAjl3Yv644/edit?usp=sharing)

  
3.3.2 Классы типов (Type Classes)

Раскрываются: паттерн "ad-hoc полиморфизма" - возможность добавлять поведение к типам post-factum, не меняя исходный код типа. Три компонента паттерна: 1) Трейт (интерфейс поведения), 2) Instance (реализация для конкретного типа через given/implicit), 3) Interface (синтаксис для использования, часто через extension methods). Отличие от ООП-наследования (разделение данных и поведения). Примеры из экосистемы: Ordering[A], Show[A]

  

[Классы типов](https://docs.google.com/document/d/1IHnjafqzjtn8iLt7symUiPPHqcrgqUtcTfyAEvVrNqo/edit?usp=sharing)

  
3.3.3 Утиная типизация (Structural Types)

Раскрываются: использование структурных типов для работы с объектами, удовлетворяющими определенной структуре (наличию методов), а не конкретной иерархии классов. Синтаксис { def close(): Unit }. Особенности реализации в Scala (использование рефлексии Java Reflection). Производительность и ограничения. Применение для обертки "совместимых" Java библиотек или создания гибких API. Предпочтение Type Classes структурным типам в чистом Scala коде

  

[Утиная типизация](https://docs.google.com/document/d/1pQoV2IDhyYBz6jbAuwnr76KgBryyhpv_Hx5VV_vJoeQ/edit?usp=sharing)
