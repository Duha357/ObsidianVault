Scala поддерживает одиночное наследование классов: наследник получает доступ к `public`- и `protected`-членам родителя и может переопределять их. В отличие от Java, ключевое слово `override` обязательно — компилятор не даст перекрыть метод случайно. Ниже: синтаксис `extends`, правила переопределения, вызов родительской реализации через `super`, полиморфизм времени выполнения и запрет наследования через `final`.

---

## Наследование класса

Наследование объявляется ключевым словом `extends`.

> [!example]- Пример: Наследование и специализация
> `AudioBook` наследует `Media` и заменяет реализацию `format`.
>
> Ожидаемый результат: `AudioBook().format()` возвращает `"MP3 Audio"`, `Media().format()` — `"Unknown format"`.
>
> ```scala
> class Media:
>   def format(): String = "Unknown format"
>
> class AudioBook extends Media:
>   override def format(): String = "MP3 Audio"
> ```
>
> Пример показывает: зачем нужно наследование — подкласс меняет только отличающуюся часть поведения.

---

## Ключевое слово override

При переопределении метода или поля родителя `override` обязателен. В Java аннотацию `@Override` можно опустить, здесь — нет.

> [!example]- Пример: Плохо — override пропущен
> Метод с той же сигнатурой объявлен без `override`. Разработчик рассчитывал переопределить поведение родителя.
>
> Ожидаемый результат: ошибка компиляции «needs `override` modifier» — сборка не проходит.
>
> ```scala
> class AudioBook extends Media:
>   def format(): String = "MP3 Audio" // ошибка компиляции
> ```
>
> Пример показывает: для чего `override` сделали обязательным — совпадение сигнатур больше не может быть случайным.

> [!example]- Пример: Хорошо — намерение объявлено явно
> Ключевое слово сообщает и компилятору, и читателю, что метод заменяет родительский.
>
> Ожидаемый результат: код компилируется; если в родителе метод переименуют, компиляция сломается и место правки будет найдено сразу.
>
> ```scala
> class AudioBook extends Media:
>   override def format(): String = "MP3 Audio"
> ```
>
> Пример показывает: почему это защищает при рефакторинге — исчезнувший родительский метод превращается в ошибку сборки.

## Конструктор родителя и super

Если у родителя есть параметры конструктора, наследник передаёт их в момент наследования. Чтобы дополнить родительское поведение, а не заменить его, применяется `super`.

> [!example]- Пример: Передача аргументов родителю и вызов super
> Параметр `title` передаётся в конструктор `Media` прямо в объявлении класса. Метод `info` дополняет родительскую реализацию, а не переписывает её.
>
> Ожидаемый результат: `AudioBook("Dune").info()` возвращает `"Title: Dune (Audiobook, MP3)"`.
>
> ```scala
> class Media(val title: String):
>   def info(): String = s"Title: $title"
>
> class AudioBook(title: String) extends Media(title): // аргумент для конструктора родителя
>   override def info(): String = super.info() + " (Audiobook, MP3)"
>
> class VideoCourse(title: String) extends Media(title):
>   override def info(): String = super.info() + " (Video, 1080p)"
> ```
>
> Пример показывает: зачем нужен `super` — общая часть описания остаётся в родителе и не дублируется в наследниках.

## Полиморфизм времени выполнения

Полиморфизм позволяет обращаться к объектам разных типов через общий тип: реализация метода выбирается по фактическому типу объекта во время выполнения, а не по типу переменной во время компиляции.

Практическая выгода не столько в замене ссылок, сколько в возможности сложить разные объекты в одну коллекцию или передать в одну функцию.

> [!example]- Пример: Плохо — разбор типов вручную
> Тип каждого элемента проверяется и приводится вручную. Каждый новый вид материала требует правки этого метода.
>
> Ожидаемый результат: вывод верный, но добавление третьего типа без правки `describe` попадёт в ветку по умолчанию.
>
> ```scala
> def describe(item: Media): String =
>   if item.isInstanceOf[AudioBook] then item.asInstanceOf[AudioBook].info()
>   else if item.isInstanceOf[VideoCourse] then item.asInstanceOf[VideoCourse].info()
>   else "Unknown media"
> ```
>
> Пример показывает: для чего нужен полиморфизм — иначе знание обо всех подтипах собирается в одном месте.

> [!example]- Пример: Хорошо — полиморфный вызов
> Коллекция объявлена с типом `List[Media]` и содержит объекты разных подтипов. Для каждого элемента вызывается его собственная реализация `info`.
>
> Ожидаемый результат: печатается `Title: Dune (Audiobook, MP3)`, затем `Title: Scala Collections (Video, 1080p)`.
>
> ```scala
> val libraryCatalog: List[Media] = List(
>   AudioBook("Dune"),
>   VideoCourse("Scala Collections")
> )
>
> libraryCatalog.foreach(item => println(item.info()))
> // Title: Dune (Audiobook, MP3)
> // Title: Scala Collections (Video, 1080p)
> ```
>
> Пример показывает: зачем нужен общий базовый тип — новый подтип подключается без единой правки вызывающего кода.

## Ключевое слово final

`final` запрещает дальнейшее расширение. Это гарантирует, что поведение будет одинаковым во всех местах использования, и позволяет компилятору применить оптимизации: он знает, что подменить реализацию невозможно.

##### final для класса

> [!example]- Пример: Класс, закрытый для наследования
> От класса нельзя отнаследоваться, поэтому его поведение фиксировано.
>
> Ожидаемый результат: попытка объявить наследника `ISBNValidator` — ошибка компиляции.
>
> ```scala
> final class ISBNValidator
> ```
>
> Пример показывает: зачем закрывать класс — валидатор с изменённой логикой не появится незаметно для остального кода.

##### final для метода

Класс остаётся открытым для наследования, но конкретный метод переопределить нельзя.

> [!example]- Пример: Плохо — метод с инвариантом открыт для переопределения
> Формат штрихкода задан алгоритмом, на который опирается остальная система. Наследник может его изменить.
>
> Ожидаемый результат: `SpecialMedia("42").generateBarcode()` возвращает `"42"` вместо `"BARCODE-42"` — весь код, ожидавший префикс, ломается.
>
> ```scala
> class Media(val id: String):
>   def generateBarcode(): String = s"BARCODE-$id"
>
> class SpecialMedia(id: String) extends Media(id):
>   override def generateBarcode(): String = id // инвариант нарушен
> ```
>
> Пример показывает: для чего нужен `final` на методе — иначе гарантия формата держится на договорённости.

> [!example]- Пример: Хорошо — метод закрыт от переопределения
> Метод объявлен как `final`, класс при этом остаётся открытым для наследования.
>
> Ожидаемый результат: попытка переопределить `generateBarcode` в наследнике — ошибка компиляции.
>
> ```scala
> class Media(val id: String):
>   final def generateBarcode(): String =
>     s"BARCODE-$id"
> ```
>
> Пример показывает: зачем разделять `final` для класса и для метода — расширять тип можно, ломать ключевой алгоритм нельзя.

##### final для поля

Поля в Scala тоже переопределяются в наследниках, поэтому `final` применим и к ним.

> [!example]- Пример: Поле, закрытое от переопределения
> Значение зафиксировано и не может быть заменено в подклассе.
>
> Ожидаемый результат: попытка объявить `override val publisher` в наследнике — ошибка компиляции.
>
> ```scala
> class Publication:
>   final val publisher = "Eksmo"
> ```
>
> Пример показывает: почему `val` сам по себе не гарантирует неизменность значения в иерархии — он запрещает присваивание, но не переопределение.
