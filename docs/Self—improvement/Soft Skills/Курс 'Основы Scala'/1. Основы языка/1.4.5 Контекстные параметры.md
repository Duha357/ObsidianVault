## Идея контекстных параметров

Контекстные параметры позволяют передавать аргументы неявно: значения берутся из области видимости, а не из явного вызова.

Механизм применяется для:

- Инверсии зависимостей на уровне функций.
- Внедрения инфраструктурных зависимостей.
- Реализации Type Classes.

Ключевая идея:

Функция может требовать наличие значения определённого типа в контексте; компилятор подставит его автоматически.

---

## Синтаксис Scala 3: using

Контекстный параметр объявляется в отдельной группе параметров через `using`.

> [!example]- Пример: объявление функции с контекстным параметром
> Функция `formatBook` объявляет обычный параметр `name` и контекстный `prefix`.
>
> Ожидаемый результат: у функции две группы параметров — обычная и контекстная.
>
> ```scala
> def formatBook(name: String)(using prefix: String): String =
>   s"$prefix $title"
> ```
>
> Пример показывает: синтаксис контекстного параметра через `using`.

Разделение групп параметров:

- Первая группа — обычные параметры.
- Вторая группа — контекстные (`using`).

> [!example]- Пример: вызов функции с контекстным параметром
> Задаётся `given String`; `formatBook` вызывается без явной передачи контекста.
>
> Ожидаемый результат: компилятор найдёт `given String` в области видимости и передаст его как `prefix`.
>
> ```scala
> given String = "Book:"
>
> formatBook("Dune")
> ```
>
> Пример показывает: неявная передача контекстного аргумента из области видимости.

## given — определение контекста

Контекстное значение объявляется через `given`.

> [!example]- Пример: именованное given
> Объявляется контекстное значение `defaultPrefix` типа `String`.
>
> Ожидаемый результат: `given defaultPrefix` доступно для использования по имени.
>
> ```scala
> given defaultPrefix: String = "Library:"
> ```
>
> Пример показывает: объявление контекстного значения с именем.

Имя полезно для явного использования:

> [!example]- Пример: явное использование именованного given
> `formatBook` вызывается с явным указанием `defaultPrefix`.
>
> Ожидаемый результат: контекстный параметр `prefix` получает значение `"Library:"`.
>
> ```scala
> formatBook("Foundation")(using defaultPrefix)
> ```
>
> Пример показывает: передача контекста по имени.

Также можно задать значение без имени:

> [!example]- Пример: анонимное given
> Объявляется контекстное значение `String` без имени.
>
> Ожидаемый результат: `given String` ищется по типу.
>
> ```scala
> given String = "Author:"
> ```
>
> Пример показывает: объявление контекстного значения без имени.

## Поиск неявных значений

Компилятор ищет `given`:

1. В локальной области видимости.
2. В импортированных объектах.
3. В companion-объектах типов.

Если найдено:

- Ровно одно подходящее значение — используется.
- Несколько — ошибка неоднозначности.
- Ни одного — ошибка компиляции.

Это делает зависимость явной на уровне типов.

## Type Classes

Контекстные параметры лежат в основе паттерна Type Classes.

> [!example]- Пример: Type Classes
> Определяются интерфейс `Show`, инстанс для `Int` и функция `printValue`.
>
> Ожидаемый результат: `printValue(42)` возвращает `"42"` — компилятор находит `given Show[Int]`.
>
> ```scala
> trait Show[A]:
>   def show(a: A): String
>
> given Show[Int] with
>   def show(a: Int): String = a.toString
>
> def printValue[A](a: A)(using s: Show[A]): String =
>   s.show(a)
>
> printValue(42)
> ```
>
> Пример показывает: паттерн Type Classes на основе контекстных параметров.

## Контекстные бинды (Context Bounds)

Сокращённая запись контекстного параметра — контекстный бинд.

> [!example]- Пример: контекстный бинд
> `printValue` объявлена с контекстным биндом `[A: Show]`.
>
> Ожидаемый результат: требуется `given Show[A]`; внутри тела значение извлекается через `summon`.
>
> ```scala
> def printValue[A: Show](a: A): String =
>   summon[Show[A]].show(a)
> ```
>
> Пример показывает: сокращённая запись требования `given Show[A]`.

Пояснения:

- Бинд `[A: Show]` требует `given Show[A]`.
- Метод `summon[T]` извлекает контекстное значение типа `T`.

## Инфраструктурные зависимости

Контекстные параметры часто передают:

- Конфигурации.
- Логгеры.
- Сериализаторы.
- Execution context.
- Таймзоны и локали.

> [!example]- Пример: передача ExecutionContext
> `loadBooks` объявляет контекстный параметр `ExecutionContext`.
>
> Ожидаемый результат: функция не знает конкретный `ExecutionContext` — он предоставляется извне.
>
> ```scala
> import scala.concurrent.ExecutionContext
>
> def loadBooks()(using ec: ExecutionContext) =
>   // асинхронная логика
>   ()
> ```
>
> Пример показывает: внедрение инфраструктурной зависимости извне.

Это обеспечивает слабую связанность.

---

## Связь с группами параметров

Контекстные параметры всегда объявляются в отдельной группе параметров.

> [!example]- Пример: разделение групп параметров
> `saveBook` принимает данные и контекстный параметр `LibraryConfig`.
>
> Ожидаемый результат: объявлена функция с обычным и контекстным списком параметров.
>
> ```scala
> def saveBook(data: String)(using config: LibraryConfig): SaveResult
> ```
>
> Пример показывает: разделение бизнес-аргументов и контекста выполнения.

Разделение:

- Первая группа — бизнес-аргументы.
- Вторая группа — контекст выполнения.

Это улучшает читаемость API.

## Отличия от implicit (Scala 2)

В Scala 2 ключевое слово `implicit` использовалось для:

- Неявных параметров.
- Неявных преобразований.
- Типа `implicit class`.
- Типа `implicit val`.

Это приводило к перегрузке механизма и сложности понимания.

Scala 3 ввёл разделение:

| Scala 2 | Scala 3 |
|---|---|
| `implicit val` | `given` |
| `implicit def` | `given` |
| `implicit parameter` | `using` |
| `implicitly[T]` | `summon[T]` |

Преимущества Scala 3:

- Более явный синтаксис.
- Разделение ролей.
- Упрощённая модель поиска.
- Лучшая читаемость кода.

## Явная передача контекста

Контекст можно передать вручную.

> [!example]- Пример: явная передача контекста
> `formatBook` вызывается с явным значением префикса.
>
> Ожидаемый результат: `prefix` получает значение `"Featured:"` без `given` в области видимости.
>
> ```scala
> formatBook("Dune")(using "Featured:")
> ```
>
> Пример показывает: ручная передача контекста. Полезно в тестах и при локальном переопределении.
