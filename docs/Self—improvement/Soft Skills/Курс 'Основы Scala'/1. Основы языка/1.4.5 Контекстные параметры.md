Контекстный параметр — аргумент, который компилятор подставляет сам, находя подходящее значение в области видимости. Так передают то, что относится к окружению, а не к задаче: конфигурацию, логгер, сериализатор, `ExecutionContext`. Ниже: синтаксис `using` и `given`, правила поиска значений, паттерн Type Classes и отличия от `implicit` из Scala 2.

---

## Идея контекстных параметров

Функция объявляет, что ей требуется значение определённого типа, но не получает его при вызове — компилятор находит его сам.

Механизм применяется для:

- Инверсии зависимостей на уровне функций.
- Внедрения инфраструктурных зависимостей.
- Реализации паттерна Type Classes.

> [!example]- Пример: Плохо — прокидывание через все уровни
> Формат вывода нужен только самой нижней функции, но передаётся через каждый промежуточный вызов. Любое новое требование окружения меняет все сигнатуры в цепочке.
>
> Ожидаемый результат: `printCatalog(books, "Book:")` работает, но параметр `prefix` присутствует в трёх сигнатурах из трёх.
>
> ```scala
> def formatBook(title: String, prefix: String): String = s"$prefix $title"
>
> def formatShelf(titles: List[String], prefix: String): List[String] =
>   titles.map(title => formatBook(title, prefix)) // просто передаёт дальше
>
> def printCatalog(titles: List[String], prefix: String): Unit =
>   formatShelf(titles, prefix).foreach(println) // тоже просто передаёт дальше
> ```
>
> Пример показывает: для чего нужны контекстные параметры — иначе окружение приходится тащить через код, которому оно не нужно.

> [!example]- Пример: Хорошо — контекст объявлен один раз
> Требование к окружению записано в отдельной группе параметров. Промежуточные функции объявляют его так же и не передают руками.
>
> Ожидаемый результат: `printCatalog(books)` вызывается без указания префикса — компилятор подставит `given` из области видимости.
>
> ```scala
> def formatBook(title: String)(using prefix: String): String = s"$prefix $title"
>
> def formatShelf(titles: List[String])(using prefix: String): List[String] =
>   titles.map(formatBook) // prefix передаётся компилятором
>
> def printCatalog(titles: List[String])(using prefix: String): Unit =
>   formatShelf(titles).foreach(println)
> ```
>
> Пример показывает: зачем `using` — зависимость остаётся видимой в типе, но исчезает из тела функций.

## Синтаксис using

Контекстный параметр объявляется в отдельной группе параметров ключевым словом `using`.

> [!example]- Пример: Объявление контекстного параметра
> Первая группа — обычные аргументы, вторая — контекст.
>
> Ожидаемый результат: у функции две группы параметров; вторая заполняется компилятором.
>
> ```scala
> def formatBook(title: String)(using prefix: String): String =
>   s"$prefix $title"
> ```
>
> Пример показывает: как отличить контекстный параметр от обычного — по ключевому слову `using` в отдельной группе.

> [!example]- Пример: Вызов без указания контекста
> В области видимости объявлено `given` нужного типа, поэтому вызов не содержит второго списка аргументов.
>
> Ожидаемый результат: `formatBook("Dune")` возвращает `"Book: Dune"`.
>
> ```scala
> given String = "Book:"
>
> formatBook("Dune") // "Book: Dune"
> ```
>
> Пример показывает: почему механизм называют неявной передачей — аргумент есть в сигнатуре, но не в вызове.

## given — определение контекста

Контекстное значение объявляется ключевым словом `given`. Имя необязательно.

> [!example]- Пример: Именованное given
> Значение объявлено с именем, поэтому к нему можно обратиться явно.
>
> Ожидаемый результат: `defaultPrefix` доступно и для автоматического поиска, и для явной передачи.
>
> ```scala
> given defaultPrefix: String = "Library:"
> ```
>
> Пример показывает: для чего `given` дают имя — чтобы указать конкретное значение там, где подходящих несколько.

> [!example]- Пример: Анонимное given
> Значение объявлено без имени: оно участвует только в поиске по типу.
>
> Ожидаемый результат: контекст типа `String` найдётся автоматически, но сослаться на него по имени нельзя.
>
> ```scala
> given String = "Author:"
> ```
>
> Пример показывает: почему имя необязательно — поиск ведётся по типу, а не по имени.

## Поиск контекстных значений

Компилятор ищет `given` в следующем порядке:

1. В локальной области видимости.
2. В импортированных объектах.
3. В companion-объектах участвующих типов.

Результат поиска:

- Найдено ровно одно значение — оно подставляется.
- Найдено несколько — ошибка неоднозначности.
- Не найдено ни одного — ошибка компиляции.

Отсутствие подходящего значения обнаруживается при сборке, а не при запуске.

## Type Classes

Контекстные параметры лежат в основе паттерна Type Classes: поведение добавляется к типу извне, без изменения его исходного кода.

> [!example]- Пример: Type Class из трёх частей
> `Show` описывает поведение, `given Show[Int]` реализует его для конкретного типа, `printValue` требует наличия реализации.
>
> Ожидаемый результат: `printValue(42)` возвращает `"42"`; для типа без `given Show` вызов не скомпилируется.
>
> ```scala
> trait Show[A]:                      // 1. интерфейс поведения
>   def show(a: A): String
>
> given Show[Int] with                // 2. реализация для Int
>   def show(a: Int): String = a.toString
>
> def printValue[A](a: A)(using s: Show[A]): String = // 3. требование реализации
>   s.show(a)
>
> printValue(42) // "42"
> ```
>
> Пример показывает: зачем нужен паттерн — поведение подключается к типу без наследования и правки его кода.

Подробно паттерн разбирается в разделе 3.3.2.

## Контекстные границы (Context Bounds)

Если контекстное значение нужно только для передачи дальше, его имя не требуется — тогда применяется сокращённая запись.

> [!example]- Пример: Контекстная граница вместо using
> Запись `[A: Show]` означает то же, что и `(using s: Show[A])`, но без имени параметра. Само значение извлекается методом `summon`.
>
> Ожидаемый результат: `printValue(42)` возвращает `"42"` — поведение совпадает с развёрнутой формой.
>
> ```scala
> def printValue[A: Show](a: A): String =
>   summon[Show[A]].show(a) // summon достаёт given нужного типа
> ```
>
> Пример показывает: для чего нужны контекстные границы — требование к типу записывается прямо в списке параметров типа.

## Инфраструктурные зависимости

Через контекстные параметры обычно передают конфигурации, логгеры, сериализаторы, `ExecutionContext`, таймзоны и локали.

> [!example]- Пример: Передача ExecutionContext
> Функция объявляет требование к пулу потоков, но не выбирает его. Конкретный `ExecutionContext` задаётся снаружи — в приложении один, в тестах другой.
>
> Ожидаемый результат: функция компилируется только там, где `given ExecutionContext` доступен.
>
> ```scala
> import scala.concurrent.ExecutionContext
>
> def loadBooks()(using ec: ExecutionContext): Unit =
>   () // асинхронная логика
> ```
>
> Пример показывает: зачем передавать инфраструктуру контекстом — компонент не привязывается к конкретной реализации.

## Явная передача контекста

Автоматический поиск можно обойти, передав значение вручную.

> [!example]- Пример: Явная передача через using
> Ключевое слово `using` в месте вызова означает «заполняю контекстную группу сам».
>
> Ожидаемый результат: `prefix` получает `"Featured:"`, даже если в области видимости объявлен другой `given`.
>
> ```scala
> formatBook("Dune")(using "Featured:")
> ```
>
> Пример показывает: для чего нужна явная передача — она полезна в тестах и при локальном переопределении контекста.

## Отличия от implicit (Scala 2)

В Scala 2 одно ключевое слово `implicit` обозначало неявные параметры, неявные преобразования, `implicit class` и `implicit val`. Перегруженность механизма делала код трудным для чтения.

| Scala 2 | Scala 3 |
|---|---|
| `implicit val` | `given` |
| `implicit def` | `given` |
| неявный параметр | `using` |
| `implicitly[T]` | `summon[T]` |

Scala 3 разделила роли: `given` определяет контекст, `using` его запрашивает. Синтаксис стал явным, а модель поиска — проще.
