# Коллекции

Коллекции — одна из наиболее сильных и выразительных частей стандартной библиотеки Scala.

- Неизменяемы по умолчанию.
- Ориентированы на функциональную обработку.
- Интегрированы с выразительной моделью языка.
- Унифицированы общей иерархией типов.

В Scala разработчик описывает, что получить, а не как пошагово изменять структуру данных.

По умолчанию в Scala 3 используются неизменяемые коллекции из пакета `scala.collection.immutable`. Операции не изменяют коллекции «на месте», а возвращают новую.

---

## Базовые коллекции

##### Иерархия коллекций

Стандартная библиотека организована вокруг общего абстрактного интерфейса коллекций. Для большинства сценариев используются:

- List.
- Set.
- Map.

Все имеют неизменяемые реализации по умолчанию.

---

## List — связный список

List — неизменяемый односвязный список.

> [!example]- Пример: создание List
> Создаётся список из трёх чисел.
>
> ```scala
> val numbers = List(1, 2, 3)
> ```
>
> Пример показывает: базовый синтаксис создания неизменяемого списка.

##### Добавление в начало (::)

Наиболее эффективная операция для List — добавление в начало.

> [!example]- Пример: добавление в начало
> Число 0 добавляется в начало списка numbers оператором ::.
>
> ```scala
> val newList = 0 :: numbers
> // List(0, 1, 2, 3)
> ```
>
> Пример показывает: :: возвращает новый список и не изменяет исходный.

Структурно список рекурсивен.

> [!example]- Пример: рекурсивная структура List
> Список из трёх элементов разворачивается во вложенные операции ::.
>
> ```scala
> List(1, 2, 3)
> // эквивалентно
> 1 :: 2 :: 3 :: Nil
> ```
>
> Пример показывает: список строится из головы, хвоста и Nil.

List предпочтителен, когда:

- Рекурсивная обработка.
- Частое добавление в начало.
- Простая неизменяемая структура.

Добавление в конец списка имеет линейную сложность.

## Set — множество

Set хранит уникальные элементы.

> [!example]- Пример: создание Set
> Создаётся множество из трёх чисел.
>
> ```scala
> val s = Set(1, 2, 3)
> ```
>
> Пример показывает: синтаксис создания неизменяемого Set.

Элементы добавляются оператором +. Дубликаты игнорируются.

> [!example]- Пример: добавление элемента в Set
> К множеству s добавляются числа 2 и 4. Дубликат 2 не меняет множество.
>
> ```scala
> val s2 = s + 2  // Set(1, 2, 3)
> val s3 = s + 4  // Set(1, 2, 3, 4)
> ```
>
> Пример показывает: + возвращает новое множество с уникальными элементами.

Наличие элемента проверяется методом contains.

> [!example]- Пример: проверка наличия в Set
> Проверяется, содержит ли множество число 2.
>
> ```scala
> s.contains(2)  // true
> ```
>
> Пример показывает: contains возвращает Boolean.

Неизменяемый Set реализован на хеш-структурах с эффективной амортизированной сложностью операций.

## Map — ассоциативный массив

Map хранит пары «ключ → значение».

> [!example]- Пример: создание Map
> Создаётся словарь с именами и возрастами.
>
> ```scala
> val ages = Map(
>   "Alice" -> 30,
>   "Bob"   -> 25
> )
> ```
>
> Пример показывает: синтаксис создания Map с парами ключ → значение.

Метод get возвращает Option и исключает работу с null.

> [!example]- Пример: доступ по ключу
> ages("Alice") возвращает 30. get по отсутствующему ключу возвращает None.
>
> ```scala
> ages("Alice")        // 30
> ages.get("Charlie") // Option[Int]
> ```
>
> Пример показывает: get исключает null и возвращает Option.

Пары добавляются оператором +.

> [!example]- Пример: добавление пары в Map
> Добавляется пара «Charlie» → 20.
>
> ```scala
> val updated = ages + ("Charlie" -> 20)
> ```
>
> Пример показывает: + возвращает новую Map с добавленной парой.

## Неизменяемость и structural sharing

Несмотря на то, что операции возвращают новую коллекцию, Scala не копирует структуру полностью. Вместо этого используется structural sharing — переиспользование неизменяемых частей структуры.

> [!example]- Пример: structural sharing
> К списку a добавляется 0 в начало. Новый список b переиспользует хвост a.
>
> ```scala
> val a = List(1, 2, 3)
> val b = 0 :: a
> ```
>
> Пример показывает: b разделяет неизменяемую часть структуры с a.

Это обеспечивает:

- Эффективность по памяти.
- Предсказуемость.
- Потокобезопасность без синхронизации.

Structural sharing делает неизменяемые коллекции практичными в промышленной разработке.

## Сборка неизменяемых коллекций

Иногда требуется постепенно собрать коллекцию, но сохранить её неизменяемой во внешнем API.

##### Подход 1: использование мутабельной структуры внутри

Мутабельная структура накапливает элементы локально. Наружу возвращается неизменяемая коллекция.

> [!example]- Пример: мутабельная структура внутри
> Элементы добавляются в ArrayBuffer, затем toList возвращает неизменяемый список.
>
> ```scala
> import scala.collection.mutable.ArrayBuffer
>
> val buffer = ArrayBuffer[Int]()
> buffer += 1
> buffer += 2
> buffer += 3
>
> val result = buffer.toList  // неизменяемая коллекция
> ```
>
> Пример показывает: мутабельная структура остаётся локальной.

##### Подход 2: Builder-паттерн

Стандартная библиотека предоставляет билдеры.

> [!example]- Пример: MapBuilder
> Пары накапливаются в билдере, затем извлекается готовая неизменяемая Map.
>
> ```scala
> import scala.collection.mutable.MapBuilder
>
> val builder = new MapBuilder[String, Int](Map.empty)
> builder += "Alice" -> 30
> builder += "Bob"   -> 25
>
> val result = builder.result()
> ```
>
> Пример показывает: билдер накапливает элементы и возвращает неизменяемую коллекцию.

Билдеры эффективны при построении коллекций в циклах или сложных вычислениях.

## Операции над коллекциями

Стандартная библиотека предоставляет богатый набор функциональных операций.

##### map — преобразование 1 → 1

Каждый элемент преобразуется независимо.

> [!example]- Пример: map
> Каждый элемент списка умножается на 2.
>
> ```scala
> val numbers = List(1, 2, 3)
> val doubled = numbers.map(_ * 2)
> // List(2, 4, 6)
> ```
>
> Пример показывает: map преобразует каждый элемент и сохраняет длину списка.

##### filter — отбор по условию

Из списка остаются только элементы, для которых предикат истинен.

> [!example]- Пример: filter
> Из списка чисел отбираются чётные элементы.
>
> ```scala
> val evens = numbers.filter(_ % 2 == 0)
> // List(2)
> ```
>
> Пример показывает: filter возвращает новую коллекцию, исходная не изменяется.

##### flatMap — преобразование с разворачиванием

Применяет функцию к каждому элементу, затем сплющивает результат.

> [!example]- Пример: flatMap
> Каждое слово разворачивается в список символов, списки склеиваются в один.
>
> ```scala
> val words = List("hello", "scala")
> val chars = words.flatMap(_.toList)
> // List(h, e, l, l, o, s, c, a, l, a)
> ```
>
> Пример показывает: на выходе один плоский список вместо списка списков.

Этот механизм лежит в основе композиции не только коллекций, но и других контейнеров (Option, Either, Try).

## foldLeft и foldRight

Сведение коллекции к одному значению.

> [!example]- Пример: foldLeft
> Сумма элементов списка вычисляется с аккумулятором и начальным значением 0.
>
> ```scala
> val sum = numbers.foldLeft(0)(_ + _)
> // 6
> ```
>
> Пример показывает: foldLeft сводит коллекцию к одному значению.

- 0 — начальное значение (аккумулятор).
- _ + _ — функция агрегации.

##### Разница между foldLeft и foldRight

Свёртка применяется слева направо (foldLeft) или справа налево (foldRight).

> [!example]- Пример: порядок свёртки
> Вычитание показывает направление свёртки.
>
> ```scala
> numbers.foldLeft(0)(_ - _)
> // ((0 - 1) - 2) - 3 = -6
>
> numbers.foldRight(0)(_ - _)
> // 1 - (2 - (3 - 0)) = 2
> ```
>
> Пример показывает: порядок свёртки меняет результат для некоммутативных операций.

Практика:

- foldLeft предпочтительнее: безопаснее по стеку.
- foldRight менее эффективен для больших коллекций.

## For-comprehensions

##### Что такое for / yield

for — синтаксический сахар: компилятор разворачивает его в вызовы map, flatMap, withFilter, foreach.

> [!example]- Пример: for / yield и эквивалент
> Из списка отбираются нечётные элементы и умножаются на 10.
>
> ```scala
> val result =
>   for
>     x <- List(1, 2, 3)
>     if x % 2 == 1
>   yield x * 10
>
> // List(10, 30)
> ```
>
> Эквивалентная цепочка вызовов:
>
> ```scala
> List(1, 2, 3)
>   .withFilter(_ % 2 == 1)
>   .map(_ * 10)
> ```
>
> Пример показывает: for / yield — декларативная запись цепочки вызовов.

for читается как императивный код, но остаётся декларативной конструкцией.

---

## for не только для коллекций

Механизм работает с любыми типами, поддерживающими map, flatMap, withFilter, foreach.

> [!example]- Пример: for с Option
> Два Option связываются и складываются.
>
> ```scala
> for
>   a <- Option(2)
>   b <- Option(3)
> yield a + b
>
> // Some(5)
> ```
>
> Пример показывает: for работает с Option, Either, Try и другими контейнерами.

## Ленивые коллекции

##### Строгие vs ленивые вычисления

- Строгие (eager): вычисляются немедленно.
- Ленивые (lazy): вычисляются по запросу.

##### LazyList

LazyList — ленивый список (заменяет устаревший Stream).

> [!example]- Пример: бесконечный LazyList
> Создаётся бесконечный список натуральных чисел. Ничего не вычисляется до запроса.
>
> ```scala
> val naturals: LazyList[Int] =
>   LazyList.from(1)
> ```
>
> Пример показывает: LazyList позволяет работать с бесконечными последовательностями.

> [!example]- Пример: получение элементов
> Берутся первые пять элементов.
>
> ```scala
> naturals.take(5).toList
> // List(1, 2, 3, 4, 5)
> ```
>
> Пример показывает: вычисляются только запрошенные элементы.

---

## Преимущества и риски ленивости

Преимущества:

- Экономия памяти.
- Бесконечные последовательности.
- Декларативный стиль.

Потенциальные риски:

> [!example]- Пример: побочные эффекты в LazyList
> map с println не выполняется при создании. Эффекты срабатывают при обращении к элементам.
>
> ```scala
> val xs = LazyList.from(1).map { x =>
>   println(x)
>   x * 2
> }
>
> xs.take(3).toList
> ```
>
> Пример показывает: побочные эффекты выполняются только при запросе элементов.

LazyList мемоизирует вычисленные значения:

- Каждый элемент вычисляется один раз.
- Повторный доступ не пересчитывает значение.

Мемоизация удерживает память и может приводить к утечкам при неосторожном использовании.
