# Коллекции

# Коллекции — одна из наиболее сильных и выразительных частей стандартной библиотеки Scala. Они:

- неизменяемы по умолчанию;
    
- ориентированы на функциональную обработку;
    
- интегрированы с выраженческой моделью языка;
    
- унифицированы общей иерархией типов.
    

В Scala разработчик преимущественно описывает что необходимо получить, а не как пошагово изменять структуру данных.

По умолчанию в Scala 3 используются неизменяемые коллекции из пакета:

scala.collection.immutable

Это означает, что операции над коллекциями не изменяют их «на месте», а возвращают новую коллекцию.

---

## Базовые коллекции

### Иерархия коллекций

Стандартная библиотека организована вокруг общего абстрактного интерфейса коллекций. Для большинства сценариев используются:

- List
    
- Set
    
- Map
    

Все они имеют неизменяемые реализации по умолчанию.

---

## List — связный список

List — неизменяемый односвязный список.

val numbers = List(1, 2, 3)

### Добавление в начало (::)

Наиболее эффективная операция для List — добавление в начало:

val newList = 0 :: numbers  
// List(0, 1, 2, 3)

Структурно список рекурсивен:

List(1, 2, 3)  
// эквивалентно  
1 :: 2 :: 3 :: Nil

List предпочтителен, когда:

- используется рекурсивная обработка;
    
- часто выполняется добавление в начало;
    
- требуется простая неизменяемая структура.
    

Добавление в конец списка имеет линейную сложность, что важно учитывать.

---

## Set — множество

Set хранит уникальные элементы.

val s = Set(1, 2, 3)

Добавление элемента:

val s2 = s + 2  // Set(1, 2, 3)  
val s3 = s + 4  // Set(1, 2, 3, 4)

Проверка наличия:

s.contains(2)  // true

Неизменяемый Set реализован на основе хеш-структур с эффективной амортизированной сложностью операций.

---

## Map — ассоциативный массив

Map хранит пары «ключ → значение».

val ages = Map(  
  "Alice" -> 30,  
  "Bob"   -> 25  
)

Доступ по ключу:

ages("Alice")        // 30  
ages.get("Charlie") // Option[Int]

Важно: метод get возвращает Option, что исключает необходимость работы с null.

Добавление элемента:

val updated = ages + ("Charlie" -> 20)

---

## Неизменяемость и structural sharing

Несмотря на то, что операции возвращают новую коллекцию:

val a = List(1, 2, 3)  
val b = 0 :: a

Scala не копирует структуру полностью. Вместо этого используется structural sharing — переиспользование неизменяемых частей структуры.

Это обеспечивает:

- эффективность по памяти;
    
- предсказуемость;
    
- потокобезопасность без синхронизации.
    

Именно благодаря structural sharing неизменяемые коллекции практичны в промышленной разработке.

---

## Сборка неизменяемых коллекций

Иногда требуется постепенно собрать коллекцию, но сохранить её неизменяемой во внешнем API.

### Подход 1: использование мутабельной структуры внутри

import scala.collection.mutable.ArrayBuffer  
  
val buffer = ArrayBuffer[Int]()  
buffer += 1  
buffer += 2  
buffer += 3  
  
val result = buffer.toList  // неизменяемая коллекция

Здесь мутабельная структура используется локально, а наружу возвращается неизменяемый результат.

### Подход 2: Builder-паттерн

Стандартная библиотека предоставляет билдеры.

import scala.collection.mutable.MapBuilder  
  
val builder = new MapBuilder[String, Int](Map.empty)  
builder += "Alice" -> 30  
builder += "Bob"   -> 25  
  
val result = builder.result()

Билдеры позволяют эффективно накапливать элементы и затем получить неизменяемую коллекцию.

Этот подход особенно полезен при построении коллекций в циклах или сложных вычислениях.

## Операции над коллекциями

Стандартная библиотека предоставляет богатый набор функциональных операций.

### map — преобразование 1 → 1

val numbers = List(1, 2, 3)  
val doubled = numbers.map(_ * 2)  
// List(2, 4, 6)

Каждый элемент преобразуется независимо.

---

### filter — отбор по условию

val evens = numbers.filter(_ % 2 == 0)  
// List(2)

Оставляет только элементы, удовлетворяющие предикату.

---

### flatMap — преобразование с разворачиванием

val words = List("hello", "scala")  
val chars = words.flatMap(_.toList)  
// List(h, e, l, l, o, s, c, a, l, a)

Сначала применяется функция, затем результат «сплющивается».

Этот механизм лежит в основе композиции не только коллекций, но и других контейнеров (Option, Either, Try).

---

## foldLeft и foldRight

Сведение коллекции к одному значению.

val sum = numbers.foldLeft(0)(_ + _)  
// 6

- 0 — начальное значение (аккумулятор);
    
- _ + _ — функция агрегации.
    

### Разница между foldLeft и foldRight

numbers.foldLeft(0)(_ - _)  
// ((0 - 1) - 2) - 3 = -6

numbers.foldRight(0)(_ - _)  
// 1 - (2 - (3 - 0)) = 2

Практика:

- foldLeft предпочтительнее (безопаснее по стеку);
    
- foldRight может быть менее эффективен для больших коллекций.

## For-comprehensions

### Что такое for / yield

for — это синтаксический сахар, который компилятор разворачивает в последовательность вызовов:

- map
    
- flatMap
    
- withFilter
    
- foreach
    

Пример:

val result =  
  for  
    x <- List(1, 2, 3)  
    if x % 2 == 1  
  yield x * 10  
  
// List(10, 30)

Эквивалентно приблизительно:

List(1, 2, 3)  
  .withFilter(_ % 2 == 1)  
  .map(_ * 10)

for читается как императивный код, но остаётся декларативной конструкцией.

---

## for не только для коллекций

Механизм работает с любыми типами, поддерживающими соответствующие операции:

for  
  a <- Option(2)  
  b <- Option(3)  
yield a + b  
  
// Some(5)

Аналогично — для Either, Try и других контейнеров.

## Ленивые коллекции

### Строгие vs ленивые вычисления

- Строгие (eager) — элементы вычисляются немедленно.
    
- Ленивые (lazy) — вычисляются только по мере запроса.
    

### LazyList

LazyList — ленивый список (заменяет устаревший Stream).

val naturals: LazyList[Int] =  
  LazyList.from(1)

Ничего не вычисляется до фактического запроса.

Получение элементов:

naturals.take(5).toList  
// List(1, 2, 3, 4, 5)

Вычисляются только необходимые элементы.

---

## Преимущества и риски ленивости

Преимущества:

- экономия памяти;
    
- работа с бесконечными последовательностями;
    
- декларативный стиль.
    

Потенциальные риски:

val xs = LazyList.from(1).map { x =>  
  println(x)  
  x * 2  
}  
  
xs.take(3).toList

Побочные эффекты выполняются только при обращении к элементам.

LazyList также мемоизирует вычисленные значения:

- каждый элемент вычисляется один раз;
    
- повторный доступ не пересчитывает значение.
    

Это удобно, но может удерживать память и приводить к утечкам при неосторожном использовании.
