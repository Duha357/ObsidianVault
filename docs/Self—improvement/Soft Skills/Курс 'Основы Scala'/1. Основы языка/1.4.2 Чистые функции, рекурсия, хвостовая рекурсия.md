# Чистые функции, рекурсия и хвостовая рекурсия

---

## Чистые функции (Pure Functions)

### Определение

Функция считается чистой, если:

1. Она детерминирована — при одинаковых входных параметрах всегда возвращает один и тот же результат.
2. Она не имеет побочных эффектов — не изменяет внешнее состояние и не зависит от него.

> [!example]- Пример: чистая функция
> Складывает количество страниц двух книг. Для одинаковых аргументов возвращает одинаковый результат.
>
> ```scala
> def calculateTotalPages(firstBookPages: Int, secondBookPages: Int): Int = firstBookPages + secondBookPages
> ```
>
> Пример показывает: результат зависит только от аргументов, побочных эффектов нет.

> [!example]- Пример: нечистая функция
> Увеличивает счётчик обработанных книг и возвращает новое значение. Результат зависит от внешней переменной.
>
> ```scala
> var booksProcessed = 0
>
> def processBook(): Int =
>   booksProcessed += 1
>   booksProcessed
> ```
>
> Пример показывает: изменение внешнего состояния делает функцию нечистой.

---

## Побочные эффекты

К побочным эффектам относятся:

- Изменение переменных.
- Ввод/вывод: печать в консоль, работа с файлами.
- Сетевые вызовы.
- Изменение коллекций.
- Бросание исключений.

Чистая функция работает только со своими аргументами и возвращает значение.

---

## Преимущества чистоты

### Предсказуемость

Функцию можно рассматривать как математическое отображение.

### Тестируемость

Нет необходимости в моках глобального состояния.

### Потокобезопасность

Отсутствие изменяемого состояния упрощает параллельное выполнение.

### Композиция

Чистые функции легко комбинируются через map, flatMap, fold.

## Рекурсия

В функциональном стиле рекурсия является основной альтернативой циклам.

> [!example]- Пример: императивный стиль
> Вычисляет сумму страниц циклом с изменяемой переменной.
>
> ```scala
> def totalPages(n: Int): Int =
>   var sum = 0
>   for i <- 1 to bookCount do
>     sum += i * 100
>   sum
> ```
>
> Пример показывает: императивное решение с циклом и мутабельным состоянием.

> [!example]- Пример: функциональный стиль
> Вычисляет сумму страниц рекурсивно, без изменяемых переменных.
>
> ```scala
> def totalPages(n: Int): Int =
>   if bookCount <= 0 then 0
>   else bookCount + totalPages(bookCount - 1)
> ```
>
> Пример показывает: рекурсия определяет задачу через более простую версию самой себя.

Рекурсия выражает решение декларативно: задача определяется через более простую версию самой себя.

---

## Проблема переполнения стека

Каждый рекурсивный вызов занимает место в стеке вызовов.

При глубокой рекурсии возможна ошибка `java.lang.StackOverflowError`.

> [!example]- Пример: переполнение стека
> Вызов рекурсивной функции с большим аргументом.
>
> ```scala
> totalPages(1000000)
> ```
>
> Пример показывает: при глубокой нехвостовой рекурсии стек растёт, возникает StackOverflowError.

Если рекурсивный вызов не является хвостовым, стек будет расти.

## Хвостовая рекурсия

### Определение

Рекурсия называется хвостовой, если рекурсивный вызов — это последнее действие функции.

> [!example]- Пример: нехвостовая рекурсия
> После рекурсивного вызова выполняется сложение — вызов не последнее действие.
>
> ```scala
> def totalPages(bookCount: Int): Int =
>   if bookCount <= 0 then 0
>   else bookCount * 100 + totalPages(bookCount - 1)
> ```
>
> Пример показывает: операция после рекурсивного вызова делает рекурсию нехвостовой.

### Хвостовая версия

Состояние передаётся параметром-аккумулятором.

> [!example]- Пример: хвостовая рекурсия
> Считает страницы через аккумулятор. Рекурсивный вызов — последнее действие функции.
>
> ```scala
> import scala.annotation.tailrec
>
> @tailrec
> def accumulatePages(remainingBooks: Int, total: Int = 0): Int =
>   if remainingBooks <= 0 then total
>   else accumulatePages(remainingBooks - 1, total + 100)
> ```
>
> Пример показывает: аккумулятор передаётся параметром, рекурсия хвостовая.

---

## Tail Call Optimization (TCO)

Scala (на JVM) оптимизирует хвостовую рекурсию:

- Стек не растёт.
- Рекурсия преобразуется в цикл с изменяемой переменной на уровне байткода.
- Достигается эффективность императивного цикла.

JVM поддерживает только самохвостовую оптимизацию (self-recursion). Взаимная рекурсия не оптимизируется автоматически.

---

## Аннотация @tailrec

Аннотация `@tailrec` заставляет компилятор проверить, что функция действительно хвостовая.

Если оптимизация невозможна, компилятор выдаст ошибку.

Это:

- Защищает от случайной потери оптимизации.
- Гарантирует безопасность по стеку.
- Делает намерение разработчика явным.

Рекомендуется всегда использовать `@tailrec`, когда функция должна быть хвостовой.
