Чистая функция зависит только от своих аргументов и не меняет ничего снаружи — поэтому её результат воспроизводим, а вызовы безопасно распараллелить. Отказ от изменяемых счётчиков приводит к рекурсии вместо циклов, а рекурсия упирается в размер стека. Ниже: определение чистоты и её выгоды, рекурсия как замена цикла, проблема переполнения стека и её решение через хвостовую рекурсию с аннотацией `@tailrec`.

## Чистые функции

Функция считается чистой, если выполняются два условия:

1. Она детерминирована: при одинаковых аргументах всегда возвращает одинаковый результат.
2. Она не имеет побочных эффектов: не меняет внешнее состояние и не зависит от него.

> [!example]- Пример: Плохо — нечистая функция
> Функция читает и изменяет переменную, объявленную снаружи. Аргументов у неё нет вовсе, а результат каждый раз новый.
>
> Ожидаемый результат: первый вызов вернёт 1, второй — 2, третий — 3; при параллельном вызове часть увеличений потеряется.
>
> ```scala
> var booksProcessed = 0
>
> def processBook(): Int =
>   booksProcessed += 1 // побочный эффект
>   booksProcessed
> ```
>
> Пример показывает: для чего нужна чистота — иначе результат зависит от истории вызовов, а не от входных данных.

> [!example]- Пример: Хорошо — чистая функция
> Функция использует только аргументы и ничего не меняет снаружи.
>
> Ожидаемый результат: `calculateTotalPages(320, 210)` возвращает 530 при любом числе вызовов и в любом порядке.
>
> ```scala
> def calculateTotalPages(firstBookPages: Int, secondBookPages: Int): Int =
>   firstBookPages + secondBookPages
> ```
>
> Пример показывает: почему чистые функции просто тестировать — достаточно сравнить результат с ожидаемым, окружение готовить не нужно.

---

## Побочные эффекты

К побочным эффектам относятся:

- Изменение переменных за пределами функции.
- Ввод и вывод: печать в консоль, работа с файлами.
- Сетевые вызовы и обращения к базе данных.
- Изменение переданных коллекций и объектов.
- Выбрасывание исключений.

Чистая функция работает только со своими аргументами и возвращает значение.

##### Что даёт чистота

- Предсказуемость: функцию можно рассматривать как математическое отображение входа в выход.
- Тестируемость: не нужны заглушки глобального состояния.
- Потокобезопасность: изменяемого состояния нет, значит, гонок нет.
- Композиция: чистые функции свободно комбинируются через `map`, `flatMap`, `fold`.

## Рекурсия

В функциональном стиле рекурсия занимает место цикла: задача определяется через более простую версию самой себя.

> [!example]- Пример: Императивное решение циклом
> Сумма страниц накапливается в изменяемой переменной, цикл двигает счётчик.
>
> Ожидаемый результат: для `bookCount = 3` результат 600 (100 + 200 + 300).
>
> ```scala
> def totalPages(bookCount: Int): Int =
>   var sum = 0
>   for i <- 1 to bookCount do
>     sum += i * 100
>   sum
> ```
>
> Пример показывает: с чем сравнивается рекурсивное решение.

> [!example]- Пример: Рекурсивное решение
> Функция вызывает себя с уменьшенным аргументом; изменяемых переменных нет.
>
> Ожидаемый результат: для `bookCount = 3` результат 600 — тот же, что и у цикла.
>
> ```scala
> def totalPages(bookCount: Int): Int =
>   if bookCount <= 0 then 0
>   else bookCount * 100 + totalPages(bookCount - 1)
> ```
>
> Пример показывает: зачем рекурсия в функциональном стиле — она выражает тот же обход без изменяемого состояния.

## Проблема переполнения стека

Каждый незавершённый вызов занимает кадр в стеке. Если после рекурсивного вызова остаётся работа, кадры накапливаются.

> [!example]- Пример: Плохо — нехвостовая рекурсия
> После рекурсивного вызова выполняется умножение и сложение, поэтому кадр вызова нельзя освободить до возврата.
>
> Ожидаемый результат: `totalPages(1000000)` завершается с `java.lang.StackOverflowError`.
>
> ```scala
> def totalPages(bookCount: Int): Int =
>   if bookCount <= 0 then 0
>   else bookCount * 100 + totalPages(bookCount - 1) // после вызова ещё есть работа
>
> totalPages(1000000) // StackOverflowError
> ```
>
> Пример показывает: для чего нужна хвостовая рекурсия — иначе глубина рекурсии ограничена размером стека.

> [!example]- Пример: Хорошо — хвостовая рекурсия
> Промежуточный результат передаётся параметром-аккумулятором, поэтому рекурсивный вызов становится последним действием и кадр можно переиспользовать.
>
> Ожидаемый результат: `accumulatePages(1000000)` возвращает 100 000 000 без переполнения стека.
>
> ```scala
> import scala.annotation.tailrec
>
> @tailrec
> def accumulatePages(remainingBooks: Int, total: Int = 0): Int =
>   if remainingBooks <= 0 then total
>   else accumulatePages(remainingBooks - 1, total + 100) // последнее действие
>
> accumulatePages(1000000) // 100000000
> ```
>
> Пример показывает: зачем нужен аккумулятор — он переносит вычисление до рекурсивного вызова и освобождает стек.

---

## Оптимизация хвостового вызова (TCO)

Если рекурсивный вызов является последним действием функции, компилятор Scala преобразует его в цикл на уровне байткода:

- Стек не растёт независимо от глубины рекурсии.
- Производительность совпадает с императивным циклом.
- Код при этом остаётся без изменяемых переменных.

JVM поддерживает оптимизацию только для самовызова. Взаимная рекурсия двух функций автоматически не оптимизируется.

## Аннотация @tailrec

Аннотация — метка для компилятора: она не меняет поведение кода, а включает дополнительную проверку или влияет на генерацию байткода. Записывается символом `@` перед объявлением, к которому относится.

`@tailrec` не включает оптимизацию, а проверяет, что она применима. Если рекурсия не хвостовая, компиляция завершится ошибкой.

> [!example]- Пример: @tailrec на нехвостовой рекурсии
> Аннотация поставлена на функцию, у которой после рекурсивного вызова остаётся умножение.
>
> Ожидаемый результат: ошибка компиляции «could not optimize @tailrec annotated method» — вместо `StackOverflowError` при запуске.
>
> ```scala
> import scala.annotation.tailrec
>
> @tailrec
> def totalPages(bookCount: Int): Int =
>   if bookCount <= 0 then 0
>   else bookCount * 100 + totalPages(bookCount - 1) // ошибка компиляции
> ```
>
> Пример показывает: для чего ставят `@tailrec` — она превращает скрытую проблему рантайма в явную ошибку сборки.

Аннотацию рекомендуется ставить всегда, когда функция задумана как хвостовая: она защищает от случайной потери оптимизации при последующих правках.
