## Частично применённые функции (Partial Application)

##### Идея

Частичное применение — фиксация части аргументов функции с получением новой функции с меньшим числом параметров.

> [!example]- Пример: частичное применение
> `addBooks` суммирует количество книг на двух полках.
>
> Ожидаемый результат: вызов `addLibraryBooks(50)` возвращает `150`.
>
> ```scala
> def addBooks(firstShelf: Int, secondShelf: Int): Int = firstShelf + secondShelf
>
> val addLibraryBooks: Int => Int = addBooks(100, _)
>
> addLibraryBooks(50) // 150
> ```
>
> Пример показывает: фиксация аргумента превращает функцию двух аргументов в функцию одного аргумента.

Определение функции не меняется — фиксируется только один аргумент.

##### Важно: это не PartialFunction

Частично применённая функция — обычная функция.

- Определена для всех допустимых входов.
- **Не:**
    - Содержит логику «определено/не определено».
    - Связана с типом `PartialFunction`.

## Частично определённые функции (PartialFunction)

##### Идея

`PartialFunction[A, B]` — функция, определённая не для всех значений типа `A`.

> [!example]- Пример: частично определённая функция
> `bookCategory` сопоставляет числу категорию книги.
>
> Ожидаемый результат: функция определена для значений 1 и 2, для остальных — не задана.
>
> ```scala
> val bookCategory: PartialFunction[Int, String] =
>   case 1 => "Fantasy"
>   case 2 => "Science Fiction"
> ```
>
> Пример показывает: объявление функции, определённой не для всех входов.

##### Методы PartialFunction

`PartialFunction` имеет два ключевых метода: `isDefinedAt(a: A): Boolean` (проверка области определения) и `apply(a: A): B` (вычисление значения). Вызов неопределённого значения (например, `bookCategory(3)`) бросает исключение.

> [!example]- Пример: isDefinedAt
> `isDefinedAt` проверяет, определена ли функция для переданного значения.
>
> Ожидаемый результат: для `bookCategory` возвращает `true` для 1 и `false` для 5.
>
> ```scala
> bookCategory.isDefinedAt(1) // true
> bookCategory.isDefinedAt(5) // false
> ```
>
> Пример показывает: `isDefinedAt` различает определённые и неопределённые входы.

##### orElse

`orElse` объединяет частичные функции: результат определён, если определена хотя бы одна из исходных.

> [!example]- Пример: orElse
> `fictionCategory` и `scienceCategory` объединяются через `orElse`.
>
> Ожидаемый результат: `allCategories` определена для 1 и 2.
>
> ```scala
> val fictionCategory: PartialFunction[Int, String] =
>   case 1 => "Fantasy"
>
> val scienceCategory: PartialFunction[Int, String] =
>   case 2 => "Science Fiction"
>
> val allCategories = fictionCategory.orElse(scienceCategory)
> ```
>
> Пример показывает: `orElse` расширяет область определения объединением функций.

##### Где используются PartialFunction

- `collect` в коллекциях применяет функцию к определённым элементам.
- Обработка сообщений (например, в акторных системах).
- Декларативное описание правил.

> [!example]- Пример: collect
> `collect` применяет case к элементам списка.
>
> Ожидаемый результат: элемент 100 отбрасывается, 200 и 350 становятся 250 и 400.
>
> ```scala
> List(100, 200, 350).collect:
>   case pages if pages > 150 => pages + 50
> ```
>
> Пример показывает: `collect` объединяет фильтрацию и преобразование через `PartialFunction`.

## Каррирование

##### Определение

Каррирование — преобразование функции нескольких аргументов в цепочку функций одного аргумента.

Исходный тип:

```scala
(A, B) => C
```

Каррированный тип:

```scala
A => B => C
```

##### Пример

Каррированная версия отличается от некаррированной списками параметров.

> [!example]- Пример: каррирование
> Объявлены некаррированная и каррированная версии `calculatePages`.
>
> Ожидаемый результат: `calculatePages(3)` возвращает функцию `Int => Int`, вызов с 200 даёт `600`.
>
> ```scala
> def calculatePages(bookCount: Int, pagesPerBook: Int): Int = bookCount * pagesPerBook
>
> def calculatePages(bookCount: Int)(pagesPerBook: Int): Int = bookCount * pagesPerBook
>
> val pagesForThreeBooks = calculatePages(3)
> pagesForThreeBooks(200) // 600
> ```
>
> Пример показывает: каррирование разбивает аргументы на последовательные вызовы функций одного аргумента.

##### Автоматическое каррирование

Функциональные значения каррируются через `.curried`.

> [!example]- Пример: .curried
> `.curried` преобразует функциональное значение `multiplyPages`.
>
> Ожидаемый результат: тип `(Int, Int) => Int` становится `Int => Int => Int`.
>
> ```scala
> val multiplyPages: (Int, Int) => Int = _ * _
> val curriedPages = multiplyPages.curried
> ```
>
> Пример показывает: `.curried` автоматически каррирует функциональное значение.

## Группы параметров (Multiple Parameter Lists)

Scala позволяет объявлять функцию с несколькими списками параметров. Это влияет на:

- Каррирование.
- Вывод типов.
- Контекстные абстракции (`using`).
- Частичное применение.

> [!example]- Пример: несколько списков параметров
> `calculateShelfCapacity` принимает два списка параметров.
>
> Ожидаемый результат: вызов с аргументами возвращает произведение `rows * booksPerRow`.
>
> ```scala
> def calculateShelfCapacity(rows: Int)(booksPerRow: Int): Int = rows * booksPerRow
> ```
>
> Пример показывает: синтаксис групп параметров — несколько списков параметров у одной функции.

##### Улучшение вывода типов

Группы параметров помогают компилятору выводить типы при передаче функций.

> [!example]- Пример: вывод типов
> `applyTo` применяет функцию `f` к аргументу `a`.
>
> Ожидаемый результат: тип `A` выводится из первого списка параметров, тип `B` — из переданной функции.
>
> ```scala
> def applyTo[A, B](a: A)(f: A => B): B = f(a)
> ```
>
> Пример показывает: тип `A` определяется из первого списка, вызов упрощается.

##### Удобство частичного применения

Несколько списков параметров упрощают частичное применение: первый аргумент фиксируется без `_`.

> [!example]- Пример: частичное применение через группы параметров
> `compute(2)` фиксирует первый аргумент.
>
> Ожидаемый результат: возвращается функция `Int => Int` — `multiplyBy2`.
>
> ```scala
> val multiplyBy2 = compute(2)
> ```
>
> Пример показывает: первый список параметров фиксируется вызовом без синтаксиса `_`.

##### Связь с контекстными параметрами

Множественные списки параметров отделяют основные аргументы от контекстных (`using`).

- Основные аргументы.
- Контекстные аргументы (`using`).

Это фундамент для type classes и контекстных абстракций.

## Сравнение понятий

| Концепция | Смысл |
|---|---|
| Частичное применение | Фиксация части аргументов |
| PartialFunction | Функция, определённая не для всех входов |
| Каррирование | Преобразование в цепочку функций |
| Группы параметров | Синтаксис поддержки каррирования и вывода типов |
