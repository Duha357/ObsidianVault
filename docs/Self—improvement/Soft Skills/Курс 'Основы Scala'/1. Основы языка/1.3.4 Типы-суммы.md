Тип-сумма описывает значение, которое может быть одного из нескольких вариантов, но только одного одновременно: A **или** B. Если тип-произведение объединяет данные, то тип-сумма задаёт альтернативу. Ниже: моделирование альтернатив через `sealed trait` и `enum`, проверка полноты `match` компилятором и стандартные типы-суммы `Either` и `Try`.

---

## Тип-сумма как логическое «ИЛИ»

Примеры альтернатив из предметной области:

- Книга существует в бумажном виде **или** в электронном.
- Ответ каталога — успех **или** ошибка.
- Экземпляр доступен **или** выдан читателю.

В отличие от типа-произведения, где поля существуют вместе, здесь варианты взаимно исключают друг друга.

---

## Реализация через sealed trait

Тип-сумма моделируется закрытой иерархией: общий трейт и перечисленные варианты.

> [!example]- Пример: Тип-сумма через sealed trait
> `BookFormat` объявлен как `sealed`, поэтому наследоваться от него можно только в этом файле. Варианты — два case-класса с собственными полями.
>
> Ожидаемый результат: значение типа `BookFormat` — это либо `PrintedBook`, либо `Ebook`; третьего варианта появиться не может.
>
> ```scala
> sealed trait BookFormat
>
> case class PrintedBook(title: String) extends BookFormat
> case class Ebook(fileSize: Double) extends BookFormat
> ```
>
> Пример показывает: зачем нужен `sealed` — он закрывает набор вариантов и позволяет компилятору знать их все.

##### Почему sealed важно

Ключевое слово `sealed` означает:

- Все наследники объявлены в том же файле.
- Компилятор знает полный список вариантов.

Отсюда следует главное преимущество — проверка полноты `match`.

---

## Исчерпывающее сопоставление

Компилятор требует, чтобы `match` покрывал все варианты типа-суммы, и предупреждает, если какой-то забыт.

> [!example]- Пример: Плохо — открытая иерархия
> Трейт объявлен без `sealed`, поэтому наследника можно добавить в любом файле. Компилятор не знает полного списка и не может проверить полноту.
>
> Ожидаемый результат: код компилируется без предупреждений, но при появлении третьего формата `describeFormat` упадёт с `MatchError` во время выполнения.
>
> ```scala
> trait BookFormat // без sealed
>
> case class PrintedBook(title: String) extends BookFormat
> case class Ebook(fileSize: Double) extends BookFormat
>
> def describeFormat(format: BookFormat): String =
>   format match
>     case PrintedBook(title) => s"Printed: $title"
>     case Ebook(size)        => s"Ebook size: $size"
> ```
>
> Пример показывает: для чего нужна закрытая иерархия — без неё пропущенная ветка обнаруживается только при запуске.

> [!example]- Пример: Хорошо — закрытая иерархия
> Тот же `match`, но иерархия объявлена через `sealed`. Компилятор сверяет список веток с полным списком вариантов.
>
> Ожидаемый результат: все ветки покрыты, ветка по умолчанию не нужна. При добавлении третьего формата компилятор выдаст предупреждение о неполном `match`.
>
> ```scala
> sealed trait BookFormat
>
> case class PrintedBook(title: String) extends BookFormat
> case class Ebook(fileSize: Double) extends BookFormat
>
> def describeFormat(format: BookFormat): String =
>   format match
>     case PrintedBook(title) => s"Printed: $title"
>     case Ebook(size)        => s"Ebook size: $size"
> ```
>
> Пример показывает: зачем типы-суммы предпочитают ООП-полиморфизму — компилятор напоминает о каждом месте, которое нужно дополнить.

## sealed enum (Scala 3)

Scala 3 даёт компактную запись для той же конструкции.

> [!example]- Пример: Плохо — статус строкой
> Состояние экземпляра книги хранится в `String`. Компилятор принимает любое значение, включая опечатку.
>
> Ожидаемый результат: `checkStatus("Borowed")` компилируется и молча попадает в ветку по умолчанию — опечатка не обнаружена.
>
> ```scala
> def checkStatus(status: String): String =
>   status match
>     case "Available" => "Можно выдать"
>     case "Borrowed"  => "Уже на руках"
>     case _           => "Неизвестный статус" // сюда попадают все опечатки
> ```
>
> Пример показывает: для чего нужен отдельный тип для набора состояний — `String` допускает любое значение.

> [!example]- Пример: Хорошо — enum
> `enum` перечисляет допустимые варианты, причём каждый может нести собственные поля.
>
> Ожидаемый результат: передать несуществующий статус нельзя — опечатка становится ошибкой компиляции.
>
> ```scala
> enum BookStatus:
>   case Available(title: String)
>   case Borrowed(days: Int)
> ```
>
> Пример показывает: зачем `enum` — компактная запись закрытой иерархии, где набор состояний задан типом.

`enum` по умолчанию является `sealed`, поддерживает параметры вариантов и подходит для моделирования конечных множеств состояний.

## Either — стандартный тип-сумма

`Either[L, R]` представляет значение одного из двух типов:

- `Left[L]` — ошибка.
- `Right[R]` — успешный результат.

> [!example]- Пример: Плохо — ошибка через исключение
> Отсутствие книги сигнализируется исключением. Тип результата обещает, что книга будет найдена всегда.
>
> Ожидаемый результат: `findBook("999")` компилируется и падает с `NoSuchElementException` — вызывающий код не обязан был это предусмотреть.
>
> ```scala
> def findBook(bookId: String): String =
>   if bookId == "101" then "The Hobbit"
>   else throw new NoSuchElementException("Book not found")
> ```
>
> Пример показывает: почему исключение не годится для ожидаемой ошибки — сигнатура о ней умалчивает.

> [!example]- Пример: Хорошо — ошибка через Either
> Оба исхода отражены в типе результата: `Left` несёт сообщение об ошибке, `Right` — найденное название.
>
> Ожидаемый результат: `findBook("101")` — `Right("The Hobbit")`, `findBook("999")` — `Left("Book not found")`.
>
> ```scala
> def findBook(bookId: String): Either[String, String] =
>   if bookId == "101" then Right("The Hobbit")
>   else Left("Book not found")
> ```
>
> Пример показывает: зачем `Either` — ошибка становится обычным значением, о котором известно из сигнатуры.

##### Разбор через pattern matching

Значение `Either` раскладывается на два случая.

> [!example]- Пример: Разбор Either
> `match` обрабатывает оба варианта отдельными ветками. Пропустить один из них компилятор не даст.
>
> Ожидаемый результат: для `Right` печатается название книги, для `Left` — текст ошибки.
>
> ```scala
> findBook("101") match
>   case Right(title) => println(s"Found: $title")
>   case Left(error)  => println(s"Error: $error")
> ```
>
> Пример показывает: для чего нужен разбор по образцу — извлечь значение можно, только обработав обе ветви.

##### Either вместо исключений

| Подход | Как выражена ошибка | Поток выполнения |
|---|---|---|
| Исключения | Побочный эффект, скрытый от типа | Прерывается неявно |
| `Either` | Значение, отражённое в типе | Остаётся явным |

Преимущества `Either`:

1. Отсутствие скрытых побочных эффектов.
2. Возможность ошибки видна в сигнатуре.
3. Лучшая композиция через `flatMap` и `for`.

## Try

`Try[A]` — ещё один стандартный тип-сумма с двумя вариантами: `Success[A]` и `Failure[Throwable]`. Он предназначен для обёртки кода, который выбрасывает исключения.

> [!example]- Пример: Обёртка исключения в Try
> Метод `toInt` выбрасывает `NumberFormatException` на некорректной строке. `Try` перехватывает его и превращает в значение.
>
> Ожидаемый результат: `Try("42".toInt)` — `Success(42)`; для `Try("abc".toInt)` — `Failure(NumberFormatException)`, без прерывания выполнения.
>
> ```scala
> import scala.util.Try
>
> val result = Try("42".toInt)
> ```
>
> Пример показывает: зачем нужен `Try` — он переводит чужой код, бросающий исключения, в модель «ошибка как значение».

##### Сравнение Either и Try

| Характеристика | `Either` | `Try` |
|---|---|---|
| Тип ошибки | Произвольный `L` | Только `Throwable` |
| Гибкость | Высокая | Ограничена исключениями |
| Область применения | Бизнес-логика | Обёртка над исключениями |

`Either` предпочтителен для доменных ошибок, `Try` — для интеграции с кодом JVM, который бросает исключения.

---

## Сравнение «И» и «ИЛИ»

| Тип | Логика | Пример |
|---|---|---|
| Произведение | A и B | `case class Book(title: String, pages: Int)` |
| Сумма | A или B | `Either[String, Book]` |

Тип-произведение объединяет данные, тип-сумма описывает альтернативы. Вместе они образуют основу алгебраических типов данных (ADT).
