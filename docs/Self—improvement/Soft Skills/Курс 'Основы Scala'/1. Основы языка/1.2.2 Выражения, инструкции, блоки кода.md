Инструкция (statement) выполняет действие и ничего не возвращает; выражение (expression) вычисляется и возвращает значение. В Scala почти всё является выражением — включая `if`, `match` и блок кода, — поэтому программа строится композицией выражений, а не последовательностью команд. Ниже: различие двух понятий, следствия для `return`, побочных эффектов и точки с запятой.

---

## Выражение против инструкции

##### Инструкция (statement)

Инструкция выполняется ради побочного эффекта: она что-то делает, но её результат нельзя присвоить.

> [!example]- Пример: if как инструкция в Java
> Конструкция `if` в Java печатает сообщение, но значения не даёт — записать `int x = if (...)` нельзя.
>
> Ожидаемый результат: при `bookCount > 0` печатается `Books available`; результата у конструкции нет.
>
> ```java
> if (bookCount > 0) {
>     System.out.println("Books available");
> }
> ```
>
> Пример показывает: с чем сравнивается выраженческая модель Scala.

##### Выражение (expression)

Выражение вычисляется, возвращает значение и может входить в состав более крупного выражения.

---

## Почти всё — выражение

В Scala значение возвращают арифметика, `if`, `match` и блок кода.

##### Арифметические операции

> [!example]- Пример: Арифметическое выражение
> Сложение двух литералов вычисляется и присваивается имени.
>
> Ожидаемый результат: `totalBooks` — 40, тип результата `Int`.
>
> ```scala
> val totalBooks = 15 + 25
> ```
>
> Пример показывает: почему арифметика — базовый случай выражения: у неё есть результат.

##### Условные конструкции

`if` возвращает значение, поэтому заменяет тернарный оператор `?:` и позволяет обойтись без промежуточного `var`.

> [!example]- Пример: Плохо — if как инструкция
> Значение объявлено через `var` и заполняется внутри веток. Инициализация и присваивание разнесены, тип приходится писать вручную.
>
> Ожидаемый результат: `libraryStatus` получает `"open"` или `"empty"`, но между объявлением и присваиванием переменная содержит заглушку.
>
> ```scala
> var libraryStatus = "" // заглушка до вычисления
>
> if bookCount > 0 then libraryStatus = "open"
> else libraryStatus = "empty"
> ```
>
> Пример показывает: для чего `if` сделали выражением — иначе появляется лишняя изменяемая переменная.

> [!example]- Пример: Хорошо — if как выражение
> Результат `if` присваивается напрямую, `var` не нужен.
>
> Ожидаемый результат: при `bookCount > 0` — `"open"`, иначе `"empty"`; `libraryStatus` неизменяем.
>
> ```scala
> val libraryStatus =
>   if bookCount > 0 then "open"
>   else "empty"
> ```
>
> Пример показывает: зачем выраженческая модель — значение вычисляется там же, где объявляется.

Тип результата `if` — общий тип обеих веток. Если ветки возвращают разное, компилятор поднимается до ближайшего общего супертипа.

> [!example]- Пример: Общий тип веток
> В первом случае обе ветки дают `Int`. Во втором — `Int` и `String`, общий супертип для них только `Any`.
>
> Ожидаемый результат: `shelfNumber` — `Int`, `shelfLabel` — `Any`; вызвать у `shelfLabel` методы `Int` или `String` уже нельзя.
>
> ```scala
> val shelfNumber = if hasBooks then 1 else 2         // Int
> val shelfLabel  = if hasBooks then 1 else "unknown" // Any
> ```
>
> Пример показывает: почему ветки лучше приводить к одному типу — иначе результат вырождается в `Any` и теряет полезные методы.

##### Match-выражения

`match` — тоже выражение: возвращает значение ветки, которая совпала.

> [!example]- Пример: Match как выражение
> Значение сравнивается с образцами, результат ветки становится результатом всего выражения.
>
> Ожидаемый результат: при `bookCount = 0` — `"no books"`, иначе — `"books: N"`, где N равно `bookCount`.
>
> ```scala
> val bookCategory = bookCount match
>   case 0 => "no books"
>   case n => s"books: $n" // n связывается с проверяемым значением
> ```
>
> Пример показывает: почему `match` заменяет `switch` — у него есть результат, а не только побочный эффект.

##### Блок как выражение

Блок `{ ... }` объединяет выражения, имеет собственную область видимости и возвращает значение последнего выражения.

> [!example]- Пример: Блок возвращает последнее выражение
> Блок объявляет два локальных значения и заканчивается их суммой.
>
> Ожидаемый результат: `availableBooks` — 30; `fictionBooks` и `scienceBooks` снаружи недоступны.
>
> ```scala
> val availableBooks = {
>   val fictionBooks = 10
>   val scienceBooks = 20
>   fictionBooks + scienceBooks // результат блока
> }
> ```
>
> Пример показывает: для чего блок-выражение — вычисление и его временные значения остаются в одном месте.

## Отсутствие необходимости в return

Метод возвращает значение последнего выражения. `return` не требуется и в идиоматическом коде не используется: он вводит императивный преждевременный выход и ломает выраженческую модель.

> [!example]- Пример: Плохо — явный return
> Тело метода состоит из одного выражения, но результат возвращается ключевым словом.
>
> Ожидаемый результат: `doubleBook(5)` возвращает 10 — как и без `return`, только запись длиннее.
>
> ```scala
> def doubleBook(count: Int): Int =
>   return count * 2 // избыточно
> ```
>
> Пример показывает: почему `return` в Scala встречается редко — он ничего не добавляет.

> [!example]- Пример: Хорошо — неявный возврат
> Результат метода — значение последнего выражения тела.
>
> Ожидаемый результат: `doubleBook(5)` возвращает 10.
>
> ```scala
> def doubleBook(count: Int): Int =
>   count * 2
> ```
>
> Пример показывает: зачем неявный возврат — тело метода читается как формула, а не как последовательность команд.

## Побочные эффекты и тип Unit

Выражение, выполняемое ради эффекта, возвращает `Unit` — аналог `void`, но полноценный тип с единственным значением `()`.

> [!example]- Пример: Результат println
> Результат вызова `println` присваивается имени.
>
> Ожидаемый результат: строка печатается в консоль, `result` получает тип `Unit` и значение `()`.
>
> ```scala
> val result = println("New book added") // result: Unit = ()
> ```
>
> Пример показывает: почему в Scala нет исключений из правила «всё — выражение» — даже побочный эффект имеет тип результата.

Подробнее о `Unit` — в разделе 1.3.2.

## Точка с запятой

Компилятор разделяет выражения по переводу строки, поэтому `;` не нужна. Она требуется только при нескольких выражениях на одной строке.

> [!example]- Пример: Хорошо — по выражению на строку
> Два объявления записаны на разных строках, разделитель не нужен.
>
> Ожидаемый результат: `authorName` — `"Tolkien"`, `bookTitle` — `"The Hobbit"`.
>
> ```scala
> val authorName = "Tolkien"
> val bookTitle = "The Hobbit"
> ```
>
> Пример показывает: зачем идиоматический стиль «одно выражение — одна строка» — разделители не нужны вовсе.

> [!example]- Пример: Плохо — несколько выражений на строке
> Два объявления на одной строке требуют явного разделителя и хуже читаются.
>
> Ожидаемый результат: оба значения объявлены, но код плотнее без выигрыша.
>
> ```scala
> val authorName = "Rowling"; val bookTitle = "Harry Potter"
> ```
>
> Пример показывает: почему `;` в Scala почти не встречается — она нужна только в этом случае.

## Сравнение с Java

| Концепция | Java | Scala |
|---|---|---|
| if | инструкция | выражение |
| switch | инструкция | `match`-выражение |
| блок | группа инструкций | выражение |
| return | обязателен | не требуется |
| void | не тип | `Unit` — тип |
