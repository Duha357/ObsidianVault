# Стили программирования в Scala: объектно-ориентированный и функциональный подходы

Одной из ключевых особенностей языка Scala является поддержка нескольких стилей программирования. Scala изначально проектировался как гибридный язык, не противопоставляющий объектно-ориентированное программирование (ООП) и функциональное программирование (ФП), а объединяющий их в рамках единой, согласованной языковой модели.

В Scala 3 разработчик не обязан жёстко выбирать одну парадигму и следовать ей во всём проекте. Язык предоставляет выразительные средства, позволяющие использовать сильные стороны как ООП, так и ФП, а также комбинировать их там, где это оправдано архитектурно и концептуально.

---

## Общая характеристика парадигм в Scala

### Объектно-ориентированный аспект

С точки зрения объектно-ориентированного программирования в Scala:

- каждое значение является объектом;
    
- поведение и данные инкапсулируются в классах;
    
- поддерживаются наследование, полиморфизм и инкапсуляция;
    
- используется композиция поведения через трейты и миксины.
    

Scala проектировался с учётом необходимости бесшовной интеграции с существующими объектно-ориентированными системами, в первую очередь с Java. Это делает объектную модель Scala знакомой и интуитивно понятной для разработчиков, имеющих опыт в классических ООП-языках.

### Функциональный аспект

С функциональной точки зрения Scala поддерживает ключевые идеи ФП:

- функции являются значениями первого класса;
    
- широко используются функции высшего порядка;
    
- поощряется неизменяемость данных;
    
- активно применяется сопоставление с образцом (pattern matching);
    
- стандартная библиотека ориентирована на декларативную обработку данных.
    

Функциональные возможности Scala не являются надстройкой — они встроены в язык на уровне синтаксиса и системы типов.

## Поддержка объектно-ориентированного программирования

### Инкапсуляция

Инкапсуляция в Scala реализуется с помощью классов, модификаторов доступа и контроля над состоянием объекта. Как и в классических ООП-языках, внутреннее состояние объекта скрывается от внешнего кода и доступно только через публичный интерфейс.

class LibraryBook(private var copies: Int):  
  
  def addCopies(amount: Int): Unit =  
    if amount > 0 then  
      copies += amount  
  
  def getCopies: Int = copies

В данном примере:

- поле balance недоступно извне;
    
- изменение состояния возможно только через методы класса;
    
- объект самостоятельно контролирует корректность операций.
    

Инкапсуляция позволяет защищать инварианты и снижать связность между компонентами системы.

---

### Наследование

Scala поддерживает наследование классов, позволяя расширять или специализировать поведение базовых типов.

class Book:  
  def genre: String = "unknown"  
  
class Novel extends Book:  
  override def genre: String = "fiction"

Класс Dog наследует поведение Book и переопределяет метод genre. Наследование используется для повторного использования кода и построения иерархий типов.

При этом в Scala наследование обычно дополняется или заменяется композицией через трейты, что снижает жесткость иерархий — этот аспект будет рассмотрен в последующих лекциях.

---

### Полиморфизм

Полиморфизм позволяет работать с объектами различных классов через общий базовый тип.

def printGenre(book: Book): Unit =  
  println(book.genre)  
  
val b: Book = Novel()  
printGenre(a) // fiction 

Функция printGenre не зависит от конкретной реализации Book. Поведение определяется динамически, в зависимости от фактического типа объекта. Такой подход лежит в основе расширяемости объектно-ориентированных систем.

## Поддержка функционального программирования

### Неизменяемость данных

В функциональном стиле программирования предпочтение отдаётся неизменяемым данным. В Scala это выражается использованием val вместо var.

val books = List("Scala Basics", "FP in Scala", "OOP Design")  
val firstBook = books.head  
val bookCount = books.length  

  
println(firstBook)  // Scala Basics  
println(bookCount)  // 3 

Исходная коллекция не изменяется — создается новая. Такой подход:

- уменьшает количество ошибок, связанных с состоянием;
    
- упрощает параллельное и асинхронное программирование;
    
- делает код более предсказуемым.
    

---

### Чистые функции

Чистой называется функция, которая:

- зависит только от входных аргументов;
    
- не имеет побочных эффектов;
    
- всегда возвращает одинаковый результат для одинаковых входных данных.  
      
    

def totalPages(book1: Int, book2: Int): Int = book1 + book2 

Чистые функции проще тестировать, анализировать и комбинировать. Они являются базовым строительным блоком функционального программирования.

---

### Функции высшего порядка

В Scala функции являются значениями и могут передаваться в качестве аргументов или возвращаться как результат.

def processPages(count: Int, f: Int => Int): Int =  
  f(count)  
  
val doublePages = (x: Int) => x * 2  
  
println(processPages(150, doublePages)) // 300

Функции высшего порядка позволяют строить декларативные и переиспользуемые абстракции для обработки данных.

## Взаимодополняемость ООП и ФП

Ключевая идея Scala заключается в том, что объектно-ориентированный и функциональный подходы не конкурируют, а дополняют друг друга.

Типичный стиль Scala-кода:

- ООП используется для моделирования структуры системы и предметной области;
    
- ФП — для описания логики и обработки данных.
    

### Пример: объектная модель и функциональная обработка

case class Author(name: String, books: Int)  
  
val authors = List(  
  Author("George Orwell", 6),  
  Author("Jane Austen", 8),  
  Author("Franz Kafka", 2)  
)  
  
val popularAuthors  =  
  authors  
    .filter(author => author.books >= 3)  
    .map(author => author.name)  
  
println(popularAuthors) // List(George Orwell, Jane Austen)

В этом примере:

- Author описывает доменную сущность;
    
- List, filter, map реализуют функциональную обработку данных;
    
- код читается декларативно, описывая что нужно получить, а не как это сделать.

## Философия гибридности Scala 3

Scala 3 не навязывает разработчику строгую парадигму программирования. Философия языка основана на осознанном выборе инструментов под конкретную задачу:

- не «чистое функциональное программирование любой ценой»;
    
- не классическое ООП с повсеместным изменяемым состоянием;
    
- приоритет читаемости, надежности и выразительности кода.
    

Scala позволяет:

- писать функционально чистый код там, где важны надежность и предсказуемость;
    
- использовать объектную модель и инкапсуляцию для сложных доменных структур;
    
- комбинировать оба подхода без архитектурных конфликтов.
    

Scala 3 усиливает эту философию за счёт более ясного синтаксиса, строгой типовой системы и улучшенной поддержки декларативного и неизменяемого стиля программирования.
