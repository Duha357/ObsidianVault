## Стили программирования в Scala: объектно-ориентированный и функциональный подходы

Scala — гибридный язык: ООП и ФП не противопоставлены, а объединены в единой языковой модели.

В Scala 3 парадигму выбирают под задачу. Средства языка используют сильные стороны ООП и ФП и комбинируют их.

##### Объектно-ориентированный аспект

- Каждое значение является объектом.
- Поведение и данные инкапсулируются в классах.
- Поддерживаются наследование, полиморфизм и инкапсуляция.
- Используется композиция поведения через трейты и миксины.

Объектная модель интегрируется с Java и знакома разработчикам классических ООП-языков.

##### Функциональный аспект

- Функции являются значениями первого класса.
- Широко используются функции высшего порядка.
- Поощряется неизменяемость данных.
- Активно применяется сопоставление с образцом (pattern matching).
- Стандартная библиотека ориентирована на декларативную обработку данных.

Функциональные возможности встроены в язык на уровне синтаксиса и системы типов.

## Поддержка объектно-ориентированного программирования

##### Инкапсуляция

Инкапсуляция реализуется классами, модификаторами доступа и контролем состояния. Внутреннее состояние скрыто от внешнего кода, доступ — через публичный интерфейс.

> [!example]- Пример: инкапсуляция
> Код определяет класс `LibraryBook` с приватным полем `copies` и методами `addCopies`/`getCopies`.
>
> Экземпляр `LibraryBook(10)`: `addCopies(5)` доводит `copies` до 15, `getCopies` возвращает 15, прямое обращение к `copies` снаружи — ошибка компиляции.
>
> ```scala
> class LibraryBook(private var copies: Int):
>   def addCopies(amount: Int): Unit =
>     if amount > 0 then
>       copies += amount
>   
>   def getCopies: Int = copies
> ```
>
> Пример показывает: методы защищают состояние от некорректного доступа.

- Объект проверяет корректность операций перед изменением (`amount > 0`).
- Защита инвариантов снижает связность компонентов системы.

##### Наследование

Наследование позволяет расширять или специализировать поведение базовых типов. Наследование переиспользует код и строит иерархии типов.

> [!example]- Пример: наследование
> Код объявляет `Book` с методом `genre` и подкласс `Novel`, переопределяющий его.
>
> `Novel().genre` возвращает `"fiction"` вместо `"unknown"`.
>
> ```scala
> class Book:
>   def genre: String = "unknown"
>
> class Novel extends Book:
>   override def genre: String = "fiction"
> ```
>
> Пример показывает: подкласс специализирует поведение родителя.

Композиция через трейты дополняет или заменяет наследование и снижает жёсткость иерархий. Подробнее — в последующих лекциях.

##### Полиморфизм

Полиморфизм позволяет работать с объектами разных классов через общий базовый тип. Поведение определяется динамически, по фактическому типу объекта.

> [!example]- Пример: полиморфизм
> Код определяет функцию `printGenre`, принимающую `Book`, и переменную типа `Book` с экземпляром `Novel`.
>
> `printGenre(Novel())` печатает `fiction`.
>
> ```scala
> def printGenre(book: Book): Unit =
>   println(book.genre)
>
> val b: Book = Novel()
> printGenre(a) // fiction
> ```
>
> Пример показывает: метод принимает любой подтип `Book`, поведение выбирается по фактическому типу.

Такой подход лежит в основе расширяемости ООП-систем.

## Поддержка функционального программирования

##### Неизменяемость данных

ФП предпочитает неизменяемые данные. В Scala это выражается через `val` вместо `var`. Операции не меняют исходную коллекцию, а создают новые значения.

> [!example]- Пример: неизменяемость данных
> Код объявляет список `books` через `val` и вычисляет `firstBook`/`bookCount` операциями `head` и `length`.
>
> `firstBook` — `"Scala Basics"`, `bookCount` — 3, исходный список `books` не изменён.
>
> ```scala
> val books = List("Scala Basics", "FP in Scala", "OOP Design")
> val firstBook = books.head
> val bookCount = books.length
>
> println(firstBook)  // Scala Basics
> println(bookCount)  // 3
> ```
>
> Пример показывает: данные доступны только для чтения, операции создают новые значения.

- Уменьшает количество ошибок, связанных с состоянием.
- Упрощает параллельное и асинхронное программирование.
- Делает код более предсказуемым.

##### Чистые функции

Чистая функция:

- Зависит только от входных аргументов.
- Не имеет побочных эффектов.
- Всегда возвращает одинаковый результат для одинаковых входных данных.

Чистые функции проще тестировать и комбинировать. Базовый строительный блок ФП.

> [!example]- Пример: чистая функция
> Код определяет функцию `totalPages`, складывающую два аргумента.
>
> `totalPages(150, 210)` возвращает 360. Повторный вызов с теми же аргументами даёт тот же результат, внешнее состояние не меняется.
>
> ```scala
> def totalPages(book1: Int, book2: Int): Int = book1 + book2
> ```
>
> Пример показывает: чистые функции легко тестировать.

##### Функции высшего порядка

Функции передаются как аргументы или возвращаются как результат. Функции высшего порядка строят декларативные переиспользуемые абстракции обработки данных.

> [!example]- Пример: функция высшего порядка
> Код определяет `processPages`, принимающую функцию `f`, и функцию-значение `doublePages`.
>
> `processPages(150, doublePages)` возвращает 300: `doublePages` передана аргументом и вызвана внутри `processPages`.
>
> ```scala
> def processPages(count: Int, f: Int => Int): Int =
>   f(count)
>
> val doublePages = (x: Int) => x * 2
>
> println(processPages(150, doublePages)) // 300
> ```
>
> Пример показывает: функция используется как значение.

## Взаимодополняемость ООП и ФП

ООП и ФП не конкурируют, а дополняют друг друга.

- ООП моделирует структуру системы и предметную область.
- ФП описывает логику и обработку данных.

> [!example]- Пример: объектная модель и функциональная обработка
> Код объявляет `case class Author` и список `authors`, затем строит `popularAuthors` через `filter` и `map`.
>
> `popularAuthors` — `List(George Orwell, Jane Austen)`: отфильтрованы авторы с 3+ книгами, извлечены имена.
>
> ```scala
> case class Author(name: String, books: Int)
>
> val authors = List(
>   Author("George Orwell", 6),
>   Author("Jane Austen", 8),
>   Author("Franz Kafka", 2)
> )
>
> val popularAuthors =
>   authors
>     .filter(author => author.books >= 3)
>     .map(author => author.name)
>
> println(popularAuthors) // List(George Orwell, Jane Austen)
> ```
>
> Пример показывает: `case class` моделирует домен, `filter` и `map` обрабатывают данные.

Код читается декларативно: описывает, что получить, а не как.

## Философия гибридности Scala 3

Scala 3 не навязывает строгую парадигму. Инструменты выбираются под конкретную задачу:

- Приоритет читаемости, надёжности и выразительности кода.
- **Не:**
    - Чистое функциональное программирование любой ценой.
    - Классическое ООП с повсеместным изменяемым состоянием.

Scala позволяет:

- Писать функционально чистый код там, где важны надёжность и предсказуемость.
- Использовать объектную модель и инкапсуляцию для сложных доменных структур.
- Комбинировать оба подхода без архитектурных конфликтов.

Scala 3 усиливает философию: ясный синтаксис, строгая типовая система, поддержка декларативного и неизменяемого стиля.
