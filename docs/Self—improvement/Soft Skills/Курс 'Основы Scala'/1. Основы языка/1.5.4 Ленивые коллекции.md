# Ленивые коллекции в Scala: LazyList и бесконечные последовательности

---

# Строгие (eager) и ленивые (lazy) вычисления

## Строгие коллекции

Большинство стандартных коллекций (List, Vector, Set, Map) являются строгими.

Это означает:

- элементы вычисляются немедленно;
    
- операции map, filter создают новую коллекцию сразу;
    
- вся структура полностью построена в момент создания.
    

Пример:

val list = List(1, 2, 3).map(_ * 2)

Все элементы вычисляются немедленно.

---

## Ленивые вычисления

Ленивые коллекции вычисляют элементы только по мере запроса.

Идея:

значение не вычисляется, пока оно не потребуется.

Это позволяет:

- экономить ресурсы;
    
- работать с потенциально бесконечными структурами.
    

---

# LazyList в Scala 3

LazyList — ленивый список.

Он является заменой устаревшего Stream (Scala 2).

Основные свойства:

- элементы вычисляются по требованию;
    
- вычисленные значения запоминаются (мемоизируются);
    
- поддерживает те же операции, что и обычные коллекции.
    

---

## Создание LazyList

Пример конечной последовательности:

val lazyList = LazyList(1, 2, 3)

Более показательный пример:

val numbers: LazyList[Int] =  
  LazyList.from(1)

Это бесконечная последовательность:

1, 2, 3, 4, ...

---

## Получение элементов

numbers.take(5).toList  
// List(1, 2, 3, 4, 5)

Элементы вычисляются только для первых 5 позиций.

---

# Бесконечные последовательности

Ленивость позволяет описывать бесконечные структуры декларативно.

Пример — последовательность Фибоначчи:

val fibs: LazyList[BigInt] =  
  BigInt(0) #:: BigInt(1) #::  
    fibs.zip(fibs.tail).map(_ + _)

Использование:

fibs.take(10).toList

Без ленивости такая структура была бы невозможна.

---

# Мемоизация

LazyList запоминает вычисленные значения.

Это означает:

- каждый элемент вычисляется максимум один раз;
    
- повторный доступ не пересчитывает значение.
    

Пример:

val lazyValues = LazyList.from(1).map { x =>  
  println(s"Computing $x")  
  x * 2  
}  
  
lazyValues.take(3).toList  
lazyValues.take(3).toList

Сообщения “Computing” появятся только при первом вычислении.

---

# Преимущества ленивых коллекций

## Экономия памяти

Не создаётся вся структура целиком.

## Работа с бесконечными потоками

Можно моделировать:

- бесконечные числовые ряды;
    
- поток событий;
    
- генераторы данных.
    

## Отложенные вычисления

Вычисления происходят только при необходимости.

---

# Потенциальные опасности

## Побочные эффекты

Если внутри map есть побочный эффект:

val ll = LazyList.from(1).map { x =>  
  println(x)  
  x  
}

Эффект будет происходить при каждом новом вычислении элемента.

Хотя значения мемоизируются, порядок вычисления может быть неочевидным.

---

## Утечки памяти

Если сохраняется ссылка на голову списка, вся уже вычисленная часть остаётся в памяти.

Пример:

val ll = LazyList.from(1)  
val first100 = ll.take(100).toList

Если ll продолжает существовать, мемоизированные значения могут удерживаться.

---

## Повторное создание

Если ленивую структуру создавать внутри метода без сохранения ссылки, элементы могут пересоздаваться.

Важно понимать жизненный цикл коллекции.

# LazyList vs строгие коллекции

  

|   |   |   |
|---|---|---|
|Характеристика|List|LazyList|
|Вычисление|Немедленное|По требованию|
|Поддержка бесконечности|Нет|Да|
|Мемоизация|Не требуется|Да|
|Подходит для|Небольших конечных данных|Потоков и генераторов|
