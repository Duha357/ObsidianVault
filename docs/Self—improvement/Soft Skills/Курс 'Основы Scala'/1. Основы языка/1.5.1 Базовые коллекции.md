# Коллекции: базовые immutable коллекции

---

## Иерархия коллекций

Основные immutable-коллекции располагаются в пакете `scala.collection.immutable`.

Базовая абстракция — `Iterable[A]`.

Упрощённая схема:

- `Iterable[A]`
- `Seq[A]`
- `List[A]`
- `Set[A]`
- `Map[K, V]`

По умолчанию рекомендуется использовать immutable-коллекции.

---

## Принцип неизменяемости

Immutable-коллекция:

- Не изменяется после создания.
- Операции «добавления» или «удаления» возвращают новую коллекцию.
- Внутренняя структура переиспользуется.

> [!example]- Пример: Неизменяемость `List`
> Создаём список и добавляем элемент в начало.
>
> Ожидаемый результат: `updatedList` начинается со 100, `bookList` не изменился.
>
> ```scala
> val bookList = List(300, 150, 420)
> val updatedList = 100 :: bookList
> ```
>
> Пример показывает: операция над immutable-коллекцией возвращает новую коллекцию, исходная остаётся прежней.

Это обеспечивает:

- Потокобезопасность.
- Предсказуемость.
- Отсутствие скрытых побочных эффектов.

## List — связный список

##### Структура

`List` — односвязный список.

Рекурсивное определение:

- Пустой список: `Nil`.
- Непустой: `head :: tail`.

> [!example]- Пример: Построение списка
> Строим список через `::` и `Nil`.
>
> Ожидаемый результат: `shelfBooks` равен `List(300, 150, 420)`.
>
> ```scala
> val shelfBooks = 300 :: 150 :: 420 :: Nil
> // Эквивалентно: List(300, 150, 420)
> ```
>
> Пример показывает: `::` и `Nil` — эквивалентный способ создания `List`.

##### Prepend-операция (`::`)

Операция добавления в начало — `::`. Добавление в начало — O(1), в конец — O(n).

`List` оптимизирован для работы с головой списка.

> [!example]- Пример: Добавление в начало
> Добавляем элемент в начало существующего списка.
>
> Ожидаемый результат: `updated` начинается со 100, `shelfBooks` не изменился.
>
> ```scala
> val updated = 100 :: shelfBooks
> ```
>
> Пример показывает: prepend через `::` выполняется за O(1).

## Set — множество

`Set[A]` хранит уникальные элементы.

> [!example]- Пример: Добавление элемента в `Set`
> Создаём `Set` и добавляем элемент.
>
> Ожидаемый результат: `updated` содержит `"Biography"`, `genres` не изменился.
>
> ```scala
> val genres = Set("Fantasy", "Fiction", "Mystery")
> val updated = genres + "Biography"
> ```
>
> Пример показывает: операция `+` возвращает новый `Set` с добавленным элементом.

> [!example]- Пример: Проверка наличия элемента
> Проверяем наличие элемента в `Set`.
>
> Ожидаемый результат: оба вызова вернут `true`.
>
> ```scala
> genres.contains("Fiction")
> genres("Fiction")
> ```
>
> Пример показывает: `contains` и вызов `Set` как функции — эквивалентные проверки.

Immutable `Set` обычно реализован как хеш-структура.

## Map — ассоциативный массив

`Map[K, V]` хранит пары ключ–значение.

> [!example]- Пример: Создание Map
> Создаём `Map` из пар ключ–значение.
>
> Ожидаемый результат: `catalog` содержит `"Dune" -> 1965` и `"Foundation" -> 1951`.
>
> ```scala
> val catalog = Map(
>   "Dune" -> 1965,
>   "Foundation" -> 1951
> )
> ```
>
> Пример показывает: литерал `Map` строится из пар `ключ -> значение`.

Доступ к значению — по ключу. Безопасный вариант возвращает `Option`.

> [!example]- Пример: Доступ к значению
> Получаем значение по ключу.
>
> Ожидаемый результат: `catalog("Dune")` вернёт 1965, `catalog.get("Dune")` вернёт `Some(1965)`.
>
> ```scala
> catalog("Dune")
> catalog.get("Dune") // Option[Int]
> ```
>
> Пример показывает: прямое обращение бросает исключение при отсутствии ключа, `get` возвращает `Option`.

Пары добавляются и удаляются операциями `+` и `-`.

> [!example]- Пример: Добавление пары
> Добавляем пару ключ–значение.
>
> Ожидаемый результат: `updated` содержит `"Neuromancer" -> 1984`, `catalog` не изменился.
>
> ```scala
> val updated = catalog + ("Neuromancer" -> 1984)
> ```
>
> Пример показывает: операция `+` возвращает новый `Map` с добавленной парой.

> [!example]- Пример: Удаление пары
> Удаляем пару по ключу.
>
> Ожидаемый результат: `removed` не содержит ключ `"Dune"`, `catalog` не изменился.
>
> ```scala
> val removed = catalog - "Dune"
> ```
>
> Пример показывает: операция `-` возвращает новый `Map` без указанного ключа.

## Structural Sharing

Immutable-коллекции не копируют всю структуру при изменении.

> [!example]- Пример: Переиспользование хвоста
> Сравниваем исходный список и результат добавления элемента в начало.
>
> Ожидаемый результат: `updatedList` переиспользует хвост `bookList` (300 :: 150 :: 420).
>
> ```text
> bookList: 300 :: 150 :: 420
> updatedList: 100 :: bookList
> ```
>
> Пример показывает: при prepend хвост не копируется, а переиспользуется.

Переиспользование хвоста делает операции эффективными по памяти.

## Как собрать immutable-коллекцию

Иногда требуется эффективно построить коллекцию поэтапно.

Вместо многократного создания новых immutable-объектов используется промежуточная mutable-структура.

##### Использование ArrayBuffer

`ArrayBuffer` — mutable-коллекция для накопления элементов.

> [!example]- Пример: Накопление в `ArrayBuffer`
> Накапливаем элементы в буфере и преобразуем в `List`.
>
> Ожидаемый результат: `result` равен `List(1, 2, 3, 4, 5)`.
>
> ```scala
> import scala.collection.mutable.ArrayBuffer
>
> val buffer = ArrayBuffer[Int]()
>
> for shelfId <- 1 to 5 do
>   buffer += shelfId
>
> val result: List[Int] = buffer.toList
> ```
>
> Пример показывает: поэтапная сборка в mutable-структуре с финальным преобразованием в immutable.

Подход:

1. Мутируем буфер локально.
2. Преобразуем в immutable-коллекцию.

Это безопасно, если мутация не выходит за пределы метода.

##### MapBuilder

Для `Map` используется builder.

> [!example]- Пример: Сборка `Map` через builder
> Собираем `Map` через `Map.newBuilder`.
>
> Ожидаемый результат: `result` равен `Map("Dune" -> 1965, "Foundation" -> 1951)`.
>
> ```scala
> import scala.collection.immutable.Map
>
> val builder = Map.newBuilder[String, Int]
>
> builder += ("Dune" -> 1965)
> builder += ("Foundation" -> 1951)
>
> val result = builder.result()
> ```
>
> Пример показывает: builder накапливает пары и возвращает immutable `Map` без промежуточных копирований.

Преимущества:

- Эффективное накопление.
- Финальный результат — immutable `Map`.
- Нет промежуточных копирований.

##### Когда использовать билдеры

Рекомендуется использовать:

- При сборке коллекции в цикле.
- При парсинге больших объёмов данных.
- Когда важна производительность.

Если преобразование происходит через `map`/`filter`, билдеры обычно создаются автоматически внутри стандартной библиотеки.
