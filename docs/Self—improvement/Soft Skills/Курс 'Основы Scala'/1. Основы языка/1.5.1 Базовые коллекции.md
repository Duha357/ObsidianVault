Базовые коллекции Scala — `List`, `Set` и `Map` — по умолчанию неизменяемы: операция «добавления» не меняет коллекцию, а возвращает новую. Это не означает копирования всей структуры: неизменяемые части переиспользуются. Ниже: иерархия коллекций, устройство и стоимость операций каждой из трёх, принцип structural sharing и способы эффективно собрать неизменяемую коллекцию.

---

## Иерархия коллекций

Неизменяемые коллекции живут в пакете `scala.collection.immutable` и доступны без импорта. Базовая абстракция — `Iterable[A]`.

Упрощённая схема:

- `Iterable[A]` — общий интерфейс обхода.
- `Seq[A]` — упорядоченная последовательность.
- `List[A]` — односвязный список, реализация `Seq`.
- `Set[A]` — множество уникальных элементов.
- `Map[K, V]` — набор пар «ключ — значение».

---

## Принцип неизменяемости

Неизменяемая коллекция не меняется после создания: операции добавления и удаления возвращают новую коллекцию, переиспользуя внутреннюю структуру исходной.

> [!example]- Пример: Операция возвращает новую коллекцию
> Элемент добавляется в начало списка. Исходная коллекция остаётся прежней.
>
> Ожидаемый результат: `updatedList` — `List(100, 300, 150, 420)`, `bookList` — по-прежнему `List(300, 150, 420)`.
>
> ```scala
> val bookList = List(300, 150, 420)
> val updatedList = 100 :: bookList // новая коллекция
> ```
>
> Пример показывает: почему неизменяемую коллекцию безопасно передавать — изменить её из чужого кода нельзя.

Отсюда следуют потокобезопасность без синхронизации, предсказуемость и отсутствие скрытых побочных эффектов.

## List — связный список

##### Структура

`List` — односвязный список, определённый рекурсивно: либо пустой список `Nil`, либо пара «голова и хвост».

> [!example]- Пример: Построение списка через ::
> Оператор `::` присоединяет элемент к началу списка. Цепочка заканчивается пустым списком `Nil`.
>
> Ожидаемый результат: `shelfBooks` — `List(300, 150, 420)`, то же самое, что и `List(300, 150, 420)`.
>
> ```scala
> val shelfBooks = 300 :: 150 :: 420 :: Nil
> // эквивалентно: List(300, 150, 420)
> ```
>
> Пример показывает: почему `List` называют рекурсивной структурой — он собирается из головы, хвоста и `Nil`.

##### Стоимость операций

Добавление в начало выполняется за O(1), в конец — за O(n): чтобы дописать элемент в хвост, список нужно пройти целиком.

> [!example]- Пример: Плохо — добавление в конец List
> Оператор `:+` дописывает элемент в конец. Для односвязного списка это означает полный обход и пересоздание всех звеньев.
>
> Ожидаемый результат: результат верный, но каждая операция стоит O(n); в цикле по 10 000 элементов время растёт квадратично.
>
> ```scala
> var shelfBooks = List(300, 150, 420)
> shelfBooks = shelfBooks :+ 100 // O(n) на каждый элемент
> ```
>
> Пример показывает: для чего знать стоимость операций — привычный по массивам приём на `List` работает плохо.

> [!example]- Пример: Хорошо — добавление в начало List
> Оператор `::` создаёт новое звено, ссылающееся на существующий список. Обхода нет.
>
> Ожидаемый результат: `updated` — `List(100, 300, 150, 420)`, операция выполняется за O(1).
>
> ```scala
> val shelfBooks = List(300, 150, 420)
> val updated = 100 :: shelfBooks // O(1)
> ```
>
> Пример показывает: зачем `List` оптимизирован под голову — так устроена его структура, и операции нужно выбирать под неё.

## Set — множество

`Set[A]` хранит уникальные элементы. Повторное добавление существующего элемента ничего не меняет.

> [!example]- Пример: Добавление элемента в Set
> Оператор `+` возвращает новое множество с добавленным элементом.
>
> Ожидаемый результат: `updated` содержит четыре жанра, `genres` — прежние три.
>
> ```scala
> val genres = Set("Fantasy", "Fiction", "Mystery")
> val updated = genres + "Biography"
> ```
>
> Пример показывает: почему `Set` ведёт себя как остальные неизменяемые коллекции — операция возвращает новое значение.

> [!example]- Пример: Проверка наличия элемента
> Проверку выполняют два эквивалентных способа: метод `contains` и вызов самого множества как функции.
>
> Ожидаемый результат: оба вызова возвращают `true`.
>
> ```scala
> genres.contains("Fiction")
> genres("Fiction") // Set является функцией A => Boolean
> ```
>
> Пример показывает: для чего `Set` реализует интерфейс функции — его можно передавать туда, где ожидается предикат.

Неизменяемый `Set` реализован на хеш-структуре, поэтому проверка наличия выполняется за близкое к константному время.

## Map — ассоциативный массив

`Map[K, V]` хранит пары «ключ — значение».

> [!example]- Пример: Создание Map
> Пары записываются оператором `->`.
>
> Ожидаемый результат: `catalog` содержит `"Dune" -> 1965` и `"Foundation" -> 1951`.
>
> ```scala
> val catalog = Map(
>   "Dune" -> 1965,
>   "Foundation" -> 1951
> )
> ```
>
> Пример показывает: зачем нужен оператор `->` — он создаёт пару, из которых собирается `Map`.

##### Доступ к значению

Есть два способа получить значение по ключу, и они по-разному ведут себя при его отсутствии.

> [!example]- Пример: Плохо — прямое обращение по ключу
> Обращение как к массиву возвращает значение, но при отсутствии ключа выбрасывает исключение.
>
> Ожидаемый результат: `catalog("Dune")` возвращает 1965; `catalog("Solaris")` выбрасывает `NoSuchElementException`.
>
> ```scala
> catalog("Dune")    // 1965
> catalog("Solaris") // NoSuchElementException
> ```
>
> Пример показывает: для чего у `Map` есть второй способ доступа — прямое обращение небезопасно для необязательных ключей.

> [!example]- Пример: Хорошо — доступ через get
> `get` возвращает `Option`: отсутствие ключа выражено значением, а не исключением.
>
> Ожидаемый результат: `catalog.get("Dune")` — `Some(1965)`, `catalog.get("Solaris")` — `None`.
>
> ```scala
> catalog.get("Dune")    // Some(1965)
> catalog.get("Solaris") // None
> ```
>
> Пример показывает: зачем `get` возвращает `Option` — вызывающий код обязан обработать отсутствие ключа.

##### Добавление и удаление

> [!example]- Пример: Добавление пары
> Оператор `+` возвращает новую `Map` с добавленной парой.
>
> Ожидаемый результат: `updated` содержит `"Neuromancer" -> 1984`, `catalog` не изменяется.
>
> ```scala
> val updated = catalog + ("Neuromancer" -> 1984)
> ```
>
> Пример показывает: почему у `Map` тот же принцип, что и у `List` — операция создаёт новое значение.

> [!example]- Пример: Удаление пары
> Оператор `-` возвращает новую `Map` без указанного ключа.
>
> Ожидаемый результат: `removed` не содержит ключ `"Dune"`, `catalog` не изменяется.
>
> ```scala
> val removed = catalog - "Dune"
> ```
>
> Пример показывает: для чего удаление тоже возвращает копию — исходная коллекция остаётся доступной другим частям программы.

## Structural sharing

Неизменяемые коллекции не копируют структуру целиком: новая коллекция переиспользует неизменившуюся часть старой.

> [!example]- Пример: Переиспользование хвоста списка
> При добавлении в начало создаётся одно новое звено, которое ссылается на существующий список.
>
> Ожидаемый результат: в памяти существует один экземпляр цепочки `300 -> 150 -> 420`, на который ссылаются оба списка.
>
> ```text
> bookList:    300 -> 150 -> 420
> updatedList: 100 -> (та же цепочка)
> ```
>
> Пример показывает: почему неизменяемые коллекции практичны — «копия» стоит одного звена, а не всего списка.

Structural sharing делает неизменяемость применимой в промышленном коде: экономия памяти сочетается с потокобезопасностью без синхронизации.

## Сборка неизменяемой коллекции

Если коллекция строится поэтапно, повторное создание новых неизменяемых объектов на каждом шаге обходится дорого. Решение — накопить элементы в изменяемой структуре и преобразовать результат один раз.

##### Накопление в ArrayBuffer

> [!example]- Пример: Плохо — конкатенация в цикле
> На каждой итерации создаётся новый список: старый копируется целиком, добавляется один элемент.
>
> Ожидаемый результат: `result` — `List(1, 2, 3, 4, 5)`, но при 10 000 шагов будет выполнено 10 000 копирований.
>
> ```scala
> var result = List.empty[Int]
> for shelfId <- 1 to 5 do
>   result = result :+ shelfId // копирование на каждом шаге
> ```
>
> Пример показывает: для чего нужны буферы и билдеры — наивная сборка списка стоит квадратичного времени.

> [!example]- Пример: Хорошо — накопление в буфере
> Элементы добавляются в изменяемый буфер, который не покидает пределов метода. Наружу отдаётся неизменяемый список.
>
> Ожидаемый результат: `result` — `List(1, 2, 3, 4, 5)`; изменяемая структура наружу не выходит.
>
> ```scala
> import scala.collection.mutable.ArrayBuffer
>
> val buffer = ArrayBuffer[Int]()
>
> for shelfId <- 1 to 5 do
>   buffer += shelfId // добавление за O(1)
>
> val result: List[Int] = buffer.toList // одно преобразование в конце
> ```
>
> Пример показывает: зачем локальная мутация допустима — она безопасна, пока не выходит за границы метода.

##### Builder

Для `Map` и других коллекций стандартная библиотека предоставляет билдер — специализированный накопитель.

> [!example]- Пример: Сборка Map через builder
> Билдер накапливает пары и один раз строит итоговую неизменяемую коллекцию.
>
> Ожидаемый результат: `result` — `Map("Dune" -> 1965, "Foundation" -> 1951)`, промежуточных копий не создавалось.
>
> ```scala
> val builder = Map.newBuilder[String, Int]
>
> builder += ("Dune" -> 1965)
> builder += ("Foundation" -> 1951)
>
> val result = builder.result()
> ```
>
> Пример показывает: для чего нужен билдер — он строит коллекцию за один проход, без промежуточных копий.

Билдеры оправданы при сборке в цикле, при разборе больших объёмов данных и там, где важна производительность. Если коллекция получается из другой через `map` или `filter`, билдер создаётся стандартной библиотекой автоматически.
