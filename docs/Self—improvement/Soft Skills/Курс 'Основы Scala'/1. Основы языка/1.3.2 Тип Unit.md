# Тип Unit в Scala

---

## Назначение типа Unit

Unit — это тип, используемый для выражений, которые выполняются ради побочного эффекта и не возвращают значимого результата.

Он является аналогом void в Java и C#.

> [!example]- Пример: функция без возвращаемого значения
> Функция addBook принимает название книги и выводит его в консоль, ничего не возвращая.
> Ожидаемый результат: в консоль выводится название книги.
> 
> ```scala
> def addBook(bookTitle: String): Unit =
>   println(bookTitle)
> ```
> 
> Пример показывает: как объявить функцию, результат которой не используется.

---

## В отличие от void

В Java:

- void не является типом.
- Создать значение типа void нельзя.
- Использовать void как параметр обобщения нельзя.

В Scala:

- Unit — полноценный тип.
- Он является подтипом AnyVal.
- Его можно использовать в обобщённых конструкциях.

Это важное концептуальное отличие.

---

## Единственное значение типа Unit

Тип Unit имеет ровно одно значение: `()`.

Это значение называется unit-значением.

> [!example]- Пример: присваивание unit-значения
> Переменной emptyResult присваивается единственное значение типа Unit — `()`.
> Ожидаемый результат: `emptyResult: Unit = ()`.
> 
> ```scala
> val emptyResult: Unit = ()
> ```
> 
> Пример показывает: как присвоить unit-значение переменной.

Любое выражение, возвращающее Unit, фактически возвращает `()`.

> [!example]- Пример: результат выражения println
> Выражение `println("New author added")` выводит строку в консоль и возвращает `()`.
> Ожидаемый результат: `result: Unit = ()`.
> 
> ```scala
> val result = println("New author added")
> // result: Unit = ()
> ```
> 
> Пример показывает: результат `println` — значение `()`.

---

## Unit и выраженческая модель

Поскольку в Scala почти всё является выражением, компилятор присваивает тип даже тем операциям, которые выполняют только побочные эффекты.

> [!example]- Пример: if-выражение с ветвями Unit
> Обе ветви if-выражения выводят строку в консоль и возвращают Unit, поэтому тип всего выражения — Unit.
> Ожидаемый результат: `notification: Unit`.
> 
> ```scala
> val notification =
>   if hasBooks then println("Library is open")
>   else println("No books available")
> ```
> 
> Пример показывает: управляющие конструкции тоже подчиняются модели «всё — выражение».

Unit позволяет:

- Сохранить единую модель «всё — выражение».
- Использовать управляющие конструкции универсально.
- Применять обобщённые механизмы к процедурному коду.

---

## Unit в обобщённых типах

Поскольку Unit — полноценный тип, его можно использовать как параметр типа.

> [!example]- Пример: список unit-значений
> Список `List[Unit]` содержит три unit-значения.
> Ожидаемый результат: `list: List[Unit] = List((), (), ())`.
> 
> ```scala
> val list: List[Unit] = List((), (), ())
> ```
> 
> Пример показывает: Unit допустим как тип элементов списка.

Или в асинхронных/эффектных вычислениях: `Future[Unit]`.

Это невозможно в языках, где void не является типом.

---

## Связь с побочными эффектами

Функция, возвращающая Unit, обычно сигнализирует:

- Результат не важен.
- Функция используется ради эффекта.
- Возможны операции ввода-вывода, изменения состояния и т.п.

Однако наличие типа Unit не гарантирует отсутствие значимого поведения — это лишь соглашение.

---

## Различие между Unit, Null и Nothing

- Unit — тип с одним значением `()`.
- Null — подтип всех ссылочных типов.
- Nothing — подтип всех типов (используется для выражений, которые не возвращают значение, например throw).

> [!example]- Пример: функция с типом Nothing
> Функция missingBook выбрасывает исключение и никогда не возвращает значение.
> Ожидаемый результат: выбрасывается `RuntimeException("Book not found")`, значение не возвращается.
> 
> ```scala
> def missingBook(): Nothing =
>   throw new RuntimeException("Book not found")
> ```
> 
> Пример показывает: тип Nothing используется для функций, завершающихся исключением.

Nothing отличается от Unit: функция с типом Unit возвращает `()`, а функция с типом Nothing никогда не возвращает.
