`Unit` — тип выражений, которые выполняются ради побочного эффекта и не дают полезного результата. Это аналог `void` из Java и C#, но, в отличие от них, полноценный тип с единственным значением `()`. Ниже: назначение `Unit`, чем он отличается от `void`, как встраивается в выраженческую модель Scala и чем отличается от `Null` и `Nothing`.

---

## Назначение типа Unit

Функция с результатом `Unit` вызывается ради того, что она делает, а не ради того, что возвращает.

> [!example]- Пример: Функция ради побочного эффекта
> Функция печатает название книги в консоль. Возвращать ей нечего, поэтому тип результата — `Unit`.
>
> Ожидаемый результат: `addBook("Dune")` печатает `Dune` и возвращает `()`.
>
> ```scala
> def addBook(bookTitle: String): Unit =
>   println(bookTitle)
> ```
>
> Пример показывает: зачем нужен `Unit` — им обозначают операции, у которых нет осмысленного результата.

---

## Отличие от void

В Java:

- `void` не является типом.
- Значение типа `void` создать нельзя.
- Использовать `void` как параметр обобщения нельзя.

В Scala:

- `Unit` — полноценный тип.
- Является подтипом `AnyVal`.
- Используется в обобщённых конструкциях наравне с другими типами.

---

## Единственное значение типа Unit

Тип `Unit` имеет ровно одно значение — `()`, его называют unit-значением.

> [!example]- Пример: Присваивание unit-значения
> Значению явно присваивается единственно возможное значение типа `Unit`.
>
> Ожидаемый результат: `emptyResult` имеет тип `Unit` и значение `()`.
>
> ```scala
> val emptyResult: Unit = ()
> ```
>
> Пример показывает: почему `Unit` считают обычным типом — у него есть литерал, который можно присвоить.

Любое выражение с типом `Unit` возвращает именно `()`.

> [!example]- Пример: Результат println
> Результат вызова `println` присваивается имени.
>
> Ожидаемый результат: строка печатается в консоль, `result` получает тип `Unit` и значение `()`.
>
> ```scala
> val result = println("New author added")
> // result: Unit = ()
> ```
>
> Пример показывает: для чего `println` вообще что-то возвращает — иначе правило «всё является выражением» нарушалось бы.

---

## Unit и выраженческая модель

Поскольку в Scala почти всё является выражением, тип получают и те конструкции, которые выполняют только побочный эффект.

> [!example]- Пример: if с ветвями Unit
> Обе ветви `if` печатают строку, значит, обе имеют тип `Unit`. Общий тип ветвей становится типом всего выражения.
>
> Ожидаемый результат: `notification` имеет тип `Unit`; печатается одно из двух сообщений.
>
> ```scala
> val notification =
>   if hasBooks then println("Library is open")
>   else println("No books available")
> ```
>
> Пример показывает: почему в Scala нет исключений из выраженческой модели — даже печать в консоль имеет тип результата.

`Unit` позволяет:

- Сохранить единую модель «всё является выражением».
- Применять управляющие конструкции универсально.
- Использовать обобщённые механизмы с процедурным кодом.

---

## Unit в обобщённых типах

`Unit` подставляется как параметр типа там, где в Java `void` подставить нельзя.

> [!example]- Пример: Unit как параметр типа
> Список параметризован типом `Unit` и содержит три unit-значения.
>
> Ожидаемый результат: `list` — `List((), (), ())`, тип `List[Unit]`.
>
> ```scala
> val list: List[Unit] = List((), (), ())
> ```
>
> Пример показывает: для чего `Unit` сделали настоящим типом — иначе обобщённый код пришлось бы дублировать для операций без результата.

То же ограничение проявляется в Java на обобщённых контейнерах: объявить `Container<void>` там нельзя, а в Scala `Container[Unit]` — обычный тип.

---

## Unit как сигнал побочного эффекта

Тип `Unit` в сигнатуре сообщает вызывающему коду: результата не будет, вызов нужен ради эффекта.

> [!example]- Пример: Плохо — результат потерян в Unit
> Функция вычисляет новое количество экземпляров, но вместо возврата печатает его. Использовать вычисленное значение дальше нельзя.
>
> Ожидаемый результат: число печатается в консоль, но `registerCopies(10, 5)` возвращает `()` — результат вычисления недоступен.
>
> ```scala
> def registerCopies(current: Int, added: Int): Unit =
>   println(current + added) // результат ушёл в консоль
> ```
>
> Пример показывает: почему `Unit` в сигнатуре — сильное заявление: он объявляет, что брать у функции нечего.

> [!example]- Пример: Хорошо — результат возвращается
> Функция возвращает вычисленное значение, а печать остаётся на стороне вызывающего кода.
>
> Ожидаемый результат: `registerCopies(10, 5)` возвращает 15; значение можно напечатать, сохранить или передать дальше.
>
> ```scala
> def registerCopies(current: Int, added: Int): Int =
>   current + added
>
> println(registerCopies(10, 5)) // 15
> ```
>
> Пример показывает: зачем разделять вычисление и эффект — чистую функцию можно переиспользовать и протестировать.

Наличие `Unit` не гарантирует, что функция делает что-то полезное, — это соглашение, а не проверка компилятора.

---

## Различие Unit, Null и Nothing

- `Unit` — тип с единственным значением `()`.
- `Null` — подтип всех ссылочных типов, единственное значение `null`.
- `Nothing` — подтип всех типов, значений не имеет.

`Nothing` типизирует выражения, которые не возвращают управление.

> [!example]- Пример: Функция с типом Nothing
> Функция всегда выбрасывает исключение, поэтому до возврата значения дело не доходит.
>
> Ожидаемый результат: вызов `missingBook()` выбрасывает `RuntimeException("Book not found")`; значение не возвращается никогда.
>
> ```scala
> def missingBook(): Nothing =
>   throw new RuntimeException("Book not found")
> ```
>
> Пример показывает: для чего нужен `Nothing` — он позволяет подставить такую функцию в выражение любого типа.

Отличие от `Unit` принципиальное: функция с типом `Unit` возвращает `()`, функция с типом `Nothing` не возвращает ничего и никогда.
