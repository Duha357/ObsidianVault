Управляющие конструкции Scala — `if`, `while`, `for` и `match` — отличаются от привычных по Java прежде всего тем, что большинство из них возвращает значение. Императивный `while` остаётся, но в функциональном коде вытесняется операциями над коллекциями и рекурсией. Ниже: синтаксис каждой конструкции, что она возвращает и когда её применяют.

---

## Условная конструкция if / else

`if` в Scala — выражение, а не инструкция. Оно заменяет тернарный оператор `?:` из Java и C#.

##### if как выражение

Тип результата определяется типами обеих ветвей.

> [!example]- Пример: Результат if присваивается напрямую
> Обе ветви возвращают строку, поэтому результат всего выражения — строка.
>
> Ожидаемый результат: при `availableBooks > 0` — `"available"`, иначе — `"out of stock"`.
>
> ```scala
> val bookStatus =
>   if availableBooks > 0 then "available"
>   else "out of stock"
> ```
>
> Пример показывает: зачем `if` сделали выражением — промежуточная переменная не нужна.

Характеристики `if`:

- Возвращает значение.
- Тип определяется типами обеих ветвей.
- Может быть вложенным.
- Используется везде, где ожидается выражение.

##### Отсутствие необходимости в return

Метод возвращает значение последнего выражения, поэтому `if` в конце тела и есть результат.

> [!example]- Пример: if как результат метода
> Метод состоит из одного выражения `if`. Ключевое слово `return` не используется.
>
> Ожидаемый результат: `calculateLateFee(3)` возвращает 15, `calculateLateFee(-1)` — 0.
>
> ```scala
> def calculateLateFee(daysLate: Int): Int =
>   if daysLate >= 0 then daysLate * 5 else 0
> ```
>
> Пример показывает: почему `return` в Scala не нужен — последнее выражение уже является результатом.

##### Ветвление без else

Без ветки `else` вторая ветвь неявно возвращает `()`, поэтому тип всего выражения — `Unit`. Такая форма применяется только ради побочного эффекта.

> [!example]- Пример: if без else
> Конструкция выполняет печать при истинном условии и ничего не возвращает.
>
> Ожидаемый результат: при `availableBooks > 0` печатается сообщение; тип выражения — `Unit`, присвоить его осмысленно нельзя.
>
> ```scala
> if availableBooks > 0 then println("Books are available")
> ```
>
> Пример показывает: для чего форма без `else` — только для побочного эффекта, не для вычисления значения.

## Цикл while

`while` проверяет условие до выполнения тела и повторяет его, пока условие истинно. Возвращает `Unit`, то есть работает исключительно ради побочного эффекта.

##### Синтаксис

> [!example]- Пример: Синтаксис while
> Счётчик увеличивается вручную, условие проверяется перед каждой итерацией.
>
> Ожидаемый результат: печатаются числа с 1 по 5, после цикла `shelfNumber` равен 6.
>
> ```scala
> var shelfNumber = 1
> while shelfNumber <= 5 do
>   println(shelfNumber)
>   shelfNumber += 1 // счётчик двигает разработчик
> ```
>
> Пример показывает: почему `while` требует `var` — состояние цикла хранится в изменяемой переменной.

##### Рекомендации по использованию

В функциональном стиле `while` вытесняется операциями над коллекциями и рекурсией.

> [!example]- Пример: Плохо — накопление через while
> Сумма страниц собирается в изменяемой переменной, коллекция обходится по индексу.
>
> Ожидаемый результат: `totalPages` — 870; при этом в коде три изменяемых значения и ручная проверка границы.
>
> ```scala
> val bookPages = List(120, 450, 300)
> var totalPages = 0
> var index = 0
>
> while index < bookPages.length do
>   totalPages += bookPages(index)
>   index += 1
> ```
>
> Пример показывает: для чего нужны операции над коллекциями — императивный обход требует ручного управления состоянием.

> [!example]- Пример: Хорошо — накопление через sum
> Обход, накопление и завершение выражены одной операцией коллекции.
>
> Ожидаемый результат: `totalPages` — 870, изменяемых переменных нет.
>
> ```scala
> val bookPages = List(120, 450, 300)
> val totalPages = bookPages.sum
> ```
>
> Пример показывает: зачем декларативный стиль — описывается результат, а не шаги его получения.

`while` оправдан в низкоуровневом коде, в производительных вычислениях и при работе с внешними API, требующими пошагового обхода.

## Конструкция for

`for` — универсальный механизм итерации и композиции. Он состоит из генераторов, необязательных фильтров и тела.

##### Генераторы

Генератор `x <- collection` задаёт источник элементов.

> [!example]- Пример: Генератор for
> Список названий книг перебирается генератором, тело выполняется для каждого элемента.
>
> Ожидаемый результат: печатаются Dune, Foundation, Neuromancer — по строке на элемент.
>
> ```scala
> for bookTitle <- List("Dune", "Foundation", "Neuromancer") do
>   println(bookTitle)
> ```
>
> Пример показывает: зачем генератор — источник элементов и переменная цикла объявляются одной записью.

##### Фильтры (guards)

Фильтр `if` внутри `for` отбрасывает элементы до выполнения тела.

> [!example]- Пример: Фильтр в for
> До тела доходят только книги от 200 страниц.
>
> Ожидаемый результат: печатаются 450 и 300; значения 120 и 90 отсеяны.
>
> ```scala
> for
>   bookPages <- List(120, 450, 90, 300)
>   if bookPages >= 200 // фильтр, а не условие внутри тела
> do
>   println(bookPages)
> ```
>
> Пример показывает: почему фильтр выносят в заголовок — тело остаётся без вложенного `if`.

##### Вложенные генераторы

Несколько генераторов подряд перебирают все комбинации элементов.

> [!example]- Пример: Вложенные генераторы
> Два генератора перебирают авторов и книги. Второй генератор выполняется для каждого элемента первого.
>
> Ожидаемый результат: 4 строки — все сочетания двух авторов и двух книг.
>
> ```scala
> for
>   authorName <- List("Tolkien", "Rowling")
>   bookTitle <- List("The Lord of the Rings", "Harry Potter")
> do
>   println(s"$authorName - $bookTitle")
> ```
>
> Пример показывает: для чего несколько генераторов — вложенные циклы записываются без вложенности кода.

##### Использование yield

`yield` превращает `for` в выражение, собирающее новую коллекцию. Без `yield` результат — `Unit`.

> [!example]- Пример: Плохо — сбор результата вручную
> Коллекция накапливается в изменяемом буфере, элементы добавляются по одному.
>
> Ожидаемый результат: `bookCodes` — `List(BOOK-1, BOOK-2, BOOK-3)`, но потребовались буфер и преобразование в конце.
>
> ```scala
> import scala.collection.mutable.ListBuffer
>
> val buffer = ListBuffer[String]()
> for bookId <- List(1, 2, 3) do
>   buffer += s"BOOK-$bookId"
>
> val bookCodes = buffer.toList
> ```
>
> Пример показывает: для чего нужен `yield` — без него сбор результата ложится на разработчика.

> [!example]- Пример: Хорошо — for ... yield
> `yield` сам собирает результаты итераций в коллекцию того же типа, что и источник.
>
> Ожидаемый результат: `bookCodes` — `List(BOOK-1, BOOK-2, BOOK-3)`.
>
> ```scala
> val bookCodes =
>   for bookId <- List(1, 2, 3)
>   yield s"BOOK-$bookId"
> ```
>
> Пример показывает: зачем `for ... yield` — преобразование коллекции записывается одним выражением.

##### Синтаксис Scala 3

Scala 3 допускает и фигурные скобки, и отступный синтаксис. В рамках проекта выбирают один стиль.

> [!example]- Пример: Форма с фигурными скобками
> Классический синтаксис Scala 2: генератор в круглых скобках, тело — в фигурных.
>
> Ожидаемый результат: печатаются все элементы `books`.
>
> ```scala
> for (bookTitle <- books) {
>   println(bookTitle)
> }
> ```
>
> Пример показывает: с чем сравнивается отступный синтаксис Scala 3.

> [!example]- Пример: Отступная форма Scala 3
> Скобок нет: генераторы идут после `for`, тело — после `do`.
>
> Ожидаемый результат: тот же вывод, что и у формы со скобками.
>
> ```scala
> for
>   bookTitle <- books
> do
>   println(bookTitle)
> ```
>
> Пример показывает: зачем отступный синтаксис — конструкция читается без служебных символов.

## Сопоставление с образцом (match)

`match` — аналог `switch-case`, но работает как выражение: возвращает результат первой подошедшей ветки.

##### Синтаксис

> [!example]- Пример: Плохо — цепочка if-else
> Три ветки условий проверяют одно и то же значение. Условие `bookCount` повторяется в каждой строке.
>
> Ожидаемый результат: при 0 — `"no books"`, при 1 — `"single book"`, иначе — `"many books"`; логика верная, но запись избыточна.
>
> ```scala
> val bookDescription =
>   if bookCount == 0 then "no books"
>   else if bookCount == 1 then "single book"
>   else "many books"
> ```
>
> Пример показывает: для чего нужен `match` — при разборе одного значения цепочка `if` дублирует проверку.

> [!example]- Пример: Хорошо — match
> Проверяемое значение указано один раз, ветки перечисляют образцы.
>
> Ожидаемый результат: при 0 — `"no books"`, при 1 — `"single book"`, иначе — `"many books"`.
>
> ```scala
> val bookDescription = bookCount match
>   case 0 => "no books"
>   case 1 => "single book"
>   case _ => "many books" // _ — любое другое значение
> ```
>
> Пример показывает: зачем `match` — разбор значения записывается компактно и единообразно.

Допустима и форма с фигурными скобками.

> [!example]- Пример: Match с фигурными скобками
> Тот же `match`, ветки заключены в фигурные скобки.
>
> Ожидаемый результат: при 0 — `"empty library"`, иначе — `"library has books"`.
>
> ```scala
> val bookDescription = bookCount match {
>   case 0 => "empty library"
>   case _ => "library has books"
> }
> ```
>
> Пример показывает: почему обе формы встречаются в коде — Scala 3 принимает и скобочный, и отступный стиль.

##### Проверка типов

В отличие от `switch`, образцом может быть тип, а не только значение.

> [!example]- Пример: Типовые образцы в match
> Параметр объявлен как `Any`, поэтому может содержать значение любого типа. Ветки различают его по типу и сразу дают имя.
>
> Ожидаемый результат: для числа — `"pages: N"`, для строки — `"title: ..."`, иначе — `"unknown item"`.
>
> ```scala
> def describeLibraryItem(item: Any): String =
>   item match
>     case pages: Int    => s"pages: $pages"    // проверка типа и связывание имени
>     case title: String => s"title: $title"
>     case _             => "unknown item"
> ```
>
> Пример показывает: почему `match` мощнее `switch` — он различает не только значения, но и типы.

Характеристики `match`:

- Возвращает значение.
- Поддерживает типовые проверки.
- Поддерживает деструктуризацию объектов.
- Проверяется компилятором на исчерпываемость для закрытых иерархий.

## Сравнение конструкций

| Конструкция | Возвращает значение | Основное назначение |
|---|---|---|
| `if` | Да | Условное ветвление |
| `while` | `Unit` | Императивный цикл |
| `for` + `yield` | Да | Генерация коллекций |
| `for` без `yield` | `Unit` | Побочные эффекты |
| `match` | Да | Разбор значений и типов |
