`Option[A]` — способ выразить «значения может не быть» типом, а не значением `null`. Контейнер либо содержит результат (`Some`), либо пуст (`None`), и достать содержимое, не обработав пустой случай, компилятор не даст. Ниже: чем плох `null`, устройство `Option`, его основные методы и идиоматический стиль работы через композицию.

Раздел читается вместе с 1.5: `Option` ведёт себя как коллекция из нуля или одного элемента и использует те же операции — `map`, `flatMap`, `fold`. Обратная связь тоже есть: `Map.get` возвращает `Option`.

## Проблема null

В языках семейства C отсутствие объекта обозначают значением `null`. Отсюда четыре проблемы:

- Отсутствие не отражено в типе — сигнатура обещает результат, которого может не быть.
- Возможен `NullPointerException` в произвольной точке программы.
- Проверку легко забыть: компилятор о ней не напоминает.
- Логика разрастается защитными ветвлениями.

Тони Хоар, автор идеи `null`, назвал её «ошибкой на миллиард долларов». В Scala `null` существует по наследству от JVM, но в идиоматическом коде не применяется.

## Тип Option

`Option[A]` — контейнер, который либо содержит значение типа `A`, либо пуст.

> [!example]- Пример: Упрощённое определение Option
> `Option` объявлен как закрытая иерархия из двух вариантов — это обычный тип-сумма, а не встроенная магия языка.
>
> Ожидаемый результат: значение типа `Option[A]` — это либо `Some(a)`, либо `None`.
>
> ```scala
> sealed trait Option[+A]
> case class Some[A](value: A) extends Option[A]
> case object None extends Option[Nothing]
> ```
>
> Пример показывает: почему `Option` безопасен — компилятор знает оба варианта и требует обработать каждый.

---

## Option вместо null

> [!example]- Пример: Плохо — отсутствие через null
> Функция возвращает `null`, когда книга не найдена. Тип результата об этом не сообщает.
>
> Ожидаемый результат: `findBook(2).length` компилируется, но падает с `NullPointerException` при запуске.
>
> ```scala
> def findBook(bookId: Int): String =
>   if bookId == 1 then "Dune" else null
>
> println(findBook(2).length) // NullPointerException
> ```
>
> Пример показывает: для чего понадобился `Option` — `null` прячет возможное отсутствие от компилятора.

> [!example]- Пример: Хорошо — отсутствие через Option
> Тип результата прямо сообщает, что книги может не быть. Обратиться к строке напрямую нельзя.
>
> Ожидаемый результат: `findBook(1)` — `Some("Dune")`, `findBook(2)` — `None`; `findBook(2).length` не компилируется.
>
> ```scala
> def findBook(bookId: Int): Option[String] =
>   if bookId == 1 then Some("Dune") else None
> ```
>
> Пример показывает: зачем выражать отсутствие типом — вызывающий код обязан рассмотреть оба случая.

Чужой код, возвращающий `null`, оборачивают конструктором `Option`.

> [!example]- Пример: Обёртка null в Option
> Конструктор `Option` возвращает `None` для `null` и `Some` для любого другого значения. Дальше работа идёт уже безопасно.
>
> Ожидаемый результат: для `null` — `0`; для строки — её длина.
>
> ```scala
> val titleFromLegacyApi: String = null
>
> val titleLength = Option(titleFromLegacyApi).map(_.length).getOrElse(0) // 0
> ```
>
> Пример показывает: для чего нужен конструктор `Option` — он ставит границу между кодом с `null` и остальной программой.

## Option как коллекция из нуля или одного элемента

`Option` поддерживает те же операции, что и коллекции, поэтому работа с ним не требует отдельных приёмов.

##### map

`map` преобразует содержимое, если оно есть. Для `None` результат остаётся `None` — проверка не нужна.

> [!example]- Пример: map по Option
> Функция `_.length` применяется к содержимому, а не к самому контейнеру.
>
> Ожидаемый результат: для `Some("Foundation")` — `Some(10)`; для `None` — `None`.
>
> ```scala
> val titleOpt: Option[String] = Some("Foundation")
> val titleLength = titleOpt.map(_.length) // Some(10)
> ```
>
> Пример показывает: зачем `map` у `Option` — преобразование пишется один раз и работает для обоих случаев.

##### flatMap

`flatMap` применяется, когда сама функция возвращает `Option`. Иначе получилось бы вложение `Option[Option[A]]`.

> [!example]- Пример: flatMap с функцией, возвращающей Option
> `parseBookId` может не справиться с разбором строки, поэтому возвращает `Option[Int]`. `flatMap` разворачивает результат.
>
> Ожидаемый результат: `Some(101)`, а не `Some(Some(101))`.
>
> ```scala
> def parseBookId(bookId: String): Option[Int] =
>   try Some(bookId.toInt)
>   catch case _: NumberFormatException => None
>
> val parsedId = Some("101").flatMap(parseBookId) // Some(101)
> ```
>
> Пример показывает: для чего нужен `flatMap` — он не даёт контейнерам вкладываться друг в друга.

##### getOrElse

`getOrElse` извлекает значение или подставляет запасное.

> [!example]- Пример: getOrElse со значением по умолчанию
> Аргумент используется только тогда, когда контейнер пуст.
>
> Ожидаемый результат: для `Some("Foundation")` — `"Foundation"`; для `None` — `"Unknown book"`.
>
> ```scala
> val bookTitle = titleOpt.getOrElse("Unknown book")
> ```
>
> Пример показывает: зачем `getOrElse` — он завершает цепочку, возвращая обычное значение вместо контейнера.

##### orElse

`orElse` подставляет альтернативный `Option`, сохраняя тип результата.

> [!example]- Пример: orElse с запасным вариантом
> Если основной контейнер пуст, берётся запасной; иначе возвращается исходный.
>
> Ожидаемый результат: `Some("Default Book")`.
>
> ```scala
> val backupTitle = None.orElse(Some("Default Book"))
> ```
>
> Пример показывает: чем `orElse` отличается от `getOrElse` — результат остаётся `Option` и цепочку можно продолжить.

##### fold

`fold` обрабатывает оба случая одним выражением: первый аргумент — значение для пустого случая, второй — функция для непустого.

> [!example]- Пример: fold для обоих случаев
> Одно выражение задаёт и запасное значение, и преобразование.
>
> Ожидаемый результат: для `Some("Foundation")` — `"FOUNDATION"`; для `None` — `"No title"`.
>
> ```scala
> val message = titleOpt.fold("No title")(_.toUpperCase)
> ```
>
> Пример показывает: для чего нужен `fold` — он заменяет `match` из двух веток одной строкой.

## Pattern matching

`Option` — обычный тип-сумма, поэтому раскладывается по образцу.

> [!example]- Пример: Разбор Option через match
> Ветка `Some` получает содержимое, ветка `None` описывает пустой случай.
>
> Ожидаемый результат: для `Some("Foundation")` печатается `Foundation`, для `None` — `No title`.
>
> ```scala
> titleOpt match
>   case Some(title) => println(title)
>   case None        => println("No title")
> ```
>
> Пример показывает: почему `Option` не требует особых правил — это тип-сумма, разбираемый как любой другой.

В повседневном коде `match` по `Option` применяют редко: `map`, `getOrElse` и `fold` короче. Но понимать эту форму нужно — она объясняет природу типа.

## Композиция вместо ветвлений

Идиоматический стиль — не проверять наличие вручную, а строить цепочку операций.

> [!example]- Пример: Плохо — ручная проверка и get
> Наличие значения проверяется через `isDefined`, содержимое извлекается через `get`. Компилятор не связывает эти две строки: `get` вызовется даже если проверку убрать.
>
> Ожидаемый результат: код работает, но `titleOpt.get` на пустом контейнере выбрасывает `NoSuchElementException` — та же проблема, что и с `null`.
>
> ```scala
> if titleOpt.isDefined then
>   println(titleOpt.get) // небезопасно само по себе
> ```
>
> Пример показывает: для чего нужна композиция — ручная проверка возвращает те же риски, ради устранения которых вводили `Option`.

> [!example]- Пример: Хорошо — foreach и for
> `foreach` выполняет действие только при наличии значения. `for` связывает несколько `Option` в одну цепочку.
>
> Ожидаемый результат: печатается `Foundation`, если значение есть; `titleSize` — `Some(10)` при непустом `titleOpt` и `None` иначе.
>
> ```scala
> titleOpt.foreach(println) // вызовется только для Some
>
> val titleSize =
>   for
>     title <- titleOpt
>     size <- Some(title.length)
>   yield size
> ```
>
> Пример показывает: зачем композиция — проверок в коде нет, а пустой случай обработан.

Композиция уменьшает количество ветвлений, делает поток данных линейным и повышает предсказуемость кода.

## Интеграция с коллекциями

`Option` преобразуется в коллекцию и участвует в коллекционных операциях.

> [!example]- Пример: Option как список
> `toList` превращает контейнер в список из нуля или одного элемента.
>
> Ожидаемый результат: для `Some("Foundation")` — `List("Foundation")`; для `None` — пустой список.
>
> ```scala
> val titleList = titleOpt.toList
> ```
>
> Пример показывает: почему `Option` называют коллекцией из 0 или 1 элемента — преобразование прямое.

Отсюда полезный приём: `Option` внутри `flatMap` работает как фильтр.

> [!example]- Пример: Option как фильтр в flatMap
> Функция возвращает `Some` для чётных идентификаторов и `None` для нечётных. `flatMap` отбрасывает пустые результаты.
>
> Ожидаемый результат: `List(100, 102)` — нечётный `101` отброшен.
>
> ```scala
> val bookIds = List(100, 101, 102)
>
> val evenIds =
>   bookIds.flatMap(id =>
>     if id % 2 == 0 then Some(id) else None
>   )
> ```
>
> Пример показывает: для чего сочетают `Option` и `flatMap` — отбор и преобразование выполняются одной операцией.

## Почему Option лучше null

| `null` | `Option` |
|---|---|
| Не отражён в типе | Отражён в типе |
| Возможен `NullPointerException` | Безопасная композиция |
| Требует ручных проверок | Поддерживает `map` и `flatMap` |
| Проверку легко забыть | Компилятор напоминает |

`Option` делает отсутствие значения явной частью модели данных, а не соглашением между разработчиками.
