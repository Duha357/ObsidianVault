# Option и обработка отсутствующих значений в Scala

Лекция предполагает знание базовых коллекций и операций над ними (map, flatMap, fold), поскольку Option концептуально ведёт себя как коллекция из 0 или 1 элемента.

---

## Проблема null

В большинстве языков семейства C значение null используется для обозначения отсутствия объекта.

Проблемы подхода:

- Отсутствие отражается в типе неявно.
- Возможны NullPointerException.
- Проверка на null часто забывается.
- Логика разрастается ветвлениями.

Эта проблема получила название «ошибка на миллиард долларов» (термин Тони Хоара).

В Scala null существует (по наследству от JVM), но его использование в идиоматическом коде не рекомендуется.

---

## Тип Option

Option[A] — контейнер, который может:

- Содержать значение типа A (Some(a)).
- Быть пустым (None).

Определение упрощённо выглядит так:

> [!example]- Пример: упрощённое определение Option
> Определение описывает структуру типа: sealed trait Option, case class Some и case object None.
>
> Результат — тип-сумма: значение Option — это Some ИЛИ None.
> ```scala
> sealed trait Option[+A]
> case class Some[A](value: A) extends Option[A]
> case object None extends Option[Nothing]
> ```
> Пример показывает: Option — тип-сумма, вариант None выражает отсутствие значения.

Это тип-сумма: значение — это Some ИЛИ None.

---

## Базовый пример

> [!example]- Пример: функция с результатом Option
> findBook принимает bookId и возвращает Some("Dune") при bookId == 1, иначе None.
>
> Результат — Some("Dune") для findBook(1), None для остальных id.
> ```scala
> def findBook(bookId: Int): Option[String] =
>   if bookId == 1 then Some("Dune") else None
> ```
> Пример показывает: возможность отсутствия значения отражена в типе результата Option[String].

Тип результата явно указывает: значение может отсутствовать.

Это ключевое преимущество перед null: возможность отсутствия отражена в типе.

## Option как коллекция из 0 или 1 элемента

Option поддерживает те же базовые операции, что и коллекции.

##### map

map преобразует значение внутри Option, если оно есть. При None результат остаётся None.

> [!example]- Пример: применение map
> Код применяет функцию _.length к Some("Foundation").
>
> Результат — Some(10): длина строки "Foundation" — 10 символов. При None результат остаётся None.
> ```scala
> val titleOpt: Option[String] = Some("Foundation")
> val titleLength = titleOpt.map(_.length)
> ```
> Пример показывает: map преобразует значение внутри Option без ручной проверки.

##### flatMap

flatMap используется, если функция сама возвращает Option.

> [!example]- Пример: flatMap с функцией, возвращающей Option
> parseBookId преобразует строку в Int и возвращает Option[Int]; при ошибке — None.
>
> Результат — Some(101): вложенности Option[Option[Int]] нет.
> ```scala
> def parseBookId(bookId: String): Option[Int] =
>   try Some(bookId.toInt)
>   catch case _: NumberFormatException => None
> val parsedId = Some("101").flatMap(parseBookId)
> ```
> Пример показывает: flatMap предотвращает появление Option[Option[A]].

##### getOrElse

getOrElse задаёт значение по умолчанию для случая None.

> [!example]- Пример: getOrElse со значением по умолчанию
> Код получает значение titleOpt; если Option пуст — подставляет "Unknown book".
>
> Результат — "Foundation" (значение внутри Some); при None — "Unknown book".
> ```scala
> val bookTitle = titleOpt.getOrElse("Unknown book")
> ```
> Пример показывает: getOrElse извлекает значение или подставляет значение по умолчанию.

##### orElse

orElse позволяет указать альтернативный Option.

> [!example]- Пример: orElse с запасным Option
> orElse на None возвращает запасной Option, на Some — исходный.
>
> Результат — Some("Default Book").
> ```scala
> val backupTitle = None.orElse(Some("Default Book"))
> ```
> Пример показывает: orElse сохраняет тип Option и подставляет альтернативу.

##### fold

fold — универсальный способ обработки. Сигнатура: fold(ifEmpty)(f).

> [!example]- Пример: fold для обработки обоих случаев
> fold принимает значение для пустого случая и функцию для значения.
>
> Результат — "FOUNDATION": функция _.toUpperCase применена к Some; при None — "No title".
> ```scala
> val message = titleOpt.fold("No title")(_.toUpperCase)
> ```
> Пример показывает: fold заменяет явный match одним выражением.

---

## Pattern matching

> [!example]- Пример: обработка Option через match
> match разбирает Option: ветка Some получает значение, ветка None — пустой случай.
>
> Результат — печать "Foundation" для Some; печать "No title" для None.
> ```scala
> titleOpt match
>   case Some(title) => println(title)
>   case None        => println("No title")
> ```
> Пример показывает: Option раскрывается через pattern matching как тип-сумма.

Используется реже в повседневной логике, но важен для понимания природы Option как типа-суммы.

## Композиция вместо ветвлений

Идиоматический стиль Scala — не проверять наличие вручную, а строить композицию.

> [!example]- Пример: композиция вместо проверки isDefined
> Сравнение трёх способов печати значения: isDefined + get, foreach, for.
>
> Результат — все три способа печатают "Foundation"; foreach и for не требуют ручной проверки.
> ```scala
> // Не рекомендуется
> if titleOpt.isDefined then
>   println(titleOpt.get)
>
> // Предпочтительно
> titleOpt.foreach(println)
>
> // Или через for
> for
>   title <- titleOpt
>   titleSize <- Some(title.length)
> yield titleSize
> ```
> Пример показывает: композиция убирает ветвления и делает поток данных линейным.

Композиция:

- Уменьшает количество ветвлений.
- Делает поток данных линейным.
- Повышает читаемость.
- Улучшает предсказуемость.

## Интеграция с коллекциями

Option легко преобразуется в коллекцию:

> [!example]- Пример: преобразование Option в List
> toList превращает Option в список из 0 или 1 элемента.
>
> Результат — List("Foundation"); при None — пустой список.
> ```scala
> val titleList = titleOpt.toList
> ```
> Пример показывает: Option встраивается в коллекционные операции.

Это удобно при работе с flatMap:

> [!example]- Пример: Option как фильтр в flatMap
> flatMap по списку bookIds возвращает Some для чётных id и None для нечётных.
>
> Результат — List(100, 102): нечётные id отброшены.
> ```scala
> val bookIds = List(100, 101, 102)
> val evenIds =
>   bookIds.flatMap(id =>
>     if id % 2 == 0 then Some(id) else None
>   )
> ```
> Пример показывает: Some/None внутри flatMap решает, оставить элемент или отбросить.

Option выступает как фильтр.

---

## Почему Option лучше null

| null | Option |
| --- | --- |
| Не отражён в типе | Отражён в типе |
| Возможен NPE | Безопасная композиция |
| Требует ручных проверок | Поддерживает map/flatMap |
| Легко забыть проверку | Компилятор помогает |

Option делает отсутствие значения явной частью модели данных.
