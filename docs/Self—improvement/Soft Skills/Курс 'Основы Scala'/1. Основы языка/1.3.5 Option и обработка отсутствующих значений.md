# Option и обработка отсутствующих значений в Scala

Лекция предполагает знание базовых коллекций и операций над ними (map, flatMap, fold), поскольку Option концептуально ведёт себя как коллекция из 0 или 1 элемента.

---

## Проблема null

В большинстве языков семейства C значение null используется для обозначения отсутствия объекта.

Проблемы подхода:

- отсутствие отражается в типе неявно;
    
- возможны NullPointerException;
    
- проверка на null часто забывается;
    
- логика разрастается ветвлениями.
    

Эта проблема получила название «миллиард долларовой ошибки» (термин Тони Хоара).

В Scala null существует (по наследству от JVM), но его использование в идиоматическом коде не рекомендуется.

---

## Тип Option

Option[A] — это контейнер, который может:

- содержать значение типа A (Some(a));
    
- быть пустым (None).
    

Определение упрощенно выглядит так:

sealed trait Option[+A]  
case class Some[A](value: A) extends Option[A]  
case object None extends Option[Nothing]

Это тип-сумма: значение — это Some ИЛИ None.

---

## Базовый пример

def findBook(bookId: Int): Option[String] =  
if bookId == 1 then Some("Dune") else None

Тип результата явно указывает:

значение может отсутствовать.

Это ключевое преимущество перед null: возможность отсутствия отражена в типе.

---

## Option как коллекция из 0 или 1 элемента

Option поддерживает те же базовые операции, что и коллекции.

### map

val titleOpt: Option[String] = Some("Foundation")  
val titleLength = titleOpt.map(_.length)

Если значение есть — применяется функция. Если None — результат остаётся None.

---

### flatMap

Используется, если функция сама возвращает Option.

def parseBookId(bookId: String): Option[Int] =  
try Some(bookId.toInt)  
catch case _: NumberFormatException => None  
val parsedId = Some("101").flatMap(parseBookId)

flatMap предотвращает вложенность Option[Option[A]].

---

### getOrElse

Возвращает значение по умолчанию:

val bookTitle = titleOpt.getOrElse("Unknown book")

Если None, возвращается значение по умолчанию.

---

### orElse

Позволяет указать альтернативный Option:

val backupTitle = None.orElse(Some("Default Book"))

---

### fold

Универсальный способ обработки:

val message = titleOpt.fold("No title")(_.toUpperCase)

Сигнатура:

fold(ifEmpty)(f)

Это выражение заменяет явный match.

---

## Pattern matching

Классический способ:

titleOpt match  
case Some(title) => println(title)  
case None        => println("No title")

Используется реже в повседневной логике, но важен для понимания природы Option как типа-суммы.

---

## Композиция вместо ветвлений

Идиоматический стиль Scala — не проверять наличие вручную, а строить композицию.

Не рекомендуется:

if titleOpt.isDefined then  
  println(titleOpt.get)

Предпочтительно:

titleOpt.foreach(println)

Или через for:

for  
  title <- titleOpt  
  titleSize<- Some(title.length)  
yield titleSize

Композиция:

- уменьшает количество ветвлений;
    
- делает поток данных линейным;
    
- повышает читаемость;
    
- улучшает предсказуемость.
    

---

## Интеграция с коллекциями

Option легко преобразуется в коллекцию:

val titleList = titleOpt.toList

Это удобно при работе с flatMap:

val bookIds = List(100, 101, 102)

val evenIds =  
bookIds.flatMap(id =>  
  if id % 2 == 0 then Some(id) else None  
)

Option выступает как фильтр.

---

## Почему Option лучше null

  

|   |   |
|---|---|
|null|Option|
|Не отражён в типе|Отражён в типе|
|Возможен NPE|Безопасная композиция|
|Требует ручных проверок|Поддерживает map/flatMap|
|Легко забыть проверку|Компилятор помогает|

Option делает отсутствие значения явной частью модели данных.
