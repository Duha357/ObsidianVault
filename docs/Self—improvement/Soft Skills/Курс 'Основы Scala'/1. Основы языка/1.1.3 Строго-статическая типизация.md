## Строго-статическая типизация в Scala

Scala — строго-статически типизированный язык. Типы — инструмент проектирования, описания предметной области и проверки корректности на этапе компиляции.

Для разработчиков из динамически типизированных языков система кажется строгой. На практике снижает ошибки, улучшает читаемость, упрощает сопровождение.

---

## Статическая и строгая типизация: основные понятия

##### Статическая типизация

- Типы всех выражений определяются и проверяются на этапе компиляции.
- Корректность операций между значениями проверяется до запуска программы.
- Программа с типовыми ошибками не компилируется.

> [!example]- Пример: ошибка несовместимости типов
> Код объявляет `bookCount: Int` и `bookTitle: String`, затем складывает их в `result`.
>
> `bookCount + bookTitle` — ошибка компиляции: несовместимые типы Int и String.
>
> ```scala
> val bookCount: Int = 10
> val bookTitle: String = "Scala Basics"
>
> val result = bookCount + bookTitle
> // Ошибка компиляции: несовместимые типы Int и String
> ```
>
> Пример показывает: ошибки типов обнаруживаются до запуска, исключая класс runtime-ошибок.

##### Строгая типизация

Строгая типизация — язык не выполняет неявных и опасных преобразований. Значения разных типов не смешиваются автоматически; каждая операция типобезопасна.

> [!example]- Пример: отсутствие неявных преобразований
> В слаботипизированных языках `"5" + 2` даёт `"52"`, `"5" - 2` — 3.
>
> В Scala `"5" + 2` — ошибка компиляции.
>
> ```scala
> "5" + 2
> // Ошибка компиляции
> ```
>
> Пример показывает: Scala требует явного намерения разработчика, предотвращая скрытые ошибки.

## Сравнение с другими языками

| Язык | Типизация | Момент обнаружения ошибок |
|---|---|---|
| Python | Динамическая, строгая | Во время выполнения |
| JavaScript | Динамическая, слабая | Во время выполнения |
| Java | Статическая, строгая | Во время компиляции |
| Scala | Статическая, строгая | Во время компиляции |

Отличие Scala от Java: строгая статическая типизация сочетается с мощным выводом типов. Компактность и выразительность без потери безопасности.

## Преимущества строго-статической типизации

##### Раннее обнаружение ошибок

Ошибки типов — одна из самых распространённых категорий ошибок. В Scala выявляются до запуска приложения.

> [!example]- Пример: ошибка аргумента
> Код определяет `readBook(title: String)` и вызывает её с числом.
>
> `readBook(123)` — ошибка компиляции: ожидается String, передано Int.
>
> ```scala
> def readBook(title: String): String = "Book: " + title
>
> readBook(123)
> // Ошибка компиляции
> ```
>
> Пример показывает: разработчик получает обратную связь на этапе разработки, а не в production.

##### Самодокументируемый код

Типы — живая и всегда актуальная документация. Из сигнатуры ясно:

- Ожидается `AuthorId`, а не `Int`.
- Результат может отсутствовать: `Option`.
- Вызывающий код обрабатывает оба сценария.

> [!example]- Пример: сигнатура как документация
> Код объявляет функцию `findAuthor`, принимающую `AuthorId` и возвращающую `Option[Author]`.
>
> Сигнатура даёт больше информации, чем текстовый комментарий.
>
> ```scala
> def findAuthor(id: AuthorId): Option[Author]
> ```
>
> Пример показывает: сигнатура документирует код.

##### Оптимизация и производительность

Статическая типовая информация позволяет компилятору:

- Избегать лишних проверок во время выполнения.
- Выбирать более эффективные инструкции JVM.
- Агрессивнее оптимизировать код.

Scala-код после компиляции сопоставим по производительности с Java, иногда превосходит за счёт точных типовых сведений.

##### Безопасность рефакторинга

Строгая типизация делает компилятор и IDE помощниками при изменении кода.

> [!example]- Пример: компилятор указывает места изменений
> Код объявляет `getBookTitle(book: Book)`, обращающуюся к `book.title`.
>
> При изменении структуры `Book` компилятор укажет все места, где код перестал быть корректным.
>
> ```scala
> def getBookTitle(book: Book): String = book.title
> ```
>
> Пример показывает: безопасность рефакторинга важна для крупных кодовых баз.

## Механизмы усиления типовой безопасности в Scala

##### Вывод типов (Type Inference)

Вывод типов уменьшает шаблонный код без ослабления строгости.

> [!example]- Пример: вывод типов без аннотаций
> Код объявляет `pages` и `bookTitle` без явных аннотаций.
>
> `pages` — Int, `bookTitle` — String. Типы строго определены компилятором.
>
> ```scala
> val pages = 464           // Int
> val bookTitle = "Clean Code" // String
> ```
>
> Пример показывает: вывод типов избавляет от избыточных аннотаций, не отменяя типизацию.

##### Параметрический полиморфизм (Generics)

Обобщённые типы — универсальный типобезопасный код.

> [!example]- Пример: обобщённая функция first
> Код объявляет `first[T]`, возвращающую первый элемент `List[T]`, и применяет её к списку `books`.
>
> `first(books)` возвращает первый элемент; тип `T` одинаков для входа и результата.
>
> ```scala
> def first[T](list: List[T]): T =
>   list.head
>
> val books = List(
>   Book("Clean Code", 464, Author("Robert C. Martin")),
>   Book("Design Patterns", 395, Author("Erich Gamma"))
> )
>
> first(books)
> ```
>
> Пример показывает: обобщённый код гибкий и безопасный, без приведения типов.

##### Null-безопасность через типы

Отсутствие значения моделируется явно, не через null.

> [!example]- Пример: Option вместо null
> Код объявляет `findBook`, возвращающую `Option[Book]`, и обрабатывает оба случая через `match`.
>
> Для `"Programming in Scala"` печатается `book.title`, иначе — `"Book not found"`.
>
> ```scala
> def findBook(title: String): Option[Book] =
>   if title == "Programming in Scala" then Some(Book("Programming in Scala", 300, Author("Martin Odersky"))) else None
>
> findBook("Programming in Scala") match
>   case Some(book) => println(book.title)
>   case None       => println("Book not found")
> ```
>
> Пример показывает: вызывающий код обязан обработать оба случая, устраняя класс null-ошибок.

## Философия типизации в Scala

##### Типы не позволяют выразить некорректные состояния

Если состояние невозможно корректно представить типами, оно не должно существовать.

> [!example]- Пример: доменные типы
> Код объявляет `case class Author(name: String)` и `case class Book(title: String, pages: Int, author: Author)`.
>
> В `Book` ожидается `Author`, а не произвольный String.
>
> ```scala
> case class Author(name: String)
> case class Book(title: String, pages: Int, author: Author)
> ```
>
> Пример показывает: специализированный тип предотвращает передачу произвольных значений.

##### Типы выражают намерения разработчика

> [!example]- Пример: сигнатура с бизнес-смыслом
> Код объявляет `lendBook(from: Library, to: Reader, book: Book)`.
>
> Сигнатура описывает операцию: книга передаётся из библиотеки читателю.
>
> ```scala
> def lendBook(from: Library, to: Reader, book: Book):
> ```
>
> Пример показывает: сигнатура описывает не только технику, но и бизнес-смысл.

##### Типы лучше комментариев

Комментарии устаревают и не проверяются компилятором.

> [!example]- Пример: комментарий против типа
> Первый вариант — комментарий `// pages must be positive` с `pages: Int`; второй — тип `PositivePages`.
>
> Во втором варианте корректность обеспечивает типовая система, а не соглашения.
>
> ```scala
> // pages must be positive
> def addBook(title: String, pages: Int): Book
>
> case class PositivePages(value: Int)
> def addBook(title: String, pages: PositivePages): Book
> ```
>
> Пример показывает: типы проверяются компилятором, комментарии — нет.
