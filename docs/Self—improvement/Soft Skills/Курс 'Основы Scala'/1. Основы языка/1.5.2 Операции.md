Вместо явных циклов и изменяемых накопителей Scala предлагает набор операций, каждая из которых описывает один вид преобразования: `map` меняет элементы, `filter` отбирает, `flatMap` разворачивает вложенность, свёртки сводят коллекцию к одному значению. Все они не изменяют исходную коллекцию и принимают функцию параметром. Ниже: семантика каждой операции, связь `flatMap` с монадами и разница между левой и правой свёрткой.

---

## Декларативная обработка вместо цикла

> [!example]- Пример: Плохо — обработка циклом
> Новый список собирается вручную: заводится изменяемая переменная, элементы дописываются по одному.
>
> Ожидаемый результат: `result` — `List(200, 400, 600)`; при этом в коде три строки служебной механики и одна строка полезной логики.
>
> ```scala
> var result = List.empty[Int]
> for pages <- List(100, 200, 300) do
>   result = result :+ (pages * 2)
> ```
>
> Пример показывает: для чего нужны операции над коллекциями — обход и накопление повторяются в каждой задаче.

> [!example]- Пример: Хорошо — обработка через map
> Обход, создание новой коллекции и сборка результата выполняются одной операцией. Задаётся только правило преобразования.
>
> Ожидаемый результат: `List(200, 400, 600)` — тот же результат без изменяемых переменных.
>
> ```scala
> List(100, 200, 300).map(_ * 2)
> ```
>
> Пример показывает: зачем декларативный стиль — в коде остаётся только то, что отличает эту задачу от других.

Общие свойства функциональных операций:

- Не изменяют исходную коллекцию.
- Возвращают новую коллекцию.
- Принимают функцию как аргумент.

## map — преобразование один к одному

`map` применяет функцию к каждому элементу и собирает результаты. Количество элементов сохраняется, тип может измениться.

Сигнатура: `map[B](f: A => B): Collection[B]`.

> [!example]- Пример: map
> Каждое число страниц удваивается.
>
> Ожидаемый результат: `doubledPages` — `List(200, 400, 600)`, длина совпадает с исходной.
>
> ```scala
> val pageCounts = List(100, 200, 300)
> val doubledPages = pageCounts.map(_ * 2) // List(200, 400, 600)
> ```
>
> Пример показывает: почему `map` называют преобразованием один к одному — на каждый вход приходится ровно один выход.

---

## filter — отбор элементов

`filter` оставляет элементы, для которых предикат вернул `true`. Количество элементов может уменьшиться, тип не меняется.

Сигнатура: `filter(p: A => Boolean): Collection[A]`.

> [!example]- Пример: filter
> Из списка отбираются книги толще 150 страниц.
>
> Ожидаемый результат: `longBooks` — `List(200, 300)`.
>
> ```scala
> val longBooks = pageCounts.filter(_ > 150) // List(200, 300)
> ```
>
> Пример показывает: чем `filter` отличается от `map` — он меняет состав коллекции, а не значения элементов.

## flatMap — преобразование с разворачиванием

##### Проблема вложенности

Если функция сама возвращает коллекцию, `map` даёт коллекцию коллекций.

> [!example]- Пример: Плохо — map с функцией, возвращающей коллекцию
> Каждый элемент превращается в список из двух копий, поэтому результат оказывается вложенным.
>
> Ожидаемый результат: `List(List(100, 100), List(200, 200), List(300, 300))` — чтобы работать с числами дальше, вложенность придётся снимать отдельно.
>
> ```scala
> List(100, 200, 300).map(pages => List(pages, pages))
> // List(List(100, 100), List(200, 200), List(300, 300))
> ```
>
> Пример показывает: для чего нужен `flatMap` — `map` сохраняет структуру, которую вернула функция.

> [!example]- Пример: Хорошо — flatMap
> `flatMap` выполняет два шага сразу: применяет функцию и склеивает вложенные коллекции в одну.
>
> Ожидаемый результат: `List(100, 100, 200, 200, 300, 300)` — плоский список.
>
> ```scala
> List(100, 200, 300).flatMap(pages => List(pages, pages))
> // List(100, 100, 200, 200, 300, 300)
> ```
>
> Пример показывает: зачем `flatMap` — он убирает лишний уровень вложенности сразу после преобразования.

Сигнатура: `flatMap[B](f: A => Collection[B]): Collection[B]`.

##### Связь с другими контейнерами

`flatMap` — не только операция коллекций. Тот же метод есть у `Option`, `Either` и `Try`, и именно он лежит в основе:

- `for`-comprehension (раздел 1.5.3).
- Композиции вычислений в контексте — тема главы 3.

## Свёртки

Свёртка сводит коллекцию к одному значению, проходя её с аккумулятором.

##### foldLeft — левая свёртка

Сигнатура: `foldLeft[B](initial: B)(f: (B, A) => B): B`. Первый аргумент — начальное значение аккумулятора, второй — правило соединения аккумулятора с элементом.

> [!example]- Пример: foldLeft
> Список страниц сворачивается в сумму, начиная с нуля.
>
> Ожидаемый результат: `totalPages` — 600; порядок вычисления — `((0 + 100) + 200) + 300`.
>
> ```scala
> val totalPages = List(100, 200, 300).foldLeft(0)(_ + _) // 600
> ```
>
> Пример показывает: зачем нужна свёртка — любой обход с накоплением записывается одной операцией.

##### foldRight — правая свёртка

Сигнатура: `foldRight[B](initial: B)(f: (A, B) => B): B`. Обход идёт с конца коллекции.

> [!example]- Пример: Порядок свёртки меняет результат
> Одна и та же операция вычитания применяется двумя свёртками. Для некоммутативной операции направление обхода важно.
>
> Ожидаемый результат: `foldLeft` даёт -6 (`((0 - 1) - 2) - 3`), `foldRight` даёт 2 (`1 - (2 - (3 - 0))`).
>
> ```scala
> val numbers = List(1, 2, 3)
>
> numbers.foldLeft(0)(_ - _)  // -6
> numbers.foldRight(0)(_ - _) //  2
> ```
>
> Пример показывает: для чего различают левую и правую свёртку — на сложении разницы нет, на вычитании есть.

##### Выбор свёртки

> [!example]- Пример: Плохо — foldRight на большом List
> Правая свёртка на односвязном списке сначала доходит до конца, удерживая кадры вызовов в стеке.
>
> Ожидаемый результат: `StackOverflowError` на списке из миллиона элементов.
>
> ```scala
> val pages = List.fill(1_000_000)(1)
> pages.foldRight(0)(_ + _) // StackOverflowError
> ```
>
> Пример показывает: для чего знать реализацию свёрток — на `List` правая свёртка ограничена размером стека.

> [!example]- Пример: Хорошо — foldLeft на большом List
> Левая свёртка реализована хвостовой рекурсией и компилируется в цикл.
>
> Ожидаемый результат: 1 000 000 — вычисление проходит без переполнения стека.
>
> ```scala
> val pages = List.fill(1_000_000)(1)
> pages.foldLeft(0)(_ + _) // 1000000
> ```
>
> Пример показывает: почему `foldLeft` выбирают по умолчанию — он безопасен по стеку на коллекциях любого размера.

Для индексируемых коллекций вроде `Vector` (раздел 1.5.1) разница менее критична, но `foldLeft` остаётся предпочтительным.

## reduce — свёртка без начального значения

`reduce` сворачивает коллекцию, беря первый элемент в качестве начального значения. Формально `reduce(f)` эквивалентно `tail.foldLeft(head)(f)`.

> [!example]- Пример: Плохо — reduce на возможно пустой коллекции
> Начального значения нет, поэтому на пустой коллекции взять его неоткуда.
>
> Ожидаемый результат: `UnsupportedOperationException` — исключение вместо результата.
>
> ```scala
> val pages = List.empty[Int]
> pages.reduce(_ + _) // UnsupportedOperationException
> ```
>
> Пример показывает: для чего у `reduce` есть безопасный вариант — пустая коллекция ломает его по определению.

> [!example]- Пример: Хорошо — reduceOption
> `reduceOption` возвращает `Option`: пустой коллекции соответствует `None`.
>
> Ожидаемый результат: для пустого списка — `None`; для `List(100, 200, 300)` — `Some(600)`.
>
> ```scala
> List.empty[Int].reduceOption(_ + _)   // None
> List(100, 200, 300).reduceOption(_ + _) // Some(600)
> ```
>
> Пример показывает: зачем `reduceOption` — отсутствие результата выражается значением, а не исключением.

## Комбинирование операций

Операции соединяются в цепочку, образуя конвейер обработки данных.

> [!example]- Пример: Конвейер из трёх операций
> Список последовательно проходит отбор, преобразование и свёртку. Каждый шаг работает с результатом предыдущего.
>
> Ожидаемый результат: 1800 — отобраны 200, 300 и 400; удвоены до 400, 600 и 800; сумма равна 1800.
>
> ```scala
> val result =
>   List(100, 200, 300, 400)
>     .filter(_ > 150)     // List(200, 300, 400)
>     .map(_ * 2)          // List(400, 600, 800)
>     .foldLeft(0)(_ + _)  // 1800
> ```
>
> Пример показывает: зачем операции делают однотипными — их можно соединять в цепочку, читаемую сверху вниз.
