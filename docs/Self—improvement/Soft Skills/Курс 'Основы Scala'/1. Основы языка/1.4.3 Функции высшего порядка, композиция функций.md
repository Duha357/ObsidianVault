Функция высшего порядка принимает функцию аргументом, возвращает функцию результатом или делает и то, и другое. Это прямое следствие того, что в Scala функции являются значениями. Композиция позволяет собрать из нескольких простых функций одну — конвейер обработки данных. Ниже: обе роли функций высшего порядка, их применение в стандартной библиотеке и операции `andThen` и `compose`.

---

## Передача функции как аргумента

Функция передаётся в другую функцию так же, как любое значение.

> [!example]- Пример: Функция в параметре
> `applyToPages` не знает, что именно делать со страницами, — правило приходит параметром `transform` и применяется дважды.
>
> Ожидаемый результат: `applyToPages(addExtraPages, 150)` возвращает 190 — по 20 страниц за каждое применение.
>
> ```scala
> def applyToPages(transform: Int => Int, pages: Int): Int =
>   transform(transform(pages))
>
> val addExtraPages: Int => Int = _ + 20
>
> applyToPages(addExtraPages, 150) // 190
> ```
>
> Пример показывает: зачем передавать функцию — алгоритм отделяется от конкретного правила.

---

## Возврат функции из функции

Функция может построить и вернуть другую функцию, запомнив значения из своего окружения.

> [!example]- Пример: Функция-фабрика
> `pagesMultiplier` возвращает лямбду, которая помнит переданный `factor`. Такое запоминание внешнего значения называется замыканием.
>
> Ожидаемый результат: `doublePages` имеет тип `Int => Int`; `doublePages(120)` возвращает 240.
>
> ```scala
> def pagesMultiplier(factor: Int): Int => Int =
>   (pages: Int) => pages * factor // factor захвачен замыканием
>
> val doublePages = pagesMultiplier(2)
> doublePages(120) // 240
> ```
>
> Пример показывает: для чего возвращать функцию — так настраиваемое поведение создаётся один раз и переиспользуется.

## Функции высшего порядка в стандартной библиотеке

Большинство операций над коллекциями — функции высшего порядка.

##### map

`map` применяет переданную функцию к каждому элементу и собирает результаты в новую коллекцию.

> [!example]- Пример: map
> Функция удвоения передаётся в `map` и применяется поэлементно.
>
> Ожидаемый результат: `List(2, 4, 6)` — исходный список не изменяется.
>
> ```scala
> List(1, 2, 3).map(_ * 2)
> ```
>
> Пример показывает: почему `map` — функция высшего порядка: правило преобразования задаёт вызывающий код.

##### filter

`filter` принимает предикат и оставляет элементы, для которых он истинен.

> [!example]- Пример: filter
> Предикат «остаток от деления на 2 равен нулю» передаётся в `filter`.
>
> Ожидаемый результат: `List(2, 4)`.
>
> ```scala
> List(1, 2, 3, 4).filter(_ % 2 == 0)
> ```
>
> Пример показывает: зачем отбор выражают функцией — условие меняется, а обход остаётся общим.

##### foldLeft

`foldLeft` принимает начальное значение и функцию накопления, сворачивая коллекцию в одно значение.

> [!example]- Пример: foldLeft
> Первый аргумент — начальное значение аккумулятора, второй — правило соединения аккумулятора с элементом.
>
> Ожидаемый результат: 6 — последовательно вычисляется `((0 + 1) + 2) + 3`.
>
> ```scala
> List(1, 2, 3).foldLeft(0)(_ + _)
> ```
>
> Пример показывает: для чего нужна свёртка — так любой обход с накоплением записывается без цикла и переменной.

## Композиция функций

Композиция строит новую функцию из нескольких простых. Если `f: A => B` и `g: B => C`, их композиция имеет тип `A => C`.

##### andThen

`andThen` применяет функции слева направо: сначала первая, затем вторая.

> [!example]- Пример: andThen
> Две функции соединяются в одну. Результат `double` попадает на вход `increment`.
>
> Ожидаемый результат: `pipeline(3)` возвращает 7 — вычисляется `(3 * 2) + 1`.
>
> ```scala
> val double: Int => Int = _ * 2
> val increment: Int => Int = _ + 1
>
> val pipeline = double.andThen(increment) // сначала double, потом increment
>
> pipeline(3) // 7
> ```
>
> Пример показывает: зачем `andThen` — порядок применения читается так же, как порядок записи.

##### compose

`compose` применяет функции справа налево — как в математической записи `f(g(x))`.

> [!example]- Пример: compose
> Те же две функции соединяются в обратном порядке записи, но выполняются в том же порядке действий.
>
> Ожидаемый результат: `composed(3)` возвращает 7 — вычисляется `increment(double(3))`.
>
> ```scala
> val composed = increment.compose(double) // сначала double, потом increment
>
> composed(3) // 7
> ```
>
> Пример показывает: чем `compose` отличается от `andThen` — тем же результатом при обратном порядке записи.

## Построение конвейера обработки

Композиция позволяет собрать сложную обработку из независимых шагов.

> [!example]- Пример: Плохо — вложенные вызовы
> Три преобразования записаны вложенными вызовами. Порядок выполнения читается изнутри наружу, справа налево.
>
> Ожидаемый результат: `"Library: DUNE"`; при добавлении четвёртого шага вложенность растёт ещё на уровень.
>
> ```scala
> addLibraryTag(toUpperCase(trimTitle("  dune  ")))
> ```
>
> Пример показывает: для чего нужна композиция — вложенные вызовы читаются в обратном порядке и плохо расширяются.

> [!example]- Пример: Хорошо — конвейер через andThen
> Шаги перечислены в порядке выполнения и собраны в одну функцию, которую можно переиспользовать.
>
> Ожидаемый результат: `processBookTitle("  dune  ")` возвращает `"Library: DUNE"`.
>
> ```scala
> val trimTitle: String => String = _.trim
> val toUpperCase: String => String = _.toUpperCase
> val addLibraryTag: String => String = "Library: " + _
>
> val processBookTitle =
>   trimTitle
>     .andThen(toUpperCase)
>     .andThen(addLibraryTag)
>
> processBookTitle("  dune  ") // "Library: DUNE"
> ```
>
> Пример показывает: зачем собирать конвейер — шаги читаются сверху вниз и тестируются по отдельности.

Преимущества такого подхода:

- Декларативность: описан порядок шагов, а не механика вызовов.
- Повторное использование отдельных функций.
- Тестируемость каждого этапа изолированно.
- Линейный поток данных.

## Связь с монадической композицией

Функции высшего порядка лежат в основе `map`, `flatMap` и `for`-comprehension, а через них — работы с `Option`, `Either` и `List`. Композиция функций — частный случай более общей идеи композиции вычислений, к которой курс возвращается в главе 3.
