Тип-произведение объединяет несколько значений в одно составное: значение содержит A **и** B одновременно. В Scala их два вида — кортеж, где поля различаются позицией, и case-класс, где у полей есть имена. Ниже: концепция логического «И», работа с кортежами и роль case-классов как именованных типов-произведений.

Полное описание case-классов — в разделе 2.1.3; здесь показано только то, что делает их типом-произведением.

---

## Тип-произведение как логическое «И»

Формально произведение A × B содержит данные обоих типов сразу. Практически это любая структура, где поля существуют вместе, а не вместо друг друга.

> [!example]- Пример: Значение содержит оба поля
> Кортеж хранит название книги и год публикации в одном значении.
>
> Ожидаемый результат: `bookInfo` содержит и строку `"Dune"`, и число `1965`; получить одно без другого нельзя.
>
> ```scala
> val bookInfo: (String, Int) = ("Dune", 1965)
> ```
>
> Пример показывает: зачем вводят понятие «произведение» — оно описывает данные, которые всегда встречаются вместе.

## Кортежи (Tuples)

##### Назначение

Кортеж группирует разнородные значения без объявления собственного класса. Scala поддерживает `Tuple2`, `Tuple3` и далее.

> [!example]- Пример: Синтаксис кортежа
> Запись `(String, Int)` — сокращение для `Tuple2[String, Int]`. Отдельный тип объявлять не нужно.
>
> Ожидаемый результат: `authorInfo` содержит `("Tolkien", 81)` и имеет тип `(String, Int)`.
>
> ```scala
> val authorInfo: (String, Int) = ("Tolkien", 81)
> ```
>
> Пример показывает: для чего нужны кортежи — временную пару значений можно собрать прямо на месте.

##### Доступ к элементам

Элементы адресуются по номеру, начиная с первого.

> [!example]- Пример: Плохо — доступ по индексу
> Элементы извлекаются через `._1` и `._2`. Что означает каждый номер, из кода не видно.
>
> Ожидаемый результат: `authorInfo._1` — `"Tolkien"`, `authorInfo._2` — `81`; смысл полей приходится помнить.
>
> ```scala
> authorInfo._1 // "Tolkien" — имя? фамилия? псевдоним?
> authorInfo._2 // 81
> ```
>
> Пример показывает: почему кортежи не годятся для публичного API — номер поля ничего не сообщает о его смысле.

> [!example]- Пример: Хорошо — деструктуризация
> Кортеж разбирается на именованные значения одной строкой.
>
> Ожидаемый результат: `authorName` — `"Tolkien"`, `authorAge` — `81`; имена объясняют содержимое.
>
> ```scala
> val (authorName, authorAge) = authorInfo
> ```
>
> Пример показывает: зачем деструктуризация — она возвращает полям смысл сразу после получения кортежа.

##### Когда использовать кортежи

Кортежи уместны:

- Для временных значений внутри одного метода.
- При возврате нескольких результатов из функции.
- В простых локальных вычислениях.
- **Не:**
    - В публичных API, где важна семантика полей.
    - В доменной модели, которая живёт долго и читается многими.

## Case-классы как именованные типы-произведения

Кортеж объединяет данные позиционно, case-класс — именованно. Набор данных тот же, различается способ обращения к полям.

> [!example]- Пример: Объявление case-класса
> Одна строка объявляет тип с двумя именованными полями и их типами.
>
> Ожидаемый результат: объявлен тип `Book` с полями `title: String` и `pages: Int`.
>
> ```scala
> case class Book(title: String, pages: Int)
> ```
>
> Пример показывает: почему case-класс вытесняет кортеж — объявление стоит одной строки, а поля получают имена.

> [!example]- Пример: Создание экземпляра
> Значения передаются конструктору в порядке объявления полей. Ключевое слово `new` не требуется.
>
> Ожидаемый результат: `book` — `Book("The Hobbit", 310)`.
>
> ```scala
> val book = Book("The Hobbit", 310) // new не нужен
> ```
>
> Пример показывает: для чего компилятор генерирует `apply` — вызов конструктора выглядит как вызов функции.

##### Что генерирует компилятор

Case-класс автоматически получает:

1. Метод `equals`.
2. Метод `hashCode`.
3. Метод `toString`.
4. Методы доступа к полям.
5. Метод `copy`.
6. Поддержку сопоставления с образцом.

> [!example]- Пример: Сравнение по значению
> Два независимо созданных экземпляра с одинаковыми полями сравниваются оператором `==`.
>
> Ожидаемый результат: `true` — сравниваются значения полей, а не ссылки на объекты. Для обычного класса результат был бы `false`.
>
> ```scala
> val firstBook = Book("Dune", 500)
> val secondBook = Book("Dune", 500)
>
> firstBook == secondBook // true
> ```
>
> Пример показывает: зачем сгенерированный `equals` — носители данных сравниваются по содержимому, как того ожидает вызывающий код.

##### Неизменяемость

Поля case-класса по умолчанию объявлены как `val`, поэтому состояние не меняется после создания.

> [!example]- Пример: Плохо — изменяемое поле
> Поле объявлено через `var`, чтобы «обновить» страницы на месте. Все, кто уже получил ссылку, увидят чужое изменение.
>
> Ожидаемый результат: `book.pages` становится 320, при этом `hashCode` объекта меняется — если книга уже лежит в `Set` или `Map`, найти её больше не получится.
>
> ```scala
> case class Book(title: String, var pages: Int)
>
> val book = Book("The Hobbit", 310)
> book.pages = 320 // объект изменился на месте
> ```
>
> Пример показывает: для чего case-классы делают неизменяемыми — изменяемое поле ломает хеш-структуры и предсказуемость.

> [!example]- Пример: Хорошо — изменение через copy
> `copy` создаёт новый экземпляр, перенося все поля, кроме явно указанных.
>
> Ожидаемый результат: `updatedBook` — `Book("The Hobbit", 320)`, исходный `book` остаётся `Book("The Hobbit", 310)`.
>
> ```scala
> case class Book(title: String, pages: Int)
>
> val book = Book("The Hobbit", 310)
> val updatedBook = book.copy(pages = 320) // новый объект
> ```
>
> Пример показывает: зачем нужен `copy` — состояние обновляется без изменения существующего объекта.

Неизменяемость даёт безопасность при параллельном использовании и предсказуемость поведения.

## Сравнение кортежей и case-классов

| Характеристика | Кортеж | Case-класс |
|---|---|---|
| Именованные поля | Нет | Да |
| Семантика | Позиционная | Явная |
| Поддержка pattern matching | Да | Да |
| Подходит для публичного API | Нет | Да |

---

## Рекомендации по размеру

| Размер | Что использовать | Причина |
|---|---|---|
| 1-3 поля | Кортеж | Быстро, удобно для временных структур |
| 4-5 полей | Case-класс | Читаемость, именованные поля |
| Больше 5 полей | Case-класс | Кортеж становится нечитаемым |
