# Типы-произведения в Scala

---

## Тип-произведение как логическое «И»

Тип-произведение объединяет несколько значений в одно составное значение.

Интуитивно: если типы A и B объединены в произведение, значение содержит A И B одновременно.

Формально: произведение A × B содержит данные обоих типов.

> [!example]- Пример: тип-произведение как логическое «И»
> Создаётся кортеж `(String, Int)` с названием книги и годом публикации.
> 
> Значение `bookInfo` содержит оба элемента: строку и число.
> 
> ```scala
> val bookInfo: (String, Int) = ("Dune", 1965)
> ```
> 
> Пример показывает: тип-произведение объединяет значения типов A и B в одно составное значение.

## Кортежи (Tuples)

##### Назначение

Кортеж объединяет несколько разнородных значений без объявления собственного класса.

Scala поддерживает Tuple2, Tuple3, … до произвольной арности (в Scala 3 — без фиксированного ограничения).

> [!example]- Пример: синтаксис кортежа
> Объявляется кортеж с именем и возрастом автора.
> 
> Тип `(String, Int)` соответствует значению `("Tolkien", 81)`.
> 
> ```scala
> val authorInfo: (String, Int) = ("Tolkien", 81)
> ```
> 
> Пример показывает: запись `(String, Int)` — сокращение для `Tuple2[String, Int]`.

##### Доступ к элементам

Доступ к элементам возможен по индексу.

> [!example]- Пример: доступ по индексу
> Элементы кортежа запрашиваются через `._1` и `._2`.
> 
> `authorInfo._1` возвращает `"Tolkien"`, `authorInfo._2` — `81`.
> 
> ```scala
> authorInfo._1  // "Tolkien"
> authorInfo._2  // 81
> ```
> 
> Пример показывает: элементы кортежа адресуются номерами, начиная с 1.

В Scala 3 доступна деструктуризация.

> [!example]- Пример: деструктуризация кортежа
> Кортеж `authorInfo` разбивается на две отдельные переменные.
> 
> `authorName` получает `"Tolkien"`, `authorAge` — `81`.
> 
> ```scala
> val (authorName, authorAge) = authorInfo
> ```
> 
> Пример показывает: деструктуризация — предпочтительный способ работы с кортежами в Scala 3.

##### Когда использовать кортежи

Кортежи уместны:

- Для временных значений.
- При возврате нескольких результатов из функции.
- В простых локальных вычислениях.
- **Не:**
	- Использовать кортежи в публичных API, где важна семантика полей.

## Case-классы как именованные типы-произведения

Кортежи объединяют данные позиционно. Case-классы объединяют данные именованно.

> [!example]- Пример: объявление case-класса
> Объявляется case-класс `Book` с полями `title` и `pages`.
> 
> Полям задаются типы `String` и `Int`.
> 
> ```scala
> case class Book(title: String, pages: Int)
> ```
> 
> Пример показывает: case-класс объединяет данные именованно, в отличие от кортежа.

> [!example]- Пример: создание экземпляра
> Создаётся экземпляр `Book` со значениями `"The Hobbit"` и `310`.
> 
> Значения передаются конструктору в порядке объявления полей.
> 
> ```scala
> val book = Book("The Hobbit", 310)
> ```
> 
> Пример показывает: экземпляр case-класса создаётся без `new`.

##### Что делает case-класс

Case-класс автоматически генерирует:

1. Метод `equals`.
2. Метод `hashCode`.
3. Метод `toString`.
4. Методы доступа к полям.
5. Метод `copy`.
6. Поддержку pattern matching.

> [!example]- Пример: сравнение по значению
> Два экземпляра с одинаковыми полями сравниваются оператором `==`.
> 
> Результат сравнения — `true`.
> 
> ```scala
> val firstBook = Book("Dune", 500)
> val secondBook = Book("Dune", 500)
> 
> firstBook == secondBook // true
> ```
> 
> Пример показывает: case-классы сравниваются по значению, а не по ссылке.

##### Неизменяемость

Поля case-класса по умолчанию объявлены как `val`.

Это означает:

- Неизменяемость состояния.
- Безопасность при параллельном использовании.
- Предсказуемость поведения.

Изменение полей осуществляется через `copy`.

> [!example]- Пример: изменение через `copy`
> Из `book` через `copy` создаётся `updatedBook` с `pages = 320`.
> 
> `updatedBook` — новый объект, исходный `book` не изменяется.
> 
> ```scala
> val updatedBook = book.copy(pages = 320)
> ```
> 
> Пример показывает: `copy` реализует неизменяемость — изменения создают новый объект.

---

## Сравнение кортежей и case-классов

|Характеристика|Кортеж|Case-класс|
|---|---|---|
|Именованные поля|Нет|Да|
|Семантика|Позиционная|Явная|
|Поддержка pattern matching|Да|Да|
|Подходит для публичного API|Нет|Да|

---

## Рекомендации по размеру

|Размер кортежа|Лучше использовать|Причина|
|---|---|---|
|1-3 поля|Кортеж|Быстро, удобно для временных структур|
|4-5 поля|Case-class|Читаемость, именованные поля|
|>5 полей|Case-class|Кортеж становится нечитаемым|
