В Scala соседствуют две похожие, но разные сущности: метод, объявленный через `def` и принадлежащий классу или объекту, и функциональное значение — объект типа `FunctionN`, который можно присвоить, передать и вернуть. Ниже: синтаксис методов и лямбд, сокращённые формы записи, различие метода и функции и механизм eta-расширения, который превращает первое во второе.

---

## Методы (def)

Метод объявляется ключевым словом `def` и является членом класса или объекта.

> [!example]- Пример: Объявление метода
> Метод объявлен внутри объекта `LibraryUtils`. Указаны типы параметра и результата.
>
> Ожидаемый результат: `countPages(150)` возвращает 300.
>
> ```scala
> object LibraryUtils:
>   def countPages(pages: Int): Int =
>     pages * 2
> ```
>
> Пример показывает: зачем нужен `def` — им объявляют поведение, привязанное к типу.

Свойства метода:

- Объявляется ключевым словом `def`.
- Принадлежит классу или объекту.
- Сам по себе значением не является.
- Тело вычисляется при каждом вызове.

> [!example]- Пример: Вызов метода
> Метод вызывается через объект-владелец.
>
> Ожидаемый результат: `LibraryUtils.countPages(150)` возвращает 300.
>
> ```scala
> LibraryUtils.countPages(150)
> ```
>
> Пример показывает: почему метод нельзя передать напрямую — он существует только вместе со своим владельцем.

## Функциональные значения

Функция в Scala может быть значением. Тип такой функции записывается стрелкой: `Int => Int`.

> [!example]- Пример: Лямбда, присвоенная значению
> Лямбда-выражение присваивается имени с явно указанным типом функции.
>
> Ожидаемый результат: `increasePages` имеет тип `Int => Int`; `increasePages(150)` возвращает 300.
>
> ```scala
> val increasePages: Int => Int =
>   (pages: Int) => pages * 2
> ```
>
> Пример показывает: зачем функциональные значения — поведение хранится в переменной наравне с данными.

Такое значение — объект, реализующий трейт `Function1[Int, Int]`. Именно поэтому его можно передавать и возвращать.

## Анонимные функции (лямбды)

Анонимная функция состоит из списка параметров, стрелки `=>` и тела.

> [!example]- Пример: Лямбда с типом параметра
> Тип параметра указан явно, потому что контекста для вывода нет.
>
> Ожидаемый результат: выражение имеет тип `Int => Int`; вызов с 150 вернёт 300.
>
> ```scala
> (bookCount: Int) => bookCount * 2
> ```
>
> Пример показывает: для чего указывать тип параметра — без контекста компилятору его взять неоткуда.

Тип параметра опускается, если компилятор выводит его из контекста.

> [!example]- Пример: Лямбда без типа параметра
> Тип функции объявлен слева, поэтому тип параметра выводится автоматически.
>
> Ожидаемый результат: `bookCount` получает тип `Int`, выведенный из аннотации `Int => Int`.
>
> ```scala
> val doublePages: Int => Int = bookCount => bookCount * 2
> ```
>
> Пример показывает: почему аннотация типа параметра встречается редко — контекст обычно уже задаёт тип.

## Синтаксический сахар с подчёркиванием

Если параметр используется в теле ровно один раз, его имя заменяется на `_`.

> [!example]- Пример: Плохо — избыточное имя параметра
> Параметр объявлен, назван и использован один раз. Имя ничего не добавляет к смыслу.
>
> Ожидаемый результат: `List(150, 250, 350)`.
>
> ```scala
> List(100, 200, 300).map(bookPages => bookPages + 50)
> ```
>
> Пример показывает: для чего нужна сокращённая форма — в короткой лямбде имя параметра только удлиняет запись.

> [!example]- Пример: Хорошо — сокращённая форма
> Подчёркивание заменяет единственный параметр, объявлять его не нужно.
>
> Ожидаемый результат: `List(150, 250, 350)` — тот же результат.
>
> ```scala
> List(100, 200, 300).map(_ + 50)
> ```
>
> Пример показывает: зачем `_` — он убирает объявление там, где параметр очевиден из контекста.

Правило: `_` применяется, если каждый параметр встречается в теле ровно один раз. При нескольких параметрах пишется по одному подчёркиванию на каждый.

> [!example]- Пример: Несколько параметров через _
> Два подчёркивания соответствуют первому и второму параметру по порядку.
>
> Ожидаемый результат: `totalPages` имеет тип `(Int, Int) => Int`; `totalPages(320, 210)` вернёт 530.
>
> ```scala
> val totalPages: (Int, Int) => Int = _ + _
> ```
>
> Пример показывает: почему форма работает и для нескольких параметров — подчёркивания подставляются по позиции.

## Метод против функции

Метод и функциональное значение внешне похожи, но это разные сущности.

##### Метод

> [!example]- Пример: Метод с двумя параметрами
> Обычный метод: объявлен через `def`, имеет типы параметров и результата.
>
> Ожидаемый результат: `addBooks(2, 3)` возвращает 5.
>
> ```scala
> def addBooks(firstShelf: Int, secondShelf: Int): Int = firstShelf + secondShelf
> ```
>
> Пример показывает: как выглядит объявление, с которым дальше сравнивается функциональное значение.

Метод принадлежит классу или объекту, не является объектом сам и не имеет типа `FunctionN`.

##### Функциональное значение

> [!example]- Пример: Функциональное значение с двумя параметрами
> То же поведение записано как значение с типом функции.
>
> Ожидаемый результат: `addBooksFn` имеет тип `(Int, Int) => Int`, то есть `Function2[Int, Int, Int]`; `addBooksFn(2, 3)` вернёт 5.
>
> ```scala
> val addBooksFn: (Int, Int) => Int = (firstShelf, secondShelf) => firstShelf + secondShelf
> ```
>
> Пример показывает: почему различие важно — только функциональное значение можно передать как аргумент.

##### Сравнение

| Характеристика | Метод (`def`) | Функция (`val f = ...`) |
|---|---|---|
| Является значением | Нет | Да |
| Принадлежит классу | Да | Нет, это самостоятельное значение |
| Передаётся напрямую | Через eta-расширение | Да |
| Тип | Не `FunctionN` | `FunctionN` |

## Eta-расширение

Eta-расширение — превращение метода в функциональное значение.

> [!example]- Пример: Плохо — ручная обёртка метода
> Метод оборачивается в лямбду вручную: объявляется параметр только для того, чтобы сразу передать его дальше.
>
> Ожидаемый результат: `List(200, 400, 600)`; лямбда не добавляет логики, только повторяет сигнатуру метода.
>
> ```scala
> List(100, 200, 300).map(pages => LibraryUtils.countPages(pages))
> ```
>
> Пример показывает: для чего нужно eta-расширение — без него метод приходится оборачивать вручную.

> [!example]- Пример: Хорошо — автоматическое eta-расширение
> Контекст ожидает функцию `Int => Int`, поэтому компилятор превращает метод в функциональное значение сам.
>
> Ожидаемый результат: `List(200, 400, 600)` — тот же результат без обёртки.
>
> ```scala
> List(100, 200, 300).map(LibraryUtils.countPages)
> ```
>
> Пример показывает: зачем компилятор делает преобразование автоматически — метод передаётся так же просто, как функция.

Когда контекст не подсказывает тип, преобразование запускается подчёркиванием после имени метода.

> [!example]- Пример: Явное eta-расширение через _
> Подчёркивание после имени метода без списка аргументов означает «взять метод как значение».
>
> Ожидаемый результат: `calculateBooksFn` имеет тип `(Int, Int) => Int`.
>
> ```scala
> def calculateBooks(boxes: Int, booksPerBox: Int): Int = boxes * booksPerBox
>
> val calculateBooksFn = calculateBooks _ // явное преобразование
> ```
>
> Пример показывает: почему запись `имя _` встречается в коде — она нужна там, где тип не выводится из контекста.

## Функции в API коллекций

Методы коллекций принимают функции параметрами — это основной сценарий, ради которого функции сделали значениями.

> [!example]- Пример: Передача функций в методы коллекций
> Три операции получают разные функции: преобразование, предикат и правило свёртки.
>
> Ожидаемый результат: `map` — `List(110, 210, 310)`, `filter` — `List(300)`, `foldLeft` — 600.
>
> ```scala
> val bookPages = List(100, 200, 300)
>
> bookPages.map(_ + 10)        // преобразование каждого элемента
> bookPages.filter(_ > 200)    // отбор по условию
> bookPages.foldLeft(0)(_ + _) // свёртка в одно значение
> ```
>
> Пример показывает: для чего функции сделали значениями — стандартная библиотека построена на их передаче.
