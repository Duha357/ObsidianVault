# Функции

Функции — центральный элемент языка Scala. В отличие от строго объектно-ориентированных языков, Scala проектировалась как гибридная платформа, объединяющая объектную и функциональную парадигмы.

В Scala функции:
- Могут быть методами классов и объектов.
- Могут быть значениями (объектами).
- Могут передаваться как аргументы.
- Могут возвращаться из других функций.
- Могут комбинироваться и образовывать композиции.

---

## Методы и функции: принципиальное различие

##### Методы (def)

Метод — член класса или объекта. Объявляется ключевым словом `def`.

> [!example]- Пример: метод
> Метод `add` принимает два числа и возвращает их сумму.
>
> ```scala
> def add(a: Int, b: Int): Int = a + b
> ```
>
> Пример показывает: синтаксис объявления метода с типами параметров и результата.

Свойства метода:
- Не является значением.
- Не существует как самостоятельный объект.
- Вызывается по имени.
- Принадлежит классу или объекту.

Метод — не функция, несмотря на синтаксическое сходство. Функцией становится только после преобразования — eta-расширения.

##### Анонимные функции (лямбды)

Анонимная функция — функциональное значение, объект.

> [!example]- Пример: анонимная функция
> Лямбда `double` удваивает аргумент. Вызов `double(10)` возвращает 20.
>
> ```scala
> val double = (x: Int) => x * 2
> double(10) // 20
> ```
>
> Пример показывает: объявление функционального значения и его вызов.

Тип такой функции — `Int => Int`.

В отличие от метода, это значение, которое можно:
- Передавать как аргумент.
- Возвращать.
- Хранить в переменной.
- Комбинировать.

На уровне JVM такие функции реализуются объектами FunctionN.

---

## Синтаксический сахар для лямбд

Если параметр используется один раз, допустима сокращённая форма с `_`.

> [!example]- Пример: один параметр
> `val double = _ * 2` — сокращение для `(x: Int) => x * 2`.
>
> ```scala
> val double = _ * 2
> ```
>
> Пример показывает: замену однократно используемого параметра подчёркиванием.

При нескольких параметрах — по одному `_` на каждый.

> [!example]- Пример: несколько параметров
> `_ + _` — сокращение для `(x, y) => x + y`.
>
> ```scala
> val sum = _ + _
> ```
>
> Пример показывает: сокращённую форму для нескольких параметров.

Сокращения применимы только при однозначном выводе типов компилятором.

---

## Метод vs функция: сравнение

> [!example]- Пример: метод и функция
> `inc` — метод, `f` — функциональное значение с тем же поведением.
>
> ```scala
> def inc(x: Int): Int = x + 1  // метод
> val f = (x: Int) => x + 1     // функция
> ```
>
> Пример показывает: синтаксическую близость метода и функции при различии их природы.

Функция:
- Является объектом.
- Имеет тип Function1[Int, Int].
- Может передаваться как значение.

Метод — нет.

---

## Eta-расширение (преобразование метода в функцию)

Метод можно явно преобразовать в функцию.

> [!example]- Пример: eta-расширение
> `square _` создаёт функциональное значение на основе метода `square`.
>
> ```scala
> def square(x: Int): Int = x * x
>
> val f = square _
> ```
>
> Пример показывает: преобразование метода в функцию через подчёркивание.

Подчёркивание сообщает компилятору: выполнить eta-расширение — создать функциональное значение на основе метода.

В Scala 3 во многих случаях eta-расширение автоматическое. Понимание механизма важно для корректной модели языка.

## Чистые функции

Функция считается чистой, если:
1. При одинаковых аргументах всегда возвращает одинаковый результат.
2. Не имеет побочных эффектов.

> [!example]- Пример: чистая функция
> `sum` складывает два числа, не изменяя внешнее состояние. Результат зависит только от аргументов.
>
> ```scala
> def sum(a: Int, b: Int): Int = a + b
> ```
>
> Пример показывает: детерминизм и отсутствие побочных эффектов.

> [!example]- Пример: нечистая функция
> `add` изменяет внешнюю переменную `total`. Результат зависит от внешнего состояния.
>
> ```scala
> var total = 0
>
> def add(x: Int): Int =
>   total += x
>   total
> ```
>
> Пример показывает: побочный эффект через изменение внешнего состояния.

##### Почему это важно

Чистые функции:
- Проще тестировать.
- Безопасны при параллельном выполнении.
- Легче комбинируются.
- Предсказуемы.

Scala поощряет проектирование через чистые функции, но не ограничивает разработчика императивной моделью.

---

## Рекурсия

В функциональном стиле рекурсия часто заменяет циклы.

> [!example]- Пример: рекурсивный факториал
> `factorial` вызывает саму себя с уменьшенным аргументом. Рекурсивный вызов — не последняя операция: результат умножается на `n`.
>
> ```scala
> def factorial(n: Int): Int =
>   if n == 0 then 1
>   else n * factorial(n - 1)
> ```
>
> Пример показывает: замену цикла рекурсией.

##### Проблема

Глубокая рекурсия может привести к StackOverflowError.

---

## Хвостовая рекурсия (Tail Recursion)

Хвостовая рекурсия — рекурсивный вызов является последней операцией функции.

> [!example]- Пример: хвостовая рекурсия
> `factorial` передаёт промежуточный результат через аккумулятор `acc`. Рекурсивный вызов — последнее действие.
>
> ```scala
> import scala.annotation.tailrec
>
> @tailrec
> def factorial(n: Int, acc: Int = 1): Int =
>   if n == 0 then acc
>   else factorial(n - 1, acc * n)
> ```
>
> Пример показывает: рекурсию с аккумулятором и аннотацией @tailrec.

##### Аннотация @tailrec

- Гарантирует, что рекурсия действительно хвостовая.
- При нарушении компиляция завершится ошибкой.
- Компилятор оптимизирует вызов в цикл.
- Стек не расходуется.

Аннотации подробнее рассматриваются в лекции по ООП.

---

## Функции высшего порядка

Функция высшего порядка (Higher-Order Function):
- Принимает функцию как аргумент.
- Возвращает функцию.

> [!example]- Пример: функция высшего порядка
> `applyTwice` применяет функцию `f` к значению `x` дважды. `applyTwice(f, x)` возвращает `f(f(x))`.
>
> ```scala
> def applyTwice(f: Int => Int, x: Int): Int = f(f(x))
> ```
>
> Пример показывает: передачу функции как аргумента.

Функции высшего порядка — фундамент функционального стиля.

---

## Композиция функций

Композиция позволяет объединять функции в конвейер.

> [!example]- Пример: функции для композиции
> `f` добавляет 1, `g` удваивает. На их основе строятся andThen и compose.
>
> ```scala
> val f = (x: Int) => x + 1
> val g = (x: Int) => x * 2
> ```
>
> Пример показывает: базовые функции для операций композиции.

##### andThen

`andThen` применяет функции по порядку: сначала `f`, затем `g`.

> [!example]- Пример: andThen
> `h = f.andThen(g)`. Вызов `h(10)` возвращает 22: `(10 + 1) * 2`.
>
> ```scala
> val h = f.andThen(g)
> h(10) // (10 + 1) * 2 = 22
> ```
>
> Пример показывает: последовательное применение функций слева направо.

##### compose

`compose` применяет функции в обратном порядке: сначала `g`, затем `f`.

> [!example]- Пример: compose
> `h = f.compose(g)`. Вызов `h(10)` возвращает 21: `(10 * 2) + 1`.
>
> ```scala
> val h = f.compose(g)
> h(10) // (10 * 2) + 1 = 21
> ```
>
> Пример показывает: применение функций справа налево.

Композиция — базовый механизм построения сложной логики из простых функций.

---

## Частичное применение (Partial Application)

Частичное применение фиксирует часть аргументов и возвращает новую функцию.

> [!example]- Пример: частичное применение
> `add10 = add(10, _)` фиксирует первый аргумент. Вызов `add10(5)` возвращает 15.
>
> ```scala
> def add(a: Int, b: Int): Int = a + b
>
> val add10 = add(10, _)
> add10(5) // 15
> ```
>
> Пример показывает: создание новой функции фиксацией части аргументов.

---

## Частично определённые функции (PartialFunction)

PartialFunction[A, B] определена не для всех значений типа A.

> [!example]- Пример: PartialFunction
> `pf` определена для 0 и 1. `pf.isDefinedAt(2)` возвращает false.
>
> ```scala
> val pf: PartialFunction[Int, String] =
>   case 0 => "zero"
>   case 1 => "one"
>
> pf.isDefinedAt(2) // false
> ```
>
> Пример показывает: функцию, определённую лишь для части значений.

Методы:
- `isDefinedAt` — проверяет, определена ли функция для значения.
- `apply` — вызывает функцию.
- `orElse` — подставляет альтернативную функцию.

Частично определённые функции активно используются при сопоставлении с образцом.

---

## Каррирование

Каррирование — преобразование функции `(A, B) => C` в `A => B => C`.

> [!example]- Пример: каррирование
> `add` принимает аргументы двумя группами. `add5 = add(5)` фиксирует первую группу; `add5(3)` возвращает 8.
>
> ```scala
> def add(a: Int)(b: Int): Int = a + b
>
> val add5 = add(5)
> add5(3) // 8
> ```
>
> Пример показывает: функцию с несколькими группами параметров и её частичное применение.

Каррирование упрощает частичное применение и улучшает вывод типов.

---

## Группы параметров

Группы параметров — несколько списков аргументов в одной функции.

> [!example]- Пример: группы параметров
> `withLogger` принимает сообщение и действие. Вызов печатает сообщение и выполняет действие.
>
> ```scala
> def withLogger(msg: String)(action: => Unit): Unit =
>   println(msg)
>   action
> ```
>
> Пример показывает: отделение логических уровней аргументов.

Группы параметров используются для:
- Улучшения вывода типов.
- Отделения логических уровней аргументов.
- Поддержки контекстных параметров.
- Построения DSL-подобного синтаксиса.

---

## Контекстные параметры и implicit-механизм

##### Общая идея

В реальных системах часто существуют значения, которые:
- Логически являются окружением.
- Передаются через множество уровней вызовов.
- Остаются неизменными в пределах контекста.

В Scala для этого используется механизм неявной передачи параметров.

---

## given и using (Scala 3)

##### Определение контекста

Контекст объявляется ключевым словом `given`.

> [!example]- Пример: given
> `intOrdering` — экземпляр Ordering[Int], доступный для неявного поиска.
>
> ```scala
> given intOrdering: Ordering[Int] with
>   def compare(a: Int, b: Int): Int = a - b
> ```
>
> Пример показывает: определение контекстного значения.

##### Использование контекста

Контекст запрашивается ключевым словом `using`.

> [!example]- Пример: using
> `max` запрашивает Ordering[Int] через using-параметр. Компилятор подставляет подходящий `given`.
>
> ```scala
> def max(a: Int, b: Int)(using ord: Ordering[Int]): Int =
>   if ord.compare(a, b) >= 0 then a else b
> ```
>
> Пример показывает: получение контекста через using-параметр.

---

## Механизм поиска

Компилятор ищет given:
1. В локальной области видимости.
2. В импортированных областях.
3. В companion-объектах соответствующих типов.

Понимание этих правил критично для диагностики ошибок неявного поиска.

---

## Практическое применение

Контекстные параметры лежат в основе:
- Реализации type classes.
- Сериализации.
- Работы с асинхронностью (например, ExecutionContext).
- Логирования и конфигурации.

Механизм — одна из ключевых особенностей Scala, требует внимательного освоения.

---

## Отличие от implicit в Scala 2

В Scala 2 ключевое слово implicit объединяло:
- Неявные параметры.
- Неявные преобразования.
- Implicit-классы.

В Scala 3 механизм разделён и стал более явным:
- `given` — определение контекста.
- `using` — получение контекста.

Это уменьшает «магичность» и делает код читаемее.
