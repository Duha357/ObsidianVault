`for`-comprehension в Scala — не управляющая конструкция, а синтаксический сахар: компилятор разворачивает её в цепочку вызовов `map`, `flatMap`, `withFilter` и `foreach`. Поэтому она работает не только с коллекциями, но и с `Option`, `Either` и любым типом, у которого есть эти методы. Ниже: правила трансляции, поведение с несколькими генераторами и фильтрами, применение к контейнерам.

---

## Базовый синтаксис

##### Форма с yield

С `yield` конструкция является выражением и собирает новую коллекцию.

> [!example]- Пример: for с yield
> Один генератор и одно преобразование. Компилятор превращает такую запись в вызов `map`.
>
> Ожидаемый результат: `result` — `List(200, 400, 600)`.
>
> ```scala
> val result =
>   for pages <- List(100, 200, 300)
>   yield pages * 2
>
> // компилятор разворачивает это в:
> List(100, 200, 300).map(pages => pages * 2)
> ```
>
> Пример показывает: зачем знать правила трансляции — `for` не добавляет возможностей, а меняет форму записи.

##### Форма без yield

Без `yield` результата нет: конструкция разворачивается в `foreach` и возвращает `Unit`.

> [!example]- Пример: for без yield
> Тело выполняется ради побочного эффекта.
>
> Ожидаемый результат: печатаются 100, 200, 300; значение конструкции — `()`.
>
> ```scala
> for pages <- List(100, 200, 300) do
>   println(pages)
>
> // компилятор разворачивает это в:
> List(100, 200, 300).foreach(pages => println(pages))
> ```
>
> Пример показывает: чем отличаются две формы — наличие `yield` определяет, есть ли у конструкции результат.

## Несколько генераторов

Каждый дополнительный генератор добавляет уровень `flatMap`; последний разворачивается в `map`.

> [!example]- Пример: Плохо — ручная цепочка flatMap и map
> Та же логика записана вызовами напрямую. Читать приходится изнутри наружу, а вложенность растёт с каждым источником.
>
> Ожидаемый результат: `List(11, 21, 12, 22)` — все комбинации элементов двух списков.
>
> ```scala
> List(1, 2).flatMap(shelfId =>
>   List(10, 20).map(bookId =>
>     shelfId + bookId
>   )
> )
> ```
>
> Пример показывает: для чего нужен `for` — при трёх и более источниках вложенность становится нечитаемой.

> [!example]- Пример: Хорошо — несколько генераторов в for
> Источники перечислены построчно, тело отделено ключевым словом `yield`.
>
> Ожидаемый результат: `List(11, 21, 12, 22)` — тот же результат, что и у цепочки вызовов.
>
> ```scala
> val combinations =
>   for
>     shelfId <- List(1, 2)
>     bookId <- List(10, 20)
>   yield shelfId + bookId
> ```
>
> Пример показывает: зачем `for`-comprehension — вложенная цепочка вызовов записывается плоским списком строк.

## Фильтры (guards)

Условие внутри `for` разворачивается не в `filter`, а в `withFilter`: тот не создаёт промежуточную коллекцию, а откладывает проверку до следующей операции.

> [!example]- Пример: Фильтр в for
> Условие отсеивает элементы до применения `yield`.
>
> Ожидаемый результат: `longBooks` — `List(300, 400)`.
>
> ```scala
> val longBooks =
>   for
>     pages <- List(100, 200, 300, 400)
>     if pages > 200
>   yield pages
>
> // компилятор разворачивает это в:
> List(100, 200, 300, 400)
>   .withFilter(pages => pages > 200)
>   .map(pages => pages)
> ```
>
> Пример показывает: почему используется `withFilter`, а не `filter` — промежуточная коллекция не создаётся.

## Промежуточные значения

Внутри `for` объявляются локальные значения — без `<-`, обычным присваиванием.

> [!example]- Пример: Локальное значение внутри for
> `doubled` вычисляется один раз на элемент и используется в `yield`.
>
> Ожидаемый результат: `result` — `List(210, 410, 610)`.
>
> ```scala
> val result =
>   for
>     pages <- List(100, 200, 300)
>     doubled = pages * 2 // локальное значение, не генератор
>   yield doubled + 10
> ```
>
> Пример показывает: для чего нужны локальные значения — промежуточный расчёт не приходится повторять в теле.

## Работа с Option

`Option` поддерживает `map` и `flatMap`, поэтому участвует в `for` наравне с коллекциями. Пустое значение обрывает цепочку.

> [!example]- Пример: Плохо — вложенные проверки Option
> Каждый `Option` разбирается отдельным `match`. Логика вычисления тонет в обработке пустых случаев.
>
> Ожидаемый результат: `Some(350)`, если обе величины известны, иначе `None`; при третьем источнике добавится ещё один уровень вложенности.
>
> ```scala
> val result =
>   findMainPages(bookId) match
>     case None => None
>     case Some(mainPages) =>
>       findAppendixPages(bookId) match
>         case None => None
>         case Some(appendixPages) => Some(mainPages + appendixPages)
> ```
>
> Пример показывает: для чего `for` применяют к `Option` — ручной разбор растёт вглубь с каждым значением.

> [!example]- Пример: Хорошо — for с Option
> Оба значения извлекаются генераторами. Проверок в коде нет: если любое из них окажется `None`, результатом станет `None`.
>
> Ожидаемый результат: `Some(350)` при `Some(300)` и `Some(50)`; `None`, если хотя бы одно значение отсутствует.
>
> ```scala
> val result =
>   for
>     mainPages <- Option(300)
>     appendixPages <- Option(50)
>   yield mainPages + appendixPages
> ```
>
> Пример показывает: зачем `for` работает не только с коллекциями — последовательные вычисления в контексте записываются линейно.

## Работа с Either

С `Either` действует то же правило: `Left` на любом шаге прекращает вычисление, до `yield` дело не доходит.

> [!example]- Пример: for с Either
> Оба шага возвращают `Either`. Ошибка любого из них становится результатом всей конструкции.
>
> Ожидаемый результат: `Right(30)` при успешных шагах; при `Left` на любом шаге — этот же `Left` без выполнения остальных шагов.
>
> ```scala
> val result =
>   for
>     totalPages <- Right(300): Either[String, Int]
>     chapters <- Right(10): Either[String, Int]
>   yield totalPages / chapters
> ```
>
> Пример показывает: зачем `Either` совмещают с `for` — обработка ошибок записывается без вложенных `match`.

---

## Обобщённое требование

Чтобы тип поддерживал `for`-comprehension, у него должны быть методы:

- `map` — для формы с одним генератором и `yield`.
- `flatMap` — для нескольких генераторов.
- `withFilter` — для фильтров.
- `foreach` — для формы без `yield`.

Требование к коллекциям здесь ни при чём: механизм работает для любого «flatMap-able» типа, включая `Option`, `Either`, `Try` и `Future`.
