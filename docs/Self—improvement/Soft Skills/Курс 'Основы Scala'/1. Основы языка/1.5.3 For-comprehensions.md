# For-comprehensions 

---

# Общая идея

for-comprehension — это синтаксический сахар.

Он не является отдельной управляющей конструкцией языка в традиционном смысле (как for в Java), а компилируется в последовательность вызовов методов:

- map
    
- flatMap
    
- withFilter
    
- foreach
    

Ключевой принцип:

for — это удобный способ записи композиции вычислений.

---

# Базовый синтаксис

## С yield

val result =  
  for  
pages <- List(100, 200, 300)  
  yield pages * 2

Результат:

List(200, 400, 600)

Компилятор преобразует это в:

List(100, 200, 300).map(pages => pages * 2) 

---

## Без yield

for  
  pages <- List(100, 200, 300)  
do  
  println(pages)  
  
Трансляция:

List(100, 200, 300).foreach(pages => println(pages))

Без yield результатом является Unit.

---

# Несколько генераторов

val combinations =  
  for  
shelfId <- List(1, 2)  
bookId <- List(10, 20)  
  yield shelfId + bookId

Результат:

List(11, 21, 12, 22)

Трансляция:

List(1, 2).flatMap(shelfId =>  
  List(10, 20).map(bookId =>  
shelfId + bookId  
  )  
)

Каждый новый генератор добавляет уровень flatMap.

---

# Фильтры (guards)

val longBooks =  
  for  
pages <- List(100, 200, 300, 400)  
if pages > 200  
  yield pages

Трансляция:

List(100, 200, 300, 400)  
  .withFilter(pages => pages > 200)  
  .map(pages => pages)

Используется withFilter, а не filter, что позволяет избежать промежуточных коллекций.

---

# Промежуточные значения

Можно объявлять локальные переменные:

val result =  
  for  
pages <- List(100, 200, 300)  
doubled = pages * 2  
  yield doubled + 10

Такие выражения компилируются как обычные map.

---

# For как декларативный pipeline

for делает цепочки flatMap/map более читаемыми.

Сравнение:

List(1, 2)  
  .flatMap(shelfId =>  
List(10, 20)  
   .map(bookId => shelfId + bookId)  
  )

И:

for  
  shelfId <- List(1, 2)  
  bookId <- List(10, 20)  
yield shelfId + bookId

Второй вариант ближе к императивному стилю, но остаётся декларативным.

---

# Использование с Option

Option поддерживает map и flatMap, поэтому работает с for.

val result =  
  for  
mainPages <- Option(300)  
appendixPages <- Option(50)  
  yield mainPages + appendixPages

Если одно из значений None, результат — None.

Это последовательная композиция вычислений в контексте возможного отсутствия.

---

# Использование с Either

val result =  
  for  
totalPages <- Right(300): Either[String, Int]  
chapters <- Right(10)  
  yield totalPages / chapter

Если на каком-либо этапе возникает Left, вычисление прекращается.

for обеспечивает линейную запись обработки ошибок без вложенных match.

---

# Обобщенное требование

Чтобы тип поддерживал for-comprehension, он должен иметь методы:

- map
    
- flatMap
    
- withFilter (для фильтров)
    
- foreach (для версии без yield)
    

Это не ограничивается коллекциями — механизм работает для любых “flatMap-able” типов.
