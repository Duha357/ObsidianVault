# Контекстные параметры и группы параметров

---

# Идея контекстных параметров

Контекстные параметры позволяют передавать аргументы неявно, предоставляя их через область видимости, а не через явный вызов.

Это механизм:

- инверсии зависимостей на уровне функций;
    
- внедрения инфраструктурных зависимостей;
    
- реализации Type Classes.
    

Ключевая идея:

Функция может требовать наличие значения определённого типа в контексте, и компилятор подставит его автоматически.

---

# Синтаксис Scala 3: using

Объявление функции с контекстным параметром:

def formatBook(name: String)(using prefix: String): String =  
  s"$prefix $title"

Здесь:

- первый список параметров — обычный;
    
- второй список — контекстный (using).
    

Вызов:

given String = "Book:"  
  
formatBook("Dune")

Компилятор найдет given String в области видимости и передаст его как prefix.

---

# given — определение контекста

Контекстное значение объявляется через given.

Пример:

given defaultPrefix: String = "Library:"

Имя полезно для явного использования:

formatBook("Foundation")(using defaultPrefix)

Также можно задать значение без имени:

given String = "Author:"

---

# Поиск неявных значений

Компилятор ищет given:

1. В локальной области видимости.
    
2. В импортированных объектах.
    
3. В companion-объектах типов.
    

Если найдено:

- ровно одно подходящее значение — оно используется;
    
- несколько — ошибка неоднозначности;
    
- ни одного — ошибка компиляции.
    

Это делает зависимость явной на уровне типов.

---

# Пример: Type Classes

Контекстные параметры лежат в основе паттерна Type Classes.

Интерфейс:

trait Show[A]:  
  def show(a: A): String

Инстанс:

given Show[Int] with  
  def show(a: Int): String = a.toString

Использование:

def printValue[A](a: A)(using s: Show[A]): String =  
  s.show(a)  
  
printValue(42)

Компилятор автоматически найдёт given Show[Int].

---

# Контекстные бинды (Context Bounds)

Сокращенная запись:

def printValue[A: Show](a: A): String =  
  summon[Show[A]].show(a)

[A: Show] означает, что требуется given Show[A].

summon[T] извлекает контекстное значение типа T.

---

# Инфраструктурные зависимости

Контекстные параметры часто используются для передачи:

- конфигураций;
    
- логгеров;
    
- сериализаторов;
    
- execution context;
    
- таймзон и локалей.
    

Пример:

import scala.concurrent.ExecutionContext  
  
def loadBooks()(using ec: ExecutionContext) =  
  // асинхронная логика  
  ()

Функция не знает, какой ExecutionContext используется — он предоставляется извне.

Это обеспечивает слабую связанность.

---

# Связь с группами параметров

Контекстные параметры всегда объявляются в отдельной группе параметров.

def saveBook(data: String)(using config: LibraryConfig): SaveResult

Разделение:

- первая группа — бизнес-аргументы;
    
- вторая — контекст выполнения.
    

Это улучшает читаемость API.

---

# Отличия от implicit (Scala 2)

В Scala 2 использовалось ключевое слово implicit для:

- неявных параметров;
    
- неявных преобразований;
    
- implicit class;
    
- implicit val.
    

Это приводило к перегрузке механизма и сложности понимания.

Scala 3 ввёл разделение:

  

|   |   |
|---|---|
|Scala 2|Scala 3|
|implicit val|given|
|implicit def|given|
|implicit parameter|using|
|implicitly[T]|summon[T]|

Преимущества Scala 3:

- более явный синтаксис;
    
- разделение ролей;
    
- упрощённая модель поиска;
    
- лучшая читаемость кода.
    

---

# Явная передача контекста

Контекст можно передать вручную:

formatBook("Dune")(using "Featured:")

Это полезно в тестах и при локальном переопределении.

	- Пользователь повторяет вопрос.

После срабатывания исключения — правила снова действуют.

## Правила

Перед выдачей проверка соответствия правилам.

- Сохранять доминирующий язык пользователя.
- Сжимать стиль, а не язык.
- Сохранять технические фрагменты: термины, код, имена API, команды CLI и точные строки ошибок дословно, на том же языке.
- Заголовки:
	- Основные блоки — H2.
	- Подблоки — H5.
- Пункты списка:
	- Вместо перечислений в прозе.
	- Вложенность — максимум 3 уровня.
	- Один пункт = один факт/действие/вывод.
	- Пункты начинаются с большой буквы.
	- Пункты заканчиваются точкой.
	- Максимум 2 предложения: первое — факт, второе — пояснение (если нужно).
	- Последовательности/порядок — нумерованными подпунктами: один шаг = один подпункт, независимо от уровня и количества.
	- Негативные — группируются подпунктами в пункт `**Не:**`.
	- Перечисляющие ситуации-исключения — группируются подпунктами в пункт `**Исключение:**`.
	- Порядок в списке:
	    1. Положительные пункты.
	    2. `**Не:**`.
	    3. `**Исключение:**`.
	- Обычные списки нумеруются на первом уровне, если пунктов больше 5 и нет `**Не:**`/`**Исключение:**`.
	- **Исключение:**
	    - Короткие перечисления однородных терминов внутри пункта (через запятую или /).
- Телеграфный стиль допустим: глагол + объект.
- Разделители `---` делят заголовки H2.
- Числа, пути, команды, имена файлов — всегда явно.
- Стрелка `->` или `→` — только для пары «замена/соответствие» (X -> Y).
- Заменять длинные формулировки короткими:
	- доктор -> врач.
	- дискуссия -> спор.
	- аварийное завершение работы приложения -> краш.
	- extensive -> big.
	- implement a solution for -> fix.
- Удалять:
	- Преамбулы (итак/давайте разберём/отличный вопрос и т.д.).
	- Заключения (надеюсь, помогло/если что — обращайтесь и т.д.).
	- Связующие слова (например стоит отметить/важно понимать/как видим/при этом и т.д.).
	- Артикли (a/an/the).
	- Слова-заполнители (просто/как бы/just/basically/actually/simply и т.д.).
	- Любезности (всё верно/действительно/sure/really/certainly/of course/happy to и т.д.).
	- Оговорки (скорее всего/возможно/на всякий случай и т.д.).
	- **Исключение:**
	    - Фрагменты фраз, оставшиеся после удаления. Предложение перефразируется.
	    - `и т.д.` как маркер открытого перечисления.
	    - Критично для смысла.
	    - Итоговый текст вводит в заблуждение.
- **Не:**
	- Писать развёрнутые предложения там, где хватает телеграфного стиля.
	- Давать неточные определения («примерно», «где-то в» и т.д.).
	- Делить заголовки H5 разделителем `---`.
	- Использовать навязанные другими инструкциями вступительные или статусные фразы.
	- Называть и объявлять стиль/правила.
	- Ссылаться на себя (самореференция).
	- Сжимать перечисления шагов и последовательности в строку символами (->, →, /, запятыми и т.д.).
