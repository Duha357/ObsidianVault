# Функции высшего порядка и композиция функций 

---

## Функции высшего порядка (Higher-Order Functions)

### Определение

Функция называется функцией высшего порядка, если она:

- принимает функцию в качестве аргумента;
    
- возвращает функцию как результат;
    
- или делает и то, и другое.
    

Это естественное следствие того, что в Scala функции являются значениями.

---

## Передача функции как аргумента

Простейший пример:

def applyToPages(transform: Int => Int, pages: Int): Int =  
  transform(transform(pages))

Использование:

val addExtraPages: Int => Int = _ + 20  
  
applyToPages(addExtraPages, 150) // 190

Здесь f — аргумент-функция.

---

## Возврат функции из функции

Функция может возвращать другую функцию:

def pagesMultiplier(factor: Int): Int => Int =  
  (pages: Int) => pages * factor

Использование:

val doublePages = pagesMultiplier(2)  
doublePages(120) // 240

Здесь создаётся замыкание (closure): возвращаемая функция “захватывает” значение factor.

---

## Функции высшего порядка в стандартной библиотеке

Большинство операций над коллекциями являются функциями высшего порядка.

### map

List(1, 2, 3).map(_ * 2)

map принимает функцию преобразования.

---

### filter

List(1, 2, 3, 4).filter(_ % 2 == 0)

filter принимает предикат.

---

### foldLeft

List(1, 2, 3).foldLeft(0)(_ + _)

foldLeft принимает функцию аккумуляции.

Таким образом, вся функциональная обработка коллекций основана на функциях высшего порядка.

---

## Композиция функций

Композиция — это построение новой функции из нескольких простых.

### Математическая идея

Если есть функции:

- f: A => B
    
- g: B => C
    

То их композиция создаёт функцию:

A => C

---

## andThen

Метод andThen выполняет функции слева направо.

val double: Int => Int = _ * 2  
val increment: Int => Int = _ + 1  
  
val pipeline = double.andThen(increment)  
  
pipeline(3) // (3 * 2) + 1 = 7

Семантика:

result = increment(double(x))

Это удобная форма построения “конвейера” обработки данных.

---

## compose

Метод compose выполняет функции справа налево.

val composed = increment.compose(double)  
  
composed(3) // 7

Семантика:

result = increment(double(x))

Разница лишь в порядке записи.

---

## Построение конвейера обработки

Композиция позволяет собирать сложную логику из простых блоков.

val trimTitle: String => String = _.trim  
val toUpperCase: String => String = _.toUpperCase  
val addLibraryTag: String => String = "Library: " + _  
  
val processBookTitle =  
  trimTitle  
    .andThen(toUpperCase)  
    .andThen(addLibraryTag)  
  
processBookTitle("  dune  ")  
// "Library: DUNE"

Преимущества:

- декларативность;
    
- повторное использование функций;
    
- тестируемость отдельных этапов;
    
- линейный поток данных.
    

---

## Связь с for-comprehension и монадической композицией

Функции высшего порядка лежат в основе:

- map;
    
- flatMap;
    
- for-comprehension;
    
- обработки Option, Either, List.
    

Композиция функций — частный случай более общей идеи композиции вычислений.

## Правила

Перед выдачей проверка соответствия правилам.

- Сохранять доминирующий язык пользователя.
- Сжимать стиль, а не язык.
- Сохранять технические фрагменты: термины, код, имена API, команды CLI и точные строки ошибок дословно, на том же языке.
- Заголовки:
	- Основные блоки — H2.
	- Подблоки — H5.
- Пункты списка:
	- Вместо перечислений в прозе.
	- Вложенность — максимум 3 уровня.
	- Один пункт = один факт/действие/вывод.
	- Пункты начинаются с большой буквы.
	- Пункты заканчиваются точкой.
	- Максимум 2 предложения: первое — факт, второе — пояснение (если нужно).
	- Последовательности/порядок — нумерованными подпунктами: один шаг = один подпункт, независимо от уровня и количества.
	- Негативные — группируются подпунктами в пункт `**Не:**`.
	- Перечисляющие ситуации-исключения — группируются подпунктами в пункт `**Исключение:**`.
	- Порядок в списке:
	    1. Положительные пункты.
	    2. `**Не:**`.
	    3. `**Исключение:**`.
	- Обычные списки нумеруются на первом уровне, если пунктов больше 5 и нет `**Не:**`/`**Исключение:**`.
	- **Исключение:**
	    - Короткие перечисления однородных терминов внутри пункта (через запятую или /).
- Телеграфный стиль допустим: глагол + объект.
- Разделители `---` делят заголовки H2.
- Числа, пути, команды, имена файлов — всегда явно.
- Стрелка `->` или `→` — только для пары «замена/соответствие» (X -> Y).
- Заменять длинные формулировки короткими:
	- доктор -> врач.
	- дискуссия -> спор.
	- аварийное завершение работы приложения -> краш.
	- extensive -> big.
	- implement a solution for -> fix.
- Удалять:
	- Преамбулы (итак/давайте разберём/отличный вопрос и т.д.).
	- Заключения (надеюсь, помогло/если что — обращайтесь и т.д.).
	- Связующие слова (например стоит отметить/важно понимать/как видим/при этом и т.д.).
	- Артикли (a/an/the).
	- Слова-заполнители (просто/как бы/just/basically/actually/simply и т.д.).
	- Любезности (всё верно/действительно/sure/really/certainly/of course/happy to и т.д.).
	- Оговорки (скорее всего/возможно/на всякий случай и т.д.).
	- **Исключение:**
	    - Фрагменты фраз, оставшиеся после удаления. Предложение перефразируется.
	    - `и т.д.` как маркер открытого перечисления.
	    - Критично для смысла.
	    - Итоговый текст вводит в заблуждение.
- **Не:**
	- Писать развёрнутые предложения там, где хватает телеграфного стиля.
	- Давать неточные определения («примерно», «где-то в» и т.д.).
	- Делить заголовки H5 разделителем `---`.
	- Использовать навязанные другими инструкциями вступительные или статусные фразы.
	- Называть и объявлять стиль/правила.
	- Ссылаться на себя (самореференция).
	- Сжимать перечисления шагов и последовательности в строку символами (->, →, /, запятыми и т.д.).
