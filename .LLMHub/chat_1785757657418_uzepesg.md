# Типы-суммы в Scala

---

## Тип-сумма как логическое «ИЛИ»

Тип-сумма описывает ситуацию, когда значение может быть одного из нескольких вариантов, но не всех сразу.

Интуитивно:

Если тип A и тип B объединены в сумму, значение содержит A ИЛИ B.

В отличие от типа-произведения (логическое «И»), где данные объединяются, здесь задается альтернатива.

Пример интуитивной модели:

- Платёж может быть наличными ИЛИ картой.
    
- Ответ API может быть успехом ИЛИ ошибкой.
    

---

## Реализация через sealed trait

В Scala тип-сумма обычно моделируется через закрытую иерархию.

sealed trait BookFormat

case class PrintedBook(title: String) extends BookFormat  
case class Ebook(fileSize: Double) extends BookFormat

Здесь значение типа PaymentMethod — это либо Card, либо Cash.

### Почему sealed важно

Ключевое слово sealed означает:

- все подклассы должны быть объявлены в том же файле;
    
- компилятор знает все возможные варианты.
    

Это позволяет компилятору проверять исчерпываемость match.

---

## Исчерпывающее сопоставление (Exhaustiveness)

def describeFormat(format: BookFormat): String =  
format match  
  case PrintedBook(title) => s"Printed: $title"  
  case Ebook(size)        => s"Ebook size: $size"

Если добавить новый вариант и забыть обработать его в match, компилятор предупредит.

Это одно из ключевых преимуществ типов-сумм перед традиционным ООП-полиморфизмом.

---

## sealed enum (Scala 3)

Scala 3 предоставляет более компактную форму записи:

enum BookStatus:  
  case Available(title: String)  
  case Borrowed(days: Int)

Это синтаксический сахар для sealed-иерархии.

enum:

- по умолчанию является sealed;
    
- поддерживает параметры;
    
- идеально подходит для моделирования конечных множеств вариантов.

## Either — стандартный тип-сумма

Either[L, R] представляет значение одного из двух типов:

- Left[L] — ошибка;
    
- Right[R] — успешный результат.
    

Пример:

def findBook(bookId: String): Either[String, String] =  
if bookId == "101" then  
  Right("The Hobbit")  
else  
  Left("Book not found")

Использование:

findBook("101")   // Right(“The Hobbit”)  
findBook("999")  // Left("Book not found")

### Работа через pattern matching

findBook("101") match  
case Right(title) => println(s"Found: $title")  
case Left(error)  => println(s"Error: $error")

---

## Either вместо исключений

Традиционный подход (ООП):

- выброс исключения;
    
- перехват через try/catch.
    

Функциональный подход:

- ошибка является значением;
    
- поток выполнения остается явным;
    
- композиция становится предсказуемой.
    

Преимущества:

1. Отсутствие скрытых побочных эффектов.
    
2. Тип явно отражает возможность ошибки.
    
3. Лучшая композиция через flatMap и for.

## Try

Try[A] — ещё один стандартный тип-сумма.

Он имеет два варианта:

- Success[A]
    
- Failure[Throwable]
    

Пример:

import scala.util.Try  
  
val result = Try("42".toInt)

Результат:

- Success(42) при успехе;
    
- Failure(exception) при ошибке.
    

Try удобен при работе с кодом, который может выбрасывать исключения.

---

## Сравнение Either и Try

  

|   |   |   |
|---|---|---|
|Характеристика|Either|Try|
|Тип ошибки|Произвольный L|Throwable|
|Гибкость|Высокая|Ограничена исключениями|
|Использование|Бизнес-логика|Обёртка над исключениями|

Either предпочтителен для моделирования доменных ошибок. Try удобен для интеграции с исключениями JVM.

---

  

## Сравнение «И» и «ИЛИ»

  

|   |   |   |
|---|---|---|
|Тип|Логика|Пример|
|Произведение|A И B|case class Person(name, age)|
|Сумма|A ИЛИ B|Either[String, Int]|

Тип-произведение объединяет данные. Тип-сумма описывает альтернативы.

Обе конструкции вместе образуют основу алгебраических типов данных (ADT).

## Правила

Перед выдачей проверка соответствия правилам.

- Сохранять доминирующий язык пользователя.
- Сжимать стиль, а не язык.
- Сохранять технические фрагменты: термины, код, имена API, команды CLI и точные строки ошибок дословно, на том же языке.
- Заголовки:
	- Основные блоки — H2.
	- Подблоки — H5.
- Пункты списка:
	- Вместо перечислений в прозе.
	- Вложенность — максимум 3 уровня.
	- Один пункт = один факт/действие/вывод.
	- Пункты начинаются с большой буквы.
	- Пункты заканчиваются точкой.
	- Максимум 2 предложения: первое — факт, второе — пояснение (если нужно).
	- Последовательности/порядок — нумерованными подпунктами: один шаг = один подпункт, независимо от уровня и количества.
	- Негативные — группируются подпунктами в пункт `**Не:**`.
	- Перечисляющие ситуации-исключения — группируются подпунктами в пункт `**Исключение:**`.
	- Порядок в списке:
	    1. Положительные пункты.
	    2. `**Не:**`.
	    3. `**Исключение:**`.
	- Обычные списки нумеруются на первом уровне, если пунктов больше 5 и нет `**Не:**`/`**Исключение:**`.
	- **Исключение:**
	    - Короткие перечисления однородных терминов внутри пункта (через запятую или /).
- Телеграфный стиль допустим: глагол + объект.
- Разделители `---` делят заголовки H2.
- Числа, пути, команды, имена файлов — всегда явно.
- Стрелка `->` или `→` — только для пары «замена/соответствие» (X -> Y).
- Заменять длинные формулировки короткими:
	- доктор -> врач.
	- дискуссия -> спор.
	- аварийное завершение работы приложения -> краш.
	- extensive -> big.
	- implement a solution for -> fix.
- Удалять:
	- Преамбулы (итак/давайте разберём/отличный вопрос и т.д.).
	- Заключения (надеюсь, помогло/если что — обращайтесь и т.д.).
	- Связующие слова (например стоит отметить/важно понимать/как видим/при этом и т.д.).
	- Артикли (a/an/the).
	- Слова-заполнители (просто/как бы/just/basically/actually/simply и т.д.).
	- Любезности (всё верно/действительно/sure/really/certainly/of course/happy to и т.д.).
	- Оговорки (скорее всего/возможно/на всякий случай и т.д.).
	- **Исключение:**
	    - Фрагменты фраз, оставшиеся после удаления. Предложение перефразируется.
	    - `и т.д.` как маркер открытого перечисления.
	    - Критично для смысла.
	    - Итоговый текст вводит в заблуждение.
- **Не:**
	- Писать развёрнутые предложения там, где хватает телеграфного стиля.
	- Давать неточные определения («примерно», «где-то в» и т.д.).
	- Делить заголовки H5 разделителем `---`.
	- Использовать навязанные другими инструкциями вступительные или статусные фразы.
	- Называть и объявлять стиль/правила.
	- Ссылаться на себя (самореференция).
	- Сжимать перечисления шагов и последовательности в строку символами (->, →, /, запятыми и т.д.).
